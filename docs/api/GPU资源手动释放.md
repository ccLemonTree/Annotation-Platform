# GPU资源手动释放

管理员进入“GPU资源”，先选择服务器。平台任务表提供“停止并释放”，计算进程表提供“释放显存”。先核对目标，再在确认窗口执行；取消不会停止进程。窗口展示服务器、目标与全部受影响GPU。仅能解除已经确认停止的任务预留，其他进程仍可能占用显存。

| 方法 | 路径（前缀 `/api/gpu-resources`） | 用途 |
| --- | --- | --- |
| GET | `/servers/{server_id}/release/tasks` | 当前租户、当前服务器的训练及权重验证/预览占用与预留 |
| POST | `/servers/{server_id}/release/preview` | 用 `{pid,gpu_uuid}` 或 `{task_kind,task_id}` 核对目标 |
| POST | `/servers/{server_id}/release/confirm` | 用 `{token,force:false}` 确认停止 |

`server_id` 支持 `default` 或已保存连接UUID。仅管理员允许调用；连接停用或凭据缺失时拒绝。确认信息签名并绑定用户、租户、服务器配置版本及目标，120秒有效；不接收命令文本。服务器密码不进入响应、确认信息或命令行参数。

平台训练调用原停止流程，停止确认后更新状态并解除GPU预留。终态遗留预留须先确认远端容器停止或不存在。权重验证及效果预览复用取消流程，执行轮次必须一致，远端停止不确定时保留预留。已保存的训练文件、权重及任务记录不删除。

普通Linux进程先发送SIGTERM，8秒后仍未退出则提示继续核对。用户勾选“正常结束超时后强制结束进程”才会追加SIGKILL。通过启动时间、主机启动标识和pidfd防止PID复用误停；服务器缺少pidfd支持时拒绝直接结束进程。Docker进程停止整个容器（正常停止10秒，随后按Docker停止规则处理），窗口说明其他进程也会停止并列出全部关联GPU；平台容器必须映射到对应租户任务，不能绕过预留更新。

Kubernetes和其他无法安全识别的容器运行时不直接结束内部进程，提示从对应工作负载停止。MIG实例、图形进程或没有可识别计算进程的显存占用，本功能不执行GPU reset或驱动操作。停止后使采集缓存失效，并刷新进程、显存及任务占用。管理员操作结果记录在后端日志，不保存凭据。

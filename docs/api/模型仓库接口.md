# 模型仓库接口

页面：`http://192.168.1.115:3000/model-repository`。其他服务使用同一入口的 `/api/model-repository`；后端 `18000` 端口仅监听服务器本机。

## 鉴权与格式

复用 `POST /api/auth/login`，请求为 `application/x-www-form-urlencoded` 的 `username`、`password`，响应包含 `access_token`、`token_type`、`expires_in`。后续请求带 `Authorization: Bearer <access_token>`。Token 过期后重新登录，不放在 URL 中。登录用户可查询、下载本租户模型；上传、训练入库和重试需要管理员账号。

### 获取 TOKEN（curl）

以下是 Bash/curl 示例。将用户名和密码替换为平台登录账号，调用登录接口：

```bash
BASE=http://192.168.1.115:3000

curl --fail-with-body "$BASE/api/auth/login" \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode 'username=你的用户名' \
  --data-urlencode 'password=你的密码'
```

复制响应 JSON 中的 `access_token`，填入 `TOKEN` 变量，再查询模型仓库：

```bash
TOKEN='上一步返回的access_token'

# 携带 TOKEN 查询模型仓库
curl --fail-with-body "$BASE/api/model-repository" \
  -H "Authorization: Bearer $TOKEN"
```

其他服务取得 TOKEN 后，同样设置请求头；下文 Bash/curl 示例中的 `TOKEN` 变量也使用此值：

```http
Authorization: Bearer 获取到的access_token
```

### 模型格式

`format` 为 `pt`、`onnx`、`tensorrt` 或 `python`。主文件扩展名分别支持 `.pt/.pth`、`.onnx`、`.engine/.plan`，Python backend使用数字版本目录下的 `model.py`。TensorRT 必填 `gpu_model`，可填写 `tensorrt_version`；相同 GPU 型号不代表 TensorRT/CUDA/驱动版本必然兼容，部署前仍需核对运行环境，参见 [NVIDIA 引擎兼容性说明](https://docs.nvidia.com/deeplearning/tensorrt/latest/inference-library/engine-compatibility.html)。其他格式不按 GPU 型号分类。

仓库只保存文件、记录来源及校验传输完整性，不反序列化模型或证明推理正确性。ONNX 如有外部权重，须与主文件一起上传并保留文件名与相对目录。单文件下载为原文件，多文件下载为 ZIP，解压后保持目录结构使用。

## 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/model-repository` | 本租户版本列表，支持 `q`、`format`、`gpu_model`、`group_name`、`page`、`page_size` |
| POST | `/api/model-repository/download-batch` | 按所选版本ID或筛选条件批量下载ZIP，普通登录用户可调用 |
| GET | `/api/model-repository/groups` | 模型分组分页，返回组内版本数、格式、GPU 型号和最近入库时间 |
| GET | `/api/model-repository/{id}` | 模型详情、来源、状态和逐文件 SHA256 |
| PATCH | `/api/model-repository/{id}` | 管理员修改名称、版本号与备注；直接上传的TensorRT另支持修正GPU型号和TensorRT版本 |
| POST | `/api/model-repository/upload` | multipart 上传一个模型及配套文件 |
| GET | `/api/model-repository/sources` | 已完成的可入库训练/导出任务 |
| GET | `/api/model-repository/sources/{run_id}/artifacts` | 来源任务中可选择的模型主文件 |
| POST | `/api/model-repository/from-training` | 后台复制所选训练产物到仓库 |
| POST | `/api/model-repository/{id}/retry` | 重试失败或中断的训练入库 |
| GET | `/api/model-repository/{id}/download` | 下载就绪模型，单文件原样、多文件 ZIP |
| GET | `/api/model-repository/{id}/config` | 查看 TensorRT 配套 config.pbtxt 的 UTF-8 内容和 SHA256 |

上传字段：`name`、`version`、`format`、`entry_file`，可选 `group_name`；TensorRT另加 `gpu_model`，可选 `tensorrt_version`。文件字段为重复的 `files`，不是 `files[]`。`entry_file` 必须匹配本次提交的主文件路径。文件大小上限沿用后端 `MAX_ARCHIVE_UPLOAD_SIZE`，默认总计 10 GiB。

名称、版本、格式、GPU 型号和 batch 规格在租户内构成唯一版本；重复返回 `409`，不会覆盖旧文件。同版本不同 GPU 或不同 batch 的 TensorRT 可分别保存。

### TensorRT 的 batch 规格

上传时可增加 `batch_profile`：固定 batch 8 为 `fixed:8`；动态 min=1、opt=4、max=8 为 `dynamic:1:4:8`。各值为 1–1024 的整数，动态规格要求 min ≤ opt ≤ max。省略或空字符串表示“未记录”，兼容旧客户端；PT/ONNX 不接受非空 batch 规格。名称、版本、GPU 相同但规格不同的 engine 可以同时保存，仍归在同一模型组下。列表、详情和下发模型选择会展示规格。

从训练产物入库时，batch 以标准导出清单为准，不接受客户端覆盖。已有训练导出记录可从原任务的有效构建参数恢复；来源不明的旧上传模型保持“未记录”。batch 属于构建信息，不能通过名称/备注编辑接口修改；应上传对应的新产物。填写 batch 只记录实际构建规格，不会转换 engine 或自动改写服务配置。

```bash
curl --fail-with-body "$BASE/api/model-repository/upload" \
  -H "Authorization: Bearer $TOKEN" \
  -F 'name=detr1023烟火训练' -F 'version=v1023' -F 'format=tensorrt' \
  -F 'gpu_model=Tesla T4' -F 'tensorrt_version=10.14.1' -F 'batch_profile=fixed:8' \
  -F 'entry_file=model.engine' -F 'files=@model.engine' -F 'files=@config.pbtxt'
```

### 模型分组与 config.pbtxt

页面优先使用显式 `group_name` 分组；上传、训练产物入库和编辑均可填写，最多100字。留空仍按模型名称自动分组，并忽略名称末尾的 ` · TENSORRT`、` · ONNX`、` · PT`（后缀大小写不敏感）。例如SAM3各组件统一填写 `group_name=sam3`，组件名称继续分别保留，版本唯一性仍按原组件名称、版本、格式、GPU及batch判断。修改分组不改变文件或下发引用。分组接口返回 `items`、`total`（组数）、`version_total`（版本总数）和 `gpu_models`；展开后通过版本列表的 `group_name` 精确查询有效分组。搜索同时匹配模型名称和模型组；格式、GPU、搜索条件同时作用于分组和组内版本。

### 批量下载及筛选

页面展开模型组后可勾选具体版本，勾选跨组、跨分页保留，也可清空勾选。点击“批量下载”，选择“下载已勾选版本”或“按筛选条件下载全部匹配版本”。筛选支持模型名称/模型组关键词 `q`、精确模型组 `group_name`、模型格式 `format` 和精确GPU型号 `gpu_model`；弹窗默认带入页面已有的关键词、格式和GPU条件。筛选针对全部分页，并仅包含 `ready` 版本。

每批最多100个版本，JSON请求中 `ids` 和 `filters` 必须且只能提供一种。重复ID、空ID列表、无效条件或超过上限返回 `422`；缺失/其他租户版本或无匹配结果返回 `404`；显式勾选未就绪版本、文件损坏或存储空间不足返回 `409`。普通登录用户可下载本租户模型，沿用Bearer认证。

```bash
# 勾选多个版本；将UUID替换为模型版本ID
curl --fail-with-body "$BASE/api/model-repository/download-batch" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  --data '{"ids":["模型版本UUID1","模型版本UUID2"]}' \
  --output models-batch.zip

# 下载sam3组中所有匹配的TensorRT版本，覆盖全部分页
curl --fail-with-body "$BASE/api/model-repository/download-batch" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  --data '{"filters":{"group_name":"sam3","format":"tensorrt","gpu_model":"Tesla T4"}}' \
  --output models-batch.zip
```

ZIP内每个版本保存在 `models/<版本UUID>/` 下，其内部文件相对路径保持不变，避免不同模型的 `model.engine`、`config.pbtxt` 等同名文件覆盖。根目录 `manifest.json` 记录版本ID、名称、模型组、格式、GPU/TensorRT/batch、主文件、总大小、目录及逐文件SHA256。文件边打包边校验，任何版本失败均不返回部分包；请求结束或失败后清理服务器临时ZIP。浏览器会暂存下载内容，超大包建议使用curl直接保存到服务器。

### Python backend完整目录

页面选择格式“Python backend”，点击“选择文件夹”，选择 `sam3_pipeline` 整个目录，模型组填 `sam3`，模型名称可填 `sam3_pipeline`，主文件选择 `sam3_pipeline/1/model.py`。保留所有上传文件的相对路径，包括tokenizer、npy、辅助Python模块和空的 `__init__.py`。目录应包含对应的 `sam3_pipeline/config.pbtxt`；API也接受不带外层目录的 `1/model.py` 与根目录 `config.pbtxt`。配置须为非空UTF-8且不超过1 MiB，主文件不能为空。跨目录或路径越界会被拒绝；每个版本最多500个文件。空目录不单独存储。

API按如下方式传递相对文件名（在包含 `sam3_pipeline` 的父目录执行）：

```bash
curl --fail-with-body "$BASE/api/model-repository/upload" \
  -H "Authorization: Bearer $TOKEN" \
  -F name=sam3_pipeline -F group_name=sam3 -F version=v1.0 -F format=python \
  -F entry_file=sam3_pipeline/1/model.py \
  -F 'files=@sam3_pipeline/config.pbtxt;filename=sam3_pipeline/config.pbtxt' \
  -F 'files=@sam3_pipeline/1/model.py;filename=sam3_pipeline/1/model.py' \
  -F 'files=@sam3_pipeline/1/tokenizer.json;filename=sam3_pipeline/1/tokenizer.json' \
  -F 'files=@sam3_pipeline/1/pos_enc_1008.npy;filename=sam3_pipeline/1/pos_enc_1008.npy'
```

下载接口返回保留目录结构的ZIP，配置预览接口同样适用。平台只保存和校验文件，不导入或执行上传的Python代码，也不解析其依赖或验证推理可运行性。当前TensorRT下发入口不接收Python目录；运行端仍需Python backend环境及脚本引用的其他模型。SAM3 pipeline依赖 `sam3_backbone`、`sam3_text_encoder` 和 `sam3_enc_dec`。

TensorRT 上传允许一个 `.engine/.plan` 主文件，加可选的根目录 `config.pbtxt`。配置必须为非空 UTF-8 文本、不含 NUL，最大 1 MiB。两个文件均记录 SHA256，下载返回包含两个文件的 ZIP。查看配置接口返回 `path`、`content`、`sha256`；未附带时返回 `404`，校验失败返回 `409`。旧版本不会自动生成配置。配置用于保存、查看和随模型下载；下发仍使用目标服务配置，不自动套用仓库配置。

```bash
curl --fail-with-body "$BASE/api/model-repository/upload" \
  -H "Authorization: Bearer $TOKEN" \
  -F 'name=detr1023烟火训练' -F 'version=v1023' \
  -F 'format=tensorrt' -F 'gpu_model=Tesla T4' -F 'tensorrt_version=10.14.1' \
  -F 'entry_file=model.engine' -F 'files=@model.engine' -F 'files=@config.pbtxt'

curl --fail-with-body "$BASE/api/model-repository/$MODEL_ID/config" \
  -H "Authorization: Bearer $TOKEN"
```

### 修改版本信息

管理员可在页面点击“编辑”，或提交以下请求。`name`、`version` 必填（各最多100字），可选 `group_name`（最多100字，省略保留原值，空字符串恢复按名称自动分组）；`description` 最多2000字，空字符串或省略表示清空备注。正在入库的记录返回 `409`。文件、SHA256、格式及batch规格不接受修改。

仅来源为直接上传的TensorRT模型可选传 `gpu_model`（最多200字，不可为空）和 `tensorrt_version`（最多100字，允许清空），用于纠正人工录入错误；省略这两个字段时保留原值。训练产物、来源不明的记录以及PT/ONNX传入构建信息返回 `422`。修改GPU型号后若与同名称、版本号、格式和batch规格的现有记录重复，返回 `409`，本次修改全部回滚。修改元数据不会转换engine或改变实际兼容性，必须填写真实构建环境。

已有下发记录保留原名称、版本和构建环境快照；环境信息修正后，尚未执行的下发记录会拒绝继续使用旧快照，请重新创建下发记录。

```bash
curl --fail-with-body -X PATCH "$BASE/api/model-repository/$MODEL_ID" \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"name":"烟火检测","version":"v10","description":"修正手填构建信息","gpu_model":"Tesla T4","tensorrt_version":"10.14.1"}'
```

列表响应为 `items`、`total`、`page`、`page_size`、`gpu_models`。条目包含 `id/name/version/format/gpu_model/tensorrt_version/entry_file/file_size/files/status/error/run_id/source/created_at`；`file_size` 是总字节数，`files` 中每项为 `path/bytes/sha256`。

## 上传和下载示例

以下是 Bash/curl 示例，`TOKEN` 由调用方安全设置为登录返回的令牌，`BASE` 为可访问的平台地址。

```bash
BASE=http://192.168.1.115:3000

# PT
curl --fail-with-body "$BASE/api/model-repository/upload" \
  -H "Authorization: Bearer $TOKEN" \
  -F name=detector -F version=v1 -F format=pt -F entry_file=best.pt \
  -F 'files=@./best.pt;filename=best.pt'

# ONNX 及外部权重（自包含 ONNX 可省略 model.data）
curl --fail-with-body "$BASE/api/model-repository/upload" \
  -H "Authorization: Bearer $TOKEN" \
  -F name=detector -F version=v1 -F format=onnx -F entry_file=model.onnx \
  -F 'files=@./model.onnx;filename=model.onnx' \
  -F 'files=@./model.data;filename=model.data'

# TensorRT
curl --fail-with-body "$BASE/api/model-repository/upload" \
  -H "Authorization: Bearer $TOKEN" \
  -F name=detector -F version=v1 -F format=tensorrt \
  -F 'gpu_model=Tesla T4' -F tensorrt_version=10.14.1 \
  -F entry_file=model.engine -F 'files=@./model.engine;filename=model.engine'

# 按格式和 GPU 筛选
curl --fail-with-body --get "$BASE/api/model-repository" \
  -H "Authorization: Bearer $TOKEN" \
  --data-urlencode format=tensorrt --data-urlencode 'gpu_model=Tesla T4'

# 用上传或列表响应中的 id 下载；输出文件扩展名按单文件/ZIP选择
curl --fail-with-body "$BASE/api/model-repository/$MODEL_ID/download" \
  -H "Authorization: Bearer $TOKEN" -o ./downloaded-model.engine
```

## 从训练入库

先从 `sources` 和对应 `artifacts` 选择任务及主文件路径，再提交：

```json
{
  "name": "detector",
  "version": "v1",
  "format": "pt",
  "run_id": "来源任务UUID",
  "artifact_path": "weights/best.pt"
}
```

创建后按 `id` 查询状态：`importing` 代表正在复制及校验，`ready` 才可下载，`failed` 或 `interrupted` 可重试。训练导入会保留原文件，模型的来源任务也受删除保护。平台已知的 TensorRT 导出 GPU 型号与版本从导出结果读取，不能通过提交不同型号把同一产物归为另一种 GPU。

## 从仓库下发模型

管理员在“模型与镜像更新”页面直接选择仓库中的 TensorRT 模型，也可调用批量接口：

```bash
curl --fail-with-body "$BASE/api/model-deployments/batches" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"kind":"model","repository_id":"模型仓库UUID","target_ids":["服务器目标UUID"]}'
```

`repository_id` 必须属于当前租户，状态为 `ready`，格式为 `tensorrt`，并包含真实构建 GPU 型号及 TensorRT 版本；目标必须是 `triton_plan`。目标列表见 `GET /api/model-deployments/targets`。创建批次只生成记录，随后按原流程先准备和校验，再手动生效；不会自动切换服务。文件从仓库读取，不重复创建模型版本。

PT/ONNX 仍可上传与下载，部署到现有推理目标前需先导出 TensorRT 并入库。大模型/向量完整目录继续使用原归档流程及 `release_id`；同一批次不得同时传 `repository_id` 和 `release_id`，镜像批次不得传这两个字段。历史下发记录继续可查。

## 错误处理

`401` 未登录或令牌过期；`403` 无管理员权限；`404` 不存在或不属于本租户；`409` 版本重复、状态不允许、来源变化或完整性校验失败；`413` 超出大小限制；`422` 字段、路径或格式不合法。入库后台失败原因见条目的 `error`，修复来源或环境后调用重试。

大文件建议通过服务端 HTTP 客户端直接下载到文件；浏览器下载会占用浏览器内存。自动化客户端应检查 HTTP 状态码，并按详情中的逐文件 SHA256 校验下载结果。

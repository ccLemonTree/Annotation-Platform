# 检测标注、审核和导出

当前入口：先在独立图片库筛选并添加到项目，再从“项目管理 → 管理图片”进入`/projects/<项目UUID>/images`，点击“标注 / 审核”，或进入 `/annotate/<项目使用UUID>`。test-img类别当前为person，不限定衣服颜色；未配置类别不默认使用“人”。类别在项目管理配置，多个项目可共用原图且标注／审核独立。API要求主平台Bearer Token及租户范围，见[图片库接口与操作](../development/图片库与项目使用说明.md)。

工作台顶部返回链接明确显示项目名称，并返回原项目图片页。项目添加图片在抽屉内完成，不切换到图片管理；图片库固定为`/assets`。旧`/assets?project_id=<UUID>`自动转到对应项目图片地址。

“标注与审核”入口`/annotations`先按项目展示进度。选择项目后以`project_id`过滤最新标注，图片预览/文件名替代长ID列。页面的`review_status`、`page`、`page_size`留在URL；工作台携带`from=review`和这些参数，切图及返回保持原项目和筛选。审核通过/驳回统一在工作台看图片与框后执行，原审核API保留。

## 保存与版本

检测数据以原图像素保存：`{"boxes":[{"label":"人","x":10,"y":20,"width":30,"height":40}]}`。x/y为左上角，宽高大于零，必须在图片内，非有限数字/布尔值/空类别拒绝。`boxes: []`表示人工确认的负样本，不等同于未标注；工作台要求勾选无目标确认。

| 操作 | 接口与约定 |
|---|---|
| 第一次保存 | POST `/api/annotations`，asset_id、annotation_data、base_version=0 |
| 修改 | PUT `/api/annotations/<最新标注ID>`，annotation_data和base_version=当前version，必填；生成新ID/版本，旧内容保留 |
| 当前列表 | GET `/api/annotations?project_id=<UUID>`，默认latest_only=true，可按asset_id/review_status筛选 |
| 历史 | GET `/api/annotations?asset_id=<UUID>&latest_only=false`；旧ID仍可GET回读 |
| 审核 | POST `/api/annotations/<最新ID>/review`，approved、review_comment；历史版本审核返回409 |
| 操作记录 | GET `/api/annotations/assets/<资产UUID>/events` |
| 批量审核/删除 | 原批量路径保留，按同一资产锁/最新版本规则更新；历史版本不能批量覆盖 |

修改会撤销当前审核，重新待审核；已通过的旧版本保留其当时的审核记录。资产行锁与两个唯一索引保证每图最多一条最新标注、版本不重复。409表示页面已过期，需要记录修改后重载；不自动覆盖其他人的结果。工作台支持矩形绘制、移动、右下角缩放、数字坐标/类别编辑、删除、上一张/下一张、历史只读；切图先自动保存，失败保留原图草稿，离开工作台仍提示未保存修改。

删除当前标注移除该记录，之前版本保持历史而不自动恢复为最新；删除事件保留内容/版本。重新创建继续版本号，不复用已删除版本。项目annotated_count统计有最新标注的图片（含负样本/驳回），reviewed_count只统计最新审核通过图片；历史版本不重复计数。手动批量改资产状态不能伪造审核；删除资产同步减少计数。时间按UTC传输，页面按本机时区显示。

## 项目类别同步

PUT `/api/projects/<UUID>`：`label_schema`提供最终类别配置；改名另传`label_renames`（旧名称→新名称）及`base_label_schema`（编辑前原配置，可为null）。例如原配置人、最终配置person，传`{"label_schema":{"labels":["person"]},"base_label_schema":{"labels":["人"]},"label_renames":{"人":"person"}}`。原配置已为person但最新框仍为人时，base也应为person；旧框使用的名称仍可作为映射来源。

受影响的最新标注在一个事务中同步，每图追加待审核版本，计数同步；历史/冻结包不变。使用中的类别被删除而未映射、来源未知或目标不在最终类别列表均返回400；原配置已变化返回409。映射必须显式提供base配置，不能根据类别顺序猜测。新增/排序而未改名不新增标注版本。

工作台按钮/快捷键切图使用原标注创建/更新接口，仍携带base_version；有修改先保存，失败不切图。无修改不写入；删空后须确认负样本。刷新/关闭浏览器不保证自动保存。见[操作说明](../development/检测标注操作说明.md)。

## 导出与冻结

项目图片页提供“导出 / 冻结数据集”。YOLO、COCO均输出图片+标注+manifest的ZIP，按资产UUID命名避免同名图片覆盖。默认只导出最新审核通过标注；可明确选择含未审核范围。类别过滤保留图片，只去掉未选框；无框图片对应空YOLO标签/零COCO框。JSON/CSV保留旧数据导出，改为只含当前标注。

| 操作 | 接口与约定 |
|---|---|
| 当前图片包 | GET `/api/export/projects/<UUID>/export?format=yolo或coco&labels=人,车&approved_only=true` |
| 仅COCO JSON | 相同接口追加package=false；COCO ZIP为当前默认行为 |
| 冻结 | POST `/api/export/projects/<UUID>/snapshots`，format、labels数组、approved_only、splits对象（每个导出资产UUID对应train/val/test） |
| 冻结列表 | GET `/api/export/projects/<UUID>/snapshots` |
| 轻量冻结列表 | 同上追加 `summary_only=true`，返回图片数量，不返回完整标注清单 |
| 冻结下载 | GET `/api/export/snapshots/<快照UUID>/download` |
| 删除冻结版本 | 管理员 DELETE `/api/export/snapshots/<快照UUID>`；被训练任务或验证集引用时返回409；保留原图、标注及操作记录 |
| 导出标签及图片数 | GET `/api/export/projects/<UUID>/summary`，按最新标注和项目标注范围统计全部/审核通过图片数，各类每图计一次 |
| 按简化规则下载 | POST `/api/export/projects/<UUID>/packages`，与冻结请求共用 `selection` 规则 |
| 当前分布 | GET `/api/stats/projects/<UUID>/distribution` |

2026-10-22：导出弹窗使用简化 `selection`，支持 `mode=ratio/train_only/val_only`，分别表示按比例、仅训练集、仅验证集；传入 `ratios={train:80,val:10,test:10}`、`budgets={标签:数量或null}`。预算只限制训练图片，仅验证集不应用训练预算。预览、下载、仅冻结和冻结并下载使用相同规则；修改条件后必须重新预览。仅验证集全部放入 `val`，仅训练集全部放入 `train`（受预算限制）。单组包可下载和冻结，平台训练器仍要求同时提供训练和验证数据。标签汇总与冻结版本列表独立加载，预览、导出和冻结统一显示实际等待秒数。

旧 `splits` 请求仍要求完整、显式的划分，训练集总量与独立测试图分开计算；旧GET下载包的all组未划分，仅用于检查，训练/评测前应冻结合适划分。YOLO标签为0起始类别索引和归一化中心/宽高，data.yaml记录类别；COCO categories为1起始ID，每个真实框一条annotation，area=宽×高。manifest记录资产/标注ID及版本、原图哈希、类别/过滤范围、审核状态、分组及框。包内原图哈希/尺寸必须与资产一致，缺失文件明确失败；未经标注的图片不冒充负样本。

新YOLO包不设置path字段，路径以data.yaml所在目录为根，解压位置/启动工作目录可变化。train、val、test键始终存在，未分配的组为[]，绝不以训练图充当验证/测试图。仅训练组的包可供加载检查，但缺验证/测试数据的包不代表评测可用。此前冻结包保持旧内容，使用新格式需重新冻结。[Ultralytics配置说明](https://docs.ultralytics.com/datasets/detect/)及[官方加载器源码](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/data/utils.py)为验证参考。

冻结ZIP独立保存到统一存储exports目录，复制是交付快照所需；图片原始存储和项目引用仍共享。后续标注编辑不会改变旧包，重新下载返回相同字节。分类/来源/划分/负样本分布随快照冻结；当前项目另显示设备、质量、状态，缺省明确为未知/未评分，不计算虚假质量分数。

内容哈希和尺寸检查始终保留。简化模式的来源分组、pHash、颜色检查默认关闭，可在高级选项中启用并设置阈值；默认64位pHash距离≤4且平均RGB最大通道差≤20时拒绝近重复跨组。旧 `splits` 路径保留原检查。此规则是保守的启发式检查，无法证明任意裁剪、改色或跨帧内容没有泄漏；独立测试划分仍需人工核对来源。

## 复现真实加载器验收

验收用独立Python，不给运行API安装Torch或Ultralytics。本机D:/anaconda已有CPU Torch 2.6.0和Torchvision 0.21.0，已借用这两项依赖建立`backend/backend/.backups/loader-env`；Ultralytics 8.4.176和pycocotools 2.0.11单独固定于requirements-loaders.txt。其他机器需先在验收环境安装匹配的CPU Torch/Torchvision，再装该SDK清单，不自动下载模型。

在主后端目录执行：

```powershell
$env:P0_POSTGRES_INTEGRATION='1'
$env:P1_POSTGRES_INTEGRATION='1'
$env:P2_POSTGRES_INTEGRATION='1'
$env:P2_LOADER_PYTHON=(Resolve-Path '.backups/loader-env/Scripts/python.exe').Path
.venv/Scripts/python.exe -m pytest -q
```

SDK用例通过独立SQLite API上传合成图片、保存/审核及导出，再由指定Python在不同工作目录中真实读取。普通pytest默认跳过6项SDK与4项PG用例，不能把跳过计为实跑通过。`scripts/verify_detection_package.py`也可独立检查已解压的本平台ZIP目录，逐张核对图片哈希、类别和框，并加载图片/张量；只禁用可选的字体下载，不替换数据加载器。

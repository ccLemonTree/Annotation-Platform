# 独立图片库与项目引用 Implementation Plan

**Goal:** 上传/拉取先进入图片库，再由标注项目选择图片；同图可用于多个项目，原图不复制。

**Architecture:** 新增租户范围的images图片目录，内容哈希去重；已有assets保留为项目使用记录，并增加image_id引用。标注/审核/版本继续绑定项目使用记录，保留已有ID和冻结包；删除项目只删除项目引用。

**Tech Stack:** 现有FastAPI/SQLAlchemy/PostgreSQL、React/AntD和统一存储，无新依赖。

1. 新建tests/test_image_library.py，验证无项目上传、独立筛选、同图多项目、重复关联、审核隔离、删除保护及越权；先确认失败。
2. 新增images模型/Schema、服务与API；复用上传校验和存储。旧项目上传接口兼容，但同样登记图片库；项目添加图片采用事务和幂等计数。
3. SmartEye所有最终下载结果进入图片库，可选自动关联；取消/旧attempt不能登记晚到图片。临时裁剪原图继续不作为标注素材。
4. Alembic008回填现有项目图片及SmartEye文件；保留Asset/Annotation/快照ID与数据，原图不搬动。先在独立PG验证迁移和并发，再备份主库后执行。
5. 图片管理默认独立图片库，提供名称/来源/批次/时间筛选、多选添加项目；可切换项目使用视图，项目移除只取消引用。项目页新增使用图片入口，继续采用统一AntD组件。
6. 回归测试、双入口构建和浏览器验证；更新TODO、接口和操作文档，明确历史版本与冻结包保护范围。

验收：不建项目也能上传和筛选；多个批次可添加同一项目，同图可添加多个项目；删除项目不影响图片库/其他项目标注；旧test-img标注、类别、审核、冻结包和原图哈希不变。

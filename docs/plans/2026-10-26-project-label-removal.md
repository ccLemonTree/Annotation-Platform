# 项目批量删除指定类别框

**Goal:** 管理员在检测标注工作台预览并删除当前项目全部参与标注图片中的指定类别框，当前需求为 person。

**Architecture:** 复用项目租户隔离、标注范围规则、save_annotation 和审核计数；修改建立新版本并保留历史。预览返回影响图片数/框数/空标注数及状态摘要，执行锁定资产后锁定项目并重算摘要，过期预览拒绝，全部写入在同一事务中完成。

**Tech Stack:** FastAPI、SQLAlchemy/PostgreSQL、React/Ant Design，沿用现有 API 客户端。

## 范围和假设

- 用户已明确选择当前项目全部图片中的 person 框，其他类别框和图片保留。
- 按项目现有 annotation_scope 处理；仅裁剪图项目继续排除原图。
- 管理员专用；项目类别配置、图库原始导入标注、其他项目副本及冻结导出包保留。
- 受影响的当前标注建立新版本并重新待审核；空框版本作为待审核负样本，不自动通过。
- 工作台有未保存草稿或正在绘制时禁止发起批量操作，避免覆盖本地修改。
- 执行后刷新当前标注、历史、审核计数及导航；清除可能已无结果的标签筛选。
- 开发和验收不自动删除业务项目的 person 框，最终由用户点击确认执行。

## 决策与验收

1. 使用既有版本机制而非直接修改 JSON 或物理删除历史，保持审核与导出语义。
2. 写失败测试：类别精确匹配、全项目/裁剪范围、其他项目及图库保留、审核计数、空标注、历史保留、过期预览/重复提交、权限/租户、事务失败回滚。
3. 在 project_labels 服务和项目 API 增加预览及执行；无迁移、依赖或独立任务队列。
4. 工作台新增按钮、类别选择、数量预览及确认弹窗；默认当前筛选类别或 person，未预览或零命中不能执行。
5. 专项后端回归、真实 PostgreSQL 并发/原子性检查、前端构建和隔离浏览器验证取消零写入、失败保留、成功刷新、普通用户隐藏及手机显示。
6. 本地加载新接口后仅只读预览真实项目，确认业务数据未改变。

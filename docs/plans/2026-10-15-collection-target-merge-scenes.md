# 上传目标、现有图片集合并与场景并发

**Goal:** 上传默认已有图片集，将1015并入绍兴嘉兴误报-1015，保留原图、分类及上传回执；改善场景串行吞吐。

**Architecture:** 两个上传入口共享目标选择：当前筛选→上次已使用且仍存在的图片集→已有第一集；无现有集时留空，不默认日期。显式手动命名仍保留。合并只改成员、会话归属/续传键和分类规则引用，不复制图片或重跑成功分类。分类使用有界asyncio任务共享HTTP连接；默认4，可设1–16。

**Tech Stack:** 现有React/Ant Design、SQLAlchemy/PostgreSQL、asyncio.TaskGroup、httpx，无新依赖。

1. 浏览器先验证默认目标/刷新记忆/空状态入口；worker并发和取消测试先失败，再做最小修改。
2. 合并服务先用隔离库验证交集去重、上传回执/续传缓存、分类结果保留、活动任务拒绝；实库操作前私有备份。
3. 记录原1并发20秒吞吐；维护时锁住未领取队列、等待当前推理完成，再核对并停止本项目后端，合并同一事务提交后重启。避免把正常进行中的推理标失败。
4. 跑相关及完整回归、双入口构建、浏览器；实库核对成员并集、原图/标注引用、分类成功结果和上传回执。对比4并发吞吐/失败数，不承诺固定倍数，不改模型服务/K8s资源。

不增加通用合并页面、调度器、EOS或多实例租约，不提交推送。活动上传不能合并；发现用户新上传先保留并等待。

完成：195项完整回归、21项浏览器检查、双入口构建/pip check及实库只读API通过。合并4676图和10条回执，4并发20秒完成39张（原16张）。首次维护端口检查失败后回滚，重试前重新备份并排空推理，随后成功合并。详情见[验收](../testing/collection-merge-scenes-verification-2026-10-15.json)。

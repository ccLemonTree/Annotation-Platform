# 通用目标属性分析实施计划

**Goal:** 拉图后按目标标签检测、逐目标切图、按可编辑属性定义分析，支持结构化保存、修正、筛选和导出。

**Architecture:** 复用描述项目、ProjectWorkJob 队列、项目私有裁剪图和标注版本。属性配置保存在项目 label_schema，结果及配置快照保存在 annotation_data；无需新表。检测批次完成后自动建立逐裁剪图的属性批次。

**Tech Stack:** FastAPI / SQLAlchemy / Pydantic / React / Ant Design。

## 约定与决定

- 通用功能，车辆模板默认目标 car 和七项属性；可改为 person 等目标并增删改属性。
- 大模型输出直接作为结构化属性预标注，来源为模型且待审核；支持检测后自动预标注和已有目标图单独预标注。
- 属性定义包含稳定 key、名称、说明、可选值；空可选值表示自由文本。每项结果为 value（字符串或 null）、reason；无法判断必须 null，不猜测。
- 项目配置和模型配置固定快照；配置变化、人工修改、审核、取消或权限撤销阻止迟到结果写回。已有标注不自动重跑。
- 沿用单进程串行队列、每批最多5000张、租户与项目权限、版本审核和私有存储。用户主动选择图片并启动处理，不自动扫描历史业务数据。
- 定时抓图绑定项目；场景和设备不限低位交通，沿用用户选择。场景多选可选择任一匹配或全部匹配，支持按需组合。
- 拉图后在项目中主动启动检测与属性分析；不改变全部现有抓图计划的自动处理行为。
- 原图保留、导出保留框坐标与来源；未知值不作为否定属性。模型可见证据无法替代独立效果评测。

## 实施与验收

1. 属性定义、结果校验与解析 → 先写隔离测试，覆盖未知、非法/缺失JSON、枚举、普通描述兼容。
2. 检测后自动创建属性队列 → 测试 car 标签、逐目标来源、重试/取消、人工修改与配置变更保护。
3. 属性配置、人工编辑、数据库分页前筛选、JSONL/CSV导出 → API与隔离数据库测试、浏览器 mock 流程。
4. 任意场景组合筛选与拉图项目入口 → 测试交集条件、分页和选择清空。
5. 前端构建、相关回归、操作文档 → 本地通过后检查115活动任务，备份并同步本次文件，允许重启时发布并只读验收；有活动任务则保留待发布包。

## 非目标

不新增依赖、训练算法、独立微服务、专用车辆表或图像质量评分。人物等其他模板可通过已有属性编辑器配置，不预设用户未确认的属性名单。

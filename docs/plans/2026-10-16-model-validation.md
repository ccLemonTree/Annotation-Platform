# 检测模型验证集实施计划

**Goal:** 在独立验证集页面用冻结真值评估已部署检测模型，查看指标和逐图错误，不改业务标注。

**Architecture:** 复用项目审核标注、冻结导出清单、模型管理和存储。验证集固定类别、原图哈希、标注版本与真值；独立持久任务固定模型配置及参数，后台推理。报告只统计成功样本并明确失败/取消覆盖率，未完成结果标为部分结果。

**Tech Stack:** FastAPI、SQLAlchemy、PostgreSQL、React、Ant Design；无新增依赖。

## 范围与默认规则

- 首版检测任务。真值来自项目已审核标注或冻结包的val/test划分，包含确认负样本；项目来源不宣称独立于训练数据。
- 三张表：validation_sets（samples为有界JSON快照）、validation_runs、validation_items；每集最多5000张，超限拒绝而非截断。
- 管理员创建集、执行/取消/重试；同租户用户查看，结果不覆盖标注。原图不复制，读取前校验哈希；原图删除后保留报告，不能重新推理。
- 标准框IoU、按置信度一对一匹配、Precision/Recall/F1、101点AP50与AP50:95；AP每图每类最多100个预测。无真值类别AP为空，空集指标为空，负样本误检单列。
- 推理置信度默认0.001，工作点0.25，匹配IoU0.5，NMS IoU0.45；工作点不得低于推理门槛。显示这些条件，不称为完整COCO评测（无面积/crowd专用规则）。
- 提供类别映射、分页逐图真值/预测叠框和漏检/误检/类别混淆过滤、JSON报告；不上传权重到本地执行，使用模型管理配置的检测服务。
- 单后端任务恢复沿用既有模式；服务重启将处理中条目标失败供手动重试。

## 执行与验证

1. 指标计算（services/detection_metrics.py及定向测试）：先验证完美/重复/分类错误/负样本/空集/排序/IoU边界，再实现；与已知手算及可用独立加载器对照。
2. 数据与任务（models、schemas、services、api的validation模块）：先测权限/真值快照/过滤/取消/重试，再实现持久队列及快照隔离；推理前后校验模型修订、图片哈希及管理员权限，不追随当前真值变化。
3. 页面（ValidationPage.tsx、api/validation.ts及路由菜单）：创建验证集、创建验证任务、进度与报告、逐图叠框和失败提示；沿用项目组件，窄屏表格内滚动。
4. 接入与迁移：016只增三表；更新空库初始化/迁移测试，隔离PG验证后备份升级本地业务库。检查存储清理时验证集快照引用，避免原图误归档。
5. 联调：定向及必要回归、前端构建、浏览器拦截写入验证、真实只读页面；不自动对整库运行模型、不改变用户标注。更新TODO、操作说明及验收JSON。

无提交或推送；保留无关工作。真实模型准确率只有在用户选定独立真值集并执行后才产生，不用模拟样本结果代表效果。

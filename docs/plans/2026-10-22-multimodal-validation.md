# 大模型描述与向量验证 Implementation Plan

**Goal:** 为图片描述、文搜图和图搜图提供验证及效果预览，同时支持已部署服务和服务器模型目录/LoRA权重。

**Architecture:** 复用 ValidationSet/Run/Item、现有队列和独立容器生命周期；通过 task_type 区分指标，不增加数据库表或写入业务向量索引。描述由人工对照冻结真值复核；向量在本次冻结候选集中进行精确余弦检索，报告已审核正样本的 Hit/Recall@1/5/10、MRR，排除同内容自身命中。

**Tech Stack:** FastAPI, SQLAlchemy JSONB, httpx, React/Ant Design, ms-swift TransformersEngine/PtEngine。

## 决定与边界
- 用户确认两类模型来源；大模型仅图片描述；向量包括文本查询和图片查询。
- 合并模型目录可直接使用；LoRA目录需明确基础模型目录。服务器与镜像采用现有训练配置，单卡GPU预留与取消规则不变。
- 复用人工审核描述、MatchQuery已审核匹配，冻结图片哈希及版本。不把自由文本字面差异判错，不将未判定候选作为负样本。
- 向量仅本次任务内检索，不污染原项目索引。结果向量留后端，接口仅返回维度、排名、分数和判定。
- 原检测接口默认行为、历史数据保持兼容。单批最多5000张、最多200条查询；失败隔离、失败重试，取消后不写入迟到结果。
- 本地上行异常期间，不启动真实全量上传或训练，不修改SSH管理器。

## 任务与验证
1. schema、冻结描述/查询、指标纯函数 → 隔离测试确认审核边界、自身排除、多正样本、无正样本、无效向量。
2. 服务调用、队列、复核与报告 → API/worker测试确认租户、取消、失败隔离、重试和检测兼容。
3. 服务器目录/LoRA校验、Swift批推理 → 目录内容指纹及模拟引擎测试；单次加载、逐图失败、批量结果下载。
4. 两页面任务类型选择、来源/参数、描述对照/复核、检索查询/排名 → TypeScript构建和浏览器交互检查。
5. 聚焦回归、文档与服务健康核对 → 不用真实业务数据作为写测试。

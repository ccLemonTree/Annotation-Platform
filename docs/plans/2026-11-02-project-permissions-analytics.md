# 项目分配、普通用户权限与图片工作量实施计划

**Goal:** 普通用户只能在管理员分配的项目内人工标注、审核；管理员按用户和日期查看去重图片工作量。

**Architecture:** 用项目成员关联表保存管理员分配关系，后端默认拒绝普通用户的管理操作，在项目和资产读取、标注写入及批量审核入口校验成员资格。前端复用项目管理弹窗和统计表；图片张数从现有人工事件按用户、模式和资产去重，保留原次数及效率口径。

**Tech Stack:** FastAPI、SQLAlchemy、Alembic、PostgreSQL；React、TypeScript、Ant Design；隔离 SQLite pytest 和浏览器接口模拟。

## 范围与假设

- 同一项目成员可人工标注和审核，不新增独立角色体系。
- 管理员保留同租户全部项目权限；未分配成员的项目仅管理员可见，旧项目和记录不迁移或删除。
- 普通用户菜单和路由仅保留标注、审核及其工作台；模型仓库、数据管理、AI任务和分析接口管理员专用。
- 继续保留负样本和 AI 转人工须管理员最终审核的既有规则。
- 张数按筛选窗口内的人工操作事件对资产去重；同图反复保存或审核计一张，次数仍分别保留。多用户处理同图时个人各计一张，总张数只计一次。
- 沿用项目筛选和浏览器本地日期筛选（含结束当天）；不回填历史活跃时间，不新增考勤或绩效规则。
- 采用现有服务和数据规模，权限在数据库查询中筛选，不加载整个租户再做前端过滤；115更新前检查活动任务。

## 决策

1. 使用项目成员表而非在标签配置中存用户，保证外键、撤销和查询范围可验证。
2. 不新增人员管理页面，复用现有同租户用户列表供管理员分配。
3. 保留操作次数及效率分子，只追加去重图片张数，避免更改已有报表含义。

## 实施与验收

1. **后台权限与分配**：新增 `models/project_member.py`、`services/project_access.py`、迁移034和 `tests/test_project_permissions.py`；修改路由/鉴权及隔离夹具。先验证普通用户越权、未分配项目、跨租户分配、撤销、混合批量操作等测试失败，再最小实现并通过。
2. **图片工作量**：修改 `services/annotation_analytics.py`、`tests/test_annotation_analytics.py`。先覆盖重复保存、多用户同图、自动/复用排除、时间区间，再增加总量及用户张数字段。
3. **前端**：修改 `MainLayout.tsx`、`ProjectsPage.tsx`、`AnalyticsPage.tsx`及API类型和相关工作台按钮；新增界面验证脚本，验证分配保存、普通用户跳转和张数/日期筛选，再执行TypeScript及Vite构建。
4. **交叉审查**：检查普通用户完整人工标注/审核调用链、所有直连管理入口、项目成员撤销及回归测试，不更改无关业务。
5. **115更新**：只同步本次差异，备份被替换文件；只读检查活动训练/验证/上传/下发任务，执行新增迁移并按需重启平台后端，验收健康、管理员分配和普通用户范围。保留旧项目数据。

本地验证强制数据库指向不可连接端口，使用临时SQLite和临时图片目录；不连接业务库写入。

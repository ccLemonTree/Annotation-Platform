# P1 完整 SmartEye 内置实施

主平台内复用正式仓库 ebee9a9 及用户工作目录已存在的去重修复；不修改原目录。假设第一版单租户、一个后端进程、本地文件系统。真实平台账号与 AI 服务沿用私有配置，测试不自动请求外部平台或付费服务。

1. 迁入完整 Flask API 与六类 React 页面，隔离 Python 包、API 路径和前端样式。验证：逐项路由清单、统一认证、主前端构建。
2. PostgreSQL 独立 smarteye schema 保留原 SQL 功能；新增主库任务/文件/调度配置持久表。删除导入时的建表、启动线程、修改代理环境变量等副作用。验证：独立测试数据库迁移、重复初始化及原核心数据保留。
3. 原下载写入共用存储校验与哈希路径，SmartEye 目录使用同盘硬链接，项目只创建资产引用。任务选择仅下载/关联项目。验证：合成真实 HTTP 图片下载、ZIP、图片读取、哈希/硬链接和去重计数。
4. 保存进度、用途、操作者、取消及重试依据；后台使用自己的数据库连接。取消及旧执行轮次禁止后续关联。重启标记中断，不自动重复执行非幂等 AI 请求；保留独立调度配置并允许显式重新启动。验证：取消迟到结果、重启重试、两个平台调度隔离和原解析/去重回归。
5. 运行已有回归、新集成测试、前端构建和浏览器检查，更新 TODO 与实测证据。真实外部平台、付费 AI、EOS 与 Docker 的未验证范围单独记录，不将路由存在当作完整验收。

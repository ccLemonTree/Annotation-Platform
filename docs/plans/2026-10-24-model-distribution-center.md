# 模型下发中心实施计划

**Goal:** 独立页面统一保管模型版本，批量选择部署目标，记录各服务器模型和镜像版本。

**Architecture:** 沿用已确认的 SSH 桥接、独立下发记录和手动生效方案；模型归档一次，多目标复用同一校验包。批次保留每个目标的独立结果，部分失败不标为全部成功。

**Tech Stack:** FastAPI、SQLAlchemy/PostgreSQL、Python 标准库、React/Ant Design、ssh-manager。

## 已确认范围与假设

- 用户要求独立页面、每台服务器模型版本、多选下发、统一本地保存，以及多服务器镜像更新。
- 用户确认镜像包括 Triton/vLLM、NexusAI HTTP 和 Kafka worker；本地指平台后端所在服务器。
- 延续先传输校验、后手动生效；不自动更新生产服务，不改变 Kafka topic、消费组或业务路由。
- 管理员按需拉取已完成的导出/完整模型，保存不可变版本、来源任务、SHA256、大小和归档时间；不自动删除旧包。
- 服务器目标保存明确的仓库/模型槽位或镜像服务选择。同一服务器可以有多个模型或服务，不能把整台机器简化成一个版本。
- 版本台账区分已核验、生效未完成和未纳管；只在全部目标实例核验成功后认定模型已生效。历史记录不等同于实时盘点。
- 单后端进程、批次最多50个目标，后台执行；保留租户隔离、连接快照和操作互斥，应用重启后待核对，不自动重放。

## 决策记录

- 复用既有下发执行器及记录，而非另建发布平台；用户已接受该方案，本轮增量沿用。
- 本地保留校验后的模型包，批量下发无需反复从训练机拉取；不用浏览器保存大模型。
- Docker 优先复用已存在 Compose 服务配置；K8s 更新明确的容器镜像并等待全部副本收敛。保留旧版本及恢复记录。
- 镜像拉取和运行实例切换分别显示。每个 K8s 环境使用自己的 `preload-ai-images.yml`：控制机拉取导出、每批4台节点分发、逐节点核对包SHA256和containerd摘要；同批次同环境复用结果。手动生效前再次核对全部实时节点，使用固定镜像摘要与 `imagePullPolicy: Never`，避免节点同时回源拉取。

## 实施与验收

1. 写失败测试：归档校验/租户隔离、目标配置、批次去重与部分失败、版本台账、镜像更新范围和恢复；隔离数据库及模拟远程命令。
2. 增加模型版本与目标配置，扩展既有记录关联版本、目标和批次；本地文件仅使用后端生成路径。测试归档损坏、磁盘不足和中断不成为可下发版本。
3. 复用模型执行流程，从本地归档向多目标分发；统一记录服务操作互斥和每实例结果。测试旧记录不覆盖新版本、批量失败隔离。
4. 增加镜像检查、准备、手动更新和恢复，保存旧/新镜像及实际运行ID；测试只修改选择的服务、配置保留、并发冲突与未完成核验。
5. 新建独立页面及侧栏入口，训练页面链接带入来源任务；覆盖版本归档、目标多选、逐台结果和确认弹窗。前端构建、专项后端回归和真实浏览器隔离流程验证。
6. 真实服务器仅只读盘点；本轮不推送模型、不拉取生产镜像、不重启生产服务。

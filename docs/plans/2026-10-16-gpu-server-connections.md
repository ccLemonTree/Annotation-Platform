# GPU服务器连接实施计划

**Goal:** 管理员在GPU资源页输入服务器IP、端口、账号、密码，测试并保存多台NVIDIA服务器，自动展示显卡与计算进程。

**Architecture:** 保留现有ssh-manager连接及默认GET接口；新增一张租户隔离的gpu_servers表，密码用Fernet认证加密。动态连接只经stdin进入现有Node MCP桥，在子进程环境中临时定义唯一只读连接，不写ssh-manager全局配置或明文配置文件。复用原NVIDIA指标解析及按服务器/修订隔离的15秒采集缓存。

**Tech Stack:** FastAPI、SQLAlchemy/PostgreSQL、现有cryptography依赖、ssh-manager MCP SDK、React/Ant Design。无直接SSH库。

## 规则与边界

- 管理员操作，IP仅IPv4/IPv6字面量，默认SSH端口22、用户名root；只执行固定nvidia-smi查询，不接受命令。
- 密码只写不读，响应仅has_password；编辑留空保留，重填替换，可明确清除。更改IP/端口/用户名时必须重填密码，防止旧密码发到另一个目标。
- GPU_CREDENTIAL_KEY可配置独立Fernet密钥；未配时以现有JWT密钥按用途派生，轮换该密钥后须重填密码。接口、错误和日志不输出密码/密文，浏览器不持久保存密码。
- 新增/编辑服务器、启停采集、删除记录和未保存连接测试；保留默认ssh-manager连接只读兼容，不读取或迁移其密码。
- 每次采集固定目标与修订，修改/删除后拒绝旧结果；跨服务器不保留旧图表作为新服务器数据；默认每30秒刷新，隐藏暂停，失败保留当前服务器最后一次数据并标明陈旧。
- 只支持可经SSH访问、安装Python3及nvidia-smi的Linux NVIDIA服务器；不安装驱动、不调整服务、不中断进程，无训练调度。

## 实施与验收

1. 后端连接模型/Schema/凭据与CRUD：先测试权限、隔离、密码不回显、目标变化重填、修订/缓存保护、删除，再实现。父任务处理017迁移与空库初始化测试。
2. MCP动态连接：先验证密码仅stdin传递、不进入argv/文件、不读取全局连接、错误脱敏，再实现环境连接和服务器缓存；旧默认采集及测试兼容。
3. GPU页面管理：复用原逐卡/进程展示，增连接表单和选择器；测试表单密码生命周期、修改保留/替换/清除、未保存测试和切换取消/迟到保护。
4. 隔离PG增量迁移/CRUD、已有采集真实MCP读取、浏览器拦截写入和真实只读页面；全量回归、双入口构建与文档。未提供的新服务器密码不猜测，不在业务库写假服务器。

保留全部现有业务数据与无关改动，不提交或推送。

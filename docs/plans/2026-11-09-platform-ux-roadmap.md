## 一、产品方向

建议把现有平台打磨成“以项目为中心的数据生产与效果验证工作台”。默认路径应当让新人完成一件事，熟练用户能跳到需要的阶段，不强迫所有项目走完采集、训练、部署。

销售暂按“进入自己获授权的项目、查看项目进展、展示已批准样例与结果；有需要时做受限试测”设计。是否允许销售自行建项目、上传客户样本、启动收费推理、导出原始数据，属于后续实施前要确定的权限范围；本轮不默认开放。

| 核心目标 | 具体产品约定 | 可检查的结果 |
| --- | --- | --- |
| 自由度高 | 推荐流程可跳过；已有模板可直接用也可改；专业参数按需展开；只重跑选定范围与失败项 | 熟练用户不用反复走向导，也不会为改一个参数重做整批 |
| 操作简单 | 每个阶段一个主要动作；项目、范围、保存状态始终可见；禁用按钮解释原因和下一步 | 新人不用问人也知道当前能做什么、为什么不能做 |
| 比人工效率高 | 模型先处理，人重点复核；保持队列与位置；批处理可恢复；以最终合格产出计时 | 比较同等质量下每百张合格数据的人工耗时与返工率 |
| 以项目维护 | 图片引用、配置、任务、审核、数据版本、模型结果和成员权限在项目内串联 | 从项目能查清“哪批图、哪套配置、哪个版本、谁处理、结果如何” |
| 销售也能用 | 按项目授权的展示入口；业务化结果摘要；演示与正式评估分清 | 销售能独立展示一个项目，无法误改标注、启动训练或看到其他项目资料 |

## 四、自由度与简单如何同时做到

1. **默认就能开始，专业设置随时可开。** 项目内复用已有模型、属性模板和最近有效配置，常用范围清楚可改；不让新用户先理解超时、并发、提示词、数据格式才能完成第一件事。
2. **有建议顺序，没有强制流水线。** 数据、标注审核、导出训练、测试评估仍可直接进入；已经有数据或模型的项目不需要重走采集或训练。前置条件不足时讲清缺什么，并给直接修复入口。
3. **改动可追溯，局部可重做。** 修改范围、模型或配置后说明对新任务和已有成果的影响；默认保护已审核结果，不把自由配置变成静默覆盖。
4. **复用现有能力。** 优先复用已有属性模板、项目配置和图片引用规则；暂不设计通用拖拽流程引擎，也不增加大而全的自动化编排。

## 五、销售最小可用路径

建议首版：
“我的项目 → 项目概况 → 选定展示样例/已批准结果 → 查看效果与限制 → 展示结果摘要”。

项目概况只需回答：解决什么问题、用在哪类场景、当前做到哪一步、有什么效果证据、还有什么限制、谁负责。先放入现有项目描述与结果页，不先做CRM、商机、报价和客户管理体系。

技术人员仍负责模型服务、提示词/阈值等专业配置、数据审核、训练和部署。销售如需自己试图，入口使用已经配置好的项目方案，并清楚标注“试测结果”；原始客户图的上传、保留及可见范围须在实施前确定。

**权限实现注意：这是未来开放权限时的风险，不是已发现线上泄露。**
现有验证列表可省略 project_id，部分详情、报告和逐图资源的底层仅按租户查询。不能仅给普通用户开放验证 GET 接口；必须在每个资源入口核验授权项目和允许展示的结果。

## 六、建议执行顺序

**第一批：先减少当前使用者的重复动作。**
- 属性列表 → 编辑 → 下一张 → 返回保持同一范围。
- 普通待审入口与继续标注采用一致的范围选择。
- AI 转人工审核保留位置并支持连续处理。
- 智搜状态读取失败可见，恢复行为清楚。

**第二批：项目内闭环。**
- 项目搜索和具体“继续工作”。
- 批处理的范围、来源、结果与失败恢复一致。
- 冻结版本直接带入训练与评估。
- 工具栏层级、禁用原因、保存/未保存状态和空态文案集中打磨。

**第三批：销售试用。**
- 项目范围的只读展示能力。
- 业务结果摘要与演示路径。
- 在实际需要时增加受限试测；做权限接口和直链验证。
- 让真实销售人员独立完成一次展示，再决定是否增加更多能力。

质量/效率测量从第一批开始，不等第三批才补。这里是工作顺序，不是工期承诺。

## 七、如何证明比人工快

选同一难度、数量及交付标准的样本，分别跑纯人工与模型辅助流程；控制熟练度/学习效应，必要时交叉分配同等难度样本。由独立复核判断是否合格，不能把模型自己的输出当真值。

记录：
- 每百张合格结果的人工实际操作时间；
- 后台等待时间与总交付耗时，分别统计；
- 需要重筛、重复选图、返回列表、重复提交的次数；
- 一次通过率、返工率及漏检/误判等任务质量指标；
- 失败后的恢复时间。

先取得基线，再确定提效门槛。现阶段不能承诺“已快几倍”。已有快捷键、批处理或高并发不等于业务效率已经提升。

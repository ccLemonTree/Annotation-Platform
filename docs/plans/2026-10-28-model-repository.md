# 模型仓库实施与验收

目标：独立模型仓库页面管理 PT、ONNX 和 TensorRT，支持已有训练产物入库、直接上传，以及其他服务调用上传和下载接口。

## 范围与决定

- 新增独立仓库记录，复用平台登录、租户隔离、训练产物读取和 SSH MCP 传输。已有模型下发中心的 release 格式和行为保持兼容。
- 登录用户查询和下载本租户模型；管理员上传、训练入库和失败重试。外部服务通过现有登录接口获得 Bearer Token。
- 同一名称、版本可以保留不同格式、不同 GPU 的产物；同一组合不覆盖已有模型。TensorRT 必须标明 GPU 型号，可记录 TensorRT 版本。
- ONNX 的外部权重随主文件保存；多文件下载为 ZIP，单文件下载保持原文件名。不执行上传的模型，不自动转换或部署模型。
- 训练入库只读已完成任务的稳定产物，复制到平台持久化目录并核对大小和 SHA256；保留来源任务及原文件。后台复制失败可重试，重启中断不会显示为就绪。

## 实施与验证

1. 后端：仓库表与迁移、接口、文件持久化和训练入库。用 SQLite、临时目录及模拟 SSH 验证三种格式、ONNX 配套文件、GPU 必填、重复版本、租户与管理员边界、非法路径、体积限制、传输损坏和失败清理；回归训练下载与模型下发。
2. 前端：侧栏入口、列表筛选、上传、训练来源选择、下载和调用说明。通过构建及 API 隔离的浏览器检查覆盖管理员/普通用户、错误状态和小屏布局。
3. 115：本地通过后同步代码，核对活动训练、验证、上传、自动处理和下发；执行新增表迁移，安全重启后端并验证真实 HTTP 和页面资源。生产库不写测试模型，真实业务数据验证与隔离样例验证分别记录。

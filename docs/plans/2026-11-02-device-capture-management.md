# 数据拉取与平台设备管理实施计划

**目标：** 平台可管理并显示连通性，按设备定时拉取已有抓图、绑定项目，设备场景自动识别且允许人工修正。

**已确认：** 2026-11-02 用户选择最近抓图自动分类并支持人工修正；选择周期拉取已生成抓图；确认完整范围。

**架构：** 保留 SmartEye 同源入口和主身份认证；平台连接配置使用既有 smarteye.platforms，新增 managed 标记保护手工配置。连接检测、平台与设备复合身份、设备场景和抓图计划使用独立持久状态，不修改历史图片、标注或项目引用。复用已有台账分页、图片入库、项目引用和 Qwen 分类逻辑。

**技术：** React/Ant Design、FastAPI→Flask、SQLAlchemy、PostgreSQL、既有后台线程及图片分类模型，不增加依赖。

## 假设与决定

- 沿用单后端进程部署；平台同步、设备分类与抓图限制后台并发，不阻塞页面。
- 平台启用状态与真实登录检测分开；无法确认的设备状态不冒充在线。
- 删除平台使用删除标记，阻止后续同步复活；保留历史、原图和项目资料，活动任务引用时拒绝删除。
- 定时器重启后保留配置并暂停，页面说明需手动恢复；每设备完整成功后推进游标，失败保留窗口，哈希去重。
- 场景沿用平台默认模板和现有模型；人工结果不被后台识别覆盖。不向上游回写设备标签。
- 所有写操作校验管理员、主租户和目的地归属；不回传平台密码，不使用正式数据库做本地测试。

## 实施与验证

1. 平台/设备 API：management.py、management_schema.py、032 迁移，以及 db_utils.py 最小修改。先失败测试，再验证增删改、凭据隐藏、连接错误、同 ID 跨平台和同步保护。
2. 设备抓图：device_capture.py，通过复用既有分页与 Runtime 入库；验证项目/图片集范围、调度保存暂停、取消、失败游标和不重入。
3. 设备场景：device_scenes.py，复用 image_scenes 模型调用；验证场景名单、异常、人工优先和迟到结果隔离。
4. 页面：平台管理、设备抓图、项目入口；全量拦截 API 的隔离浏览器验证，加 npm run build。
5. 集成：hooks.py 注册与生命周期、bridge.py 传递角色；定向 SmartEye/场景回归。通过后核对115差异和活动任务，经 ssh-manager 部署与迁移，检查服务/相关接口。若活动任务阻止重启，保留可验收产物并明确待部署原因。

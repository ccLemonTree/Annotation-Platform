# 验证任务删除

验证任务列表为管理员增加“删除任务”按钮和确认弹窗。删除成功后关闭该任务的报告、刷新列表；删除末页最后一条时返回上一页。失败保留任务和确认框并显示原因；确认前取消不会发送删除请求。非管理员只有读取权限。

`DELETE /api/validation/runs/{run_id}` 复用租户范围和预览隔离检查。先复用 cancel_run 取消待处理项并确认权重验证远端停止；停止失败时返回 409，保留任务及 GPU 占用记录。重新锁定并刷新状态，防止取消后被另一个请求重试的任务被误删。最后删除 ValidationRun，由数据库 ON DELETE CASCADE 删除 ValidationItem。迟到的 worker 结果因任务不存在而被丢弃。

删除范围为验证任务记录、逐图结果和报告；验证集、项目原图、标注和训练权重保留。远端已退出容器及历史结果目录沿用现有保留策略，取消时仍按已有规则清理临时输入、本地结果缓存。本次不增加服务器历史目录的递归删除。

验证：先观察旧代码 7 项因 DELETE 405 失败。实现后删除专项 7 项通过，覆盖完成/失败/取消任务、联动结果删除、验证集/原图/标注/其他任务保留、登录与管理员权限、租户及预览隔离、远端停止成功/失败、迟到结果不复活。相关验证、模型预览、目标容差回归共 70 项通过；前端生产构建通过。

浏览器夹具 4 项通过：运行中任务提示、取消确认不删除、停止失败保留、成功关闭报告并刷新/回退页码、只读账号无删除按钮。截图 `output/playwright/validation-delete-confirm.png`，脚本 `scripts/verify_validation_delete.cjs`；真实用户任务删除数 0。

后台更新前确认上传、验证、训练、预标注、图片语义、项目处理无活跃任务或验证资源占用。更新后用新建的 completed 临时任务及单条结果执行真实 API DELETE，返回 204；再读为 404，数据库逐图记录同步消失。比较所有原有任务 ID、验证集、Asset、Annotation、LibraryImage 计数，完全一致。临时任务不进入 worker 队列，没有启动模型推理。报告 `output/validation-delete-live-result.json`，脚本 `output/verify-validation-delete-live.py`。健康检查通过，未删除任何现有用户验证任务。

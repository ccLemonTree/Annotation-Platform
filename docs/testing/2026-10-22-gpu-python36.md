# GPU采集兼容Python 3.6

截图服务器：绍兴移动算法2，36.212.5.102:3227；实测主机Python 3.6.8，NVIDIA Tesla T4两张，驱动580.105.08。

原因：`scripts/gpu_mcp_bridge.mjs`发送的远程脚本使用Python 3.7才支持的`subprocess.run(capture_output=True,text=True)`。原脚本在目标主机复现`TypeError: __init__() got an unexpected keyword argument 'capture_output'`；nvidia-smi本身正常。

仅将远程两处调用改为`stdout=subprocess.PIPE,stderr=subprocess.PIPE,universal_newlines=True`，保留10秒超时、返回码、进程采集失败语义及固定只读查询。不更改本地后端的Python运行要求或服务器Python。

- 新增`tests/test_gpu_python36.py`：直接提取并执行实际发送的脚本，严格模拟Python 3.6调用签名；覆盖采集成功、GPU查询失败、进程列表未知。修改前因capture_output失败，修改后通过。
- GPU采集、动态连接、权限/隔离与真实本地MCP/SSH密码测试：90 passed，日志`output/gpu36-tests.log`。
- 实际平台Node→ssh-manager→绍兴移动算法2→Python 3.6.8→nvidia-smi→平台解析：两张T4，进程采集完整，7条进程，无警告；日志`output/gpu36-live.log`。
- Node脚本语法检查通过。桥接脚本每次采集从磁盘加载，本次无需重启后端；未改服务器环境、未停止容器、未创建GPU服务器记录。实际目标的新增连接表单保存未代替用户执行；密码stdin路径由隔离MCP/SSH测试覆盖。

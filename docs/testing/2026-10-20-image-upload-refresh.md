# 图片集数量及上传状态刷新

根因：图库的图片集列表仅在页面初始化或显式 reload 时读取，翻页、筛选仅更新图片表格，保留了导入中途的计数。上传窗口的历史记录仅在打开或手动刷新时读取，上传队列已经进入后台入库，但历史行仍可能显示旧的 waiting/uploading 状态和 77% 上传进度。

变更：

- 图库翻页、切换筛选或每页数量时，同时读取图片集计数；关闭上传窗口也刷新图库。图片集总数不使用当前筛选后的 total 替代。
- 上传窗口打开时，按两秒间隔串行刷新历史记录；状态、接收字节及入库统计均来自服务端。关闭窗口停止轮询，继续保留现有后台上传队列。使用请求序号忽略旧响应，关闭后失效未完成的历史读取。
- 状态 processing 显示“正在处理”，pending 显示“等待处理”。不修改后台任务、图片或项目数据。

验证：`scripts/verify_collection_upload_refresh.cjs` 四项通过：模拟 844 → 2267 的陈旧计数；文件名筛选总数降至 2 时，图片集仍为 2267；窗口内状态从等待续传自动更新为正在处理、100% 接收和最新入库数；完成自动更新，关闭后停止轮询。全部 API 写入禁止。

既有关闭/重开、隐藏窗口继续队列、完成文件不重复提交等 5 项生命周期回归通过。前端 TypeScript + Vite 构建通过。

上传图片集默认值、关闭后记忆、当前选择优先、无图片集时显式命名等 5 项既有回归通过，合计 14 项浏览器检查，上传业务写入均被 mock 拦截。测试在撤销路由前离开页面，确保新增历史轮询先停止。Lint 无错误，保留 effect 状态设置和请求计数器清理的提示。

真实只读核对：后续的“验证数据_yolo.zip”也已完成（1678 张），原“0806验证_yolo.zip”新增 2267 张；图片集计数接口与未加筛选的图片列表总数均为 3945。前端采用开发服务热更新；没有重启或中断入库任务。

验证项目选择：当前两个检测项目与下拉列表一致。用户确认新建的是图片集而非项目；本次不改验证项目的筛选规则，也不代为创建项目或关联标注。

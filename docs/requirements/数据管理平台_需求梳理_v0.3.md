# 数据管理与模型生产线：需求细化 v0.3

日期：2026-09-30  
用途：需求讨论、范围确认和后续验收准备。

本版新增：尽量减少人工标注与人工审核，支持多轮大模型研判、rerank和多模态Embedding辅助核验；相应调整审核通过和进入训练集的条件。v0.2保留为此前需求快照。

本次补充：用户于2026-09-30确认将八项建议纳入需求，包括标注范围与完整性、人工基准样本与盲审、模型及审核策略更新的回归验证、训练前数据就绪检查、人工修正反馈与主动选样、结果复用与局部重算、切图上下文充分性、取消/重试/迟到结果处理。具体阈值、抽检量与执行规则仍待定。

本文依据本次对话整理。用户明确的功能与流程推演补充项分别标记；验收描述是便于讨论的草案，不表示指标已经定稿。案例数字仅用于纸面模拟，未实际执行训练、数据导入或生产发布。本文不选择数据库、前后端技术或调度组件的实现方案。

## 2026-10-14 用户确认补充

最新决定优先于下面的早期讨论：第一版单租户，SmartEye内置于主平台，无需独立启动；图片库与标注项目通过引用关联，图片集支持日期/平台名。

上传和SmartEye拉取的最终图片按`max(宽,高)>=阈值`入库，任一边达到720即可，720×720通过；每个图片集独立配置分辨率、分类开关、模型与场景，平台默认仅作新集模板；阈值支持本次覆盖，0关闭过滤。合格图片入库后调用vLLM OpenAI格式的Qwen3.8-27B做多标签场景分类，地址为`http://10.11.12.123:31030/v1`；模型地址、名称、场景名单均可自定义。初始场景为山上、河边、工厂、电梯、高位摄像头和低位摄像头。场景与命名图片集、检测框类别独立；分类失败或超时仍保留入库，标记失败并支持重试。同集按内容去重只留一张；场景结果跟随原图，同图跨集共享已有分类，不自动按新集重复推理；手动重分类按选中集规则，结果更新所有所属集。历史图按需分类，不自动全量调用。实施/验收见[操作说明](../development/图片场景与入库规则.md)。

## 2. 从用户工作出发的完整流程

选择租户和项目 → 导入图片 → 设备/场景分类与质量评分 → 筛选并组成候选数据集 → 选择独立标注任务并明确标注范围 → 模型预标注 → 自动核验与按需多轮修正 → 达标自动通过，疑难/冲突/抽检样本人工处理 → 检查任务范围内标注完整性 → 固定审核通过的数据集版本 → 选择标签和导出模板 → 训练前数据就绪检查与目标端验收 → 交付训练服务器并发起训练 → 查看日志、指标和产物 → 独立测试、版本比较及旧类别/设备/场景回归验证 → 下发模型或回退。

人工修正记录用于推荐下一批待处理样本；符合任务、模型和审核策略版本等复用条件的结果可复用，仅重算受影响部分。审核策略更新先在固定基准样本上比较，再决定是否扩大应用。任务取消、重试和迟到结果均受任务状态及版本约束。

向量分支在测试阶段增加“批量生成向量和检索评测”；DINOv3分支增加“无标注训练/蒸馏、少样本下游微调”的明确方法选择。它们的任务、数据和模型版本均独立记录。

## 3. 细化需求表

“沿用”与“新增”表示用户已提出功能；“本次确认补充”表示用户本轮要求纳入的八项建议；其他“推演补充”仍待确认。所有验收口径中的阈值、时间和支持名单都需后续定稿。第6.2节的优先级是讨论建议，不代表已确定开发排期。

### 3.2 标注、语义预标注与自动研判

| 编号 | 需求 | 来源 | 验收口径草案 |
|---|---|---|---|
| A01 | YOLO类框与类别标注；大模型和向量任务分别进行图片描述。 | 沿用 | 三条任务独立维护标注、规则、状态和版本；共享原图不自动共享标注。 |
| A02 | 支持整图描述、检测后切图描述。 | 沿用 | 切图关联原图、框、检测结果版本与切图规则；框修改后旧切图可识别为旧版本。描述与实际使用的图一致。 |
| A03 | 语义理解预标注：输入“框出穿红色衣服的人”等自然语言要求，产生可编辑目标框。 | 新增 | 能处理多个匹配、无匹配、含糊指令和失败；结果回到原图坐标，不能把一段文字回答直接视为检测标注。 |
| A04 | 语义定位结果分别用于小模型标注、目标切图、向量任务的目标区域与描述。 | 新增 | 保留指令、模型版本、类别和属性解释；“人+红色衣服属性”与“红衣人类别”由任务标签规则决定。 |

| A06 | 标注数据采用统一表达，保存框、类别、属性、图片描述、来源和状态。 | 新增 | 坐标约定明确；检测框、图片描述等保留各自类型，不强行转成同一种标注。各导出格式由模板转换。 |
| A07 | 管理标签表和标注规则版本，支持任务自定义类别与属性。 | 推演补充 | 同名标签可区分语义；类别重命名、合并、拆分后历史版本仍可追溯。 |
| A08 | 区分待生成、待自动核验、自动通过、待人工处理、人工通过、退回、无目标和无效样本。 | 推演补充；自动通过为本次新增 | 自动通过和人工通过均保留来源，可按任务规则组成训练集；原始模型草稿不因生成完成就视为审核通过。空输出、超时、无匹配需区分，自动确认无目标也需符合核验规则。 |
| A09 | 自动复核与疑难人工复核、退回、修改记录；两人同时修改可发现冲突。 | 新增+推演补充；减少人工审核为本次新增 | 记录核验的标注版本、方法与结果；改动已通过结果时重新核验。不是每条结果都需人工逐条审批。人工复核是否必须第二人完成待定。 |
| A10 | 人工主要处理疑难、分歧和抽检样本，支持快捷键、批量处理、自动保存与撤销。 | 推演补充；人工减量为本次新增 | 展示候选差异、核验结论、简要理由与相关图片；相同问题可批量修正。人工不必重复查看全部自动通过结果。 |
| A11 | 独立任务间可选择复用已审核描述或框。 | 推演补充 | 引用/复制来源及版本可见，目标任务可独立修订；一方修改不悄悄改变另一方已冻结的数据集。 |
| A12 | 多轮大模型研判与修正：生成、核验、提出修正、再次验证。 | 本次新增；停止细则为补充 | 支持按任务组合不同模型、提示词或图像视图；问题解决即停止，持续分歧或到达轮数上限转人工/待定。保存每轮结果和差异，不要求公开模型内部思维链。 |
| A13 | 多模态Embedding辅助研判。 | 本次新增 | 可比较原图/切图与目标描述、标签或已核验参考样例，支持异常发现、候选筛选和一致性评分。相似度不单独证明属性事实、框位置或标注完整性。 |
| A14 | rerank辅助研判。 | 本次新增 | 对图片/目标区域与候选标签或描述的相关性评分、排序，可辅助选择或复核。记录评分输入和模型版本；只有候选排序不能作为已发现全部目标的依据。 |
| A15 | 自动审核通过、自动修正再核验、拒绝/无效、转人工的分流规则。 | 本次新增；准入细则为补充 | 设备场景、类别、框、描述等按各自规则判断。明确通过依据与异常处理；未校准的模型自报置信度、重复投票或相关性高分不能单独等同于正确率。 |
| A16 | 对争议样本人工介入，对自动通过样本开展少量抽检。 | 人工减量明确；抽检策略为补充 | 新场景、罕见类别、无目标判断、模型冲突等可优先处理。发现错误后可定位同类数据，调整规则并重新核验，抽检比例与触发条件待定。 |
| A17 | 按需增加核验轮数，并限定轮数、耗时和算力成本。 | 推演补充 | 简单达标样本可提前结束，疑难样本才升级研判；到达预算上限有明确结果。失败调用不视为通过，重复运行不无限循环。 |
| A18 | 核验依据留存、任务级校准与质量验证。 | 推演补充 | 记录模型/规则版本、图像输入、候选、评分、结论、简要理由、调用成本和人工修改。使用小规模已人工核验样本校准规则，再用独立样本评价自动通过错误率；多次调用同一模型不当作独立证据。 |
| A19 | 明确任务标注范围，并检查整张图片在该范围内是否标注完整。 | 本次确认补充 | 保存任务目标、类别/属性定义及图片完整性状态；区分单个框审核通过与图片在任务范围内全部目标已标完。只框出红衣人的结果不能直接作为完整的普通person训练标注；转换到另一任务需重新检查范围及漏标。完整性未知的数据不能按完整标注进入该检测训练集。 |
| A20 | 人工基准样本与部分盲审。 | 本次确认补充 | 建立小规模人工独立确认的基准样本；用于调整规则与独立验证的样本分开。部分基准/抽检样本先隐藏模型标注、结论和分数，提交人工判断后再比较；保存差异、纠正结果与基准版本。基准规模、盲审比例及更新规则待定，不要求全部人工处理采用盲审。 |
| A21 | 结果复用与局部重算。 | 本次确认补充 | 图片内容/版本、任务定义、模型、提示词、预处理及审核策略等相关条件一致时，可复用生成和核验结果，并保留来源；改变标签、框、描述或审核策略时，明确受影响部分并重新核验。图片级完整性等整体结论可能随局部变动失效，不能继续沿用。跨任务复用需校验适用性，跨租户遵循共享规则；不覆盖人工修改或冻结版本。 |
| A22 | 判断切图是否保留任务所需上下文。 | 本次确认补充 | 按任务使用目标紧框、扩大裁剪范围或原图与切图联合输入，并记录实际图像范围和裁剪规则。衣服颜色与翻越围栏等任务分别判断上下文需求；不足以确认属性、动作或关系时标记无法判断、补充图像或转人工，不生成确定性结论。 |

| E06 | 对数据删除、标签变更、模板改版的影响可追溯。 | 推演补充 | 可查受影响任务和数据集；不静默改变正在训练或历史模型对应的数据。物理删除和保留规则待定。 |
| E07 | 训练前数据就绪检查。 | 本次确认补充 | 对指定数据集版本和训练方法检查图片可读取、标注审核状态、任务范围完整性、类别映射、导出格式兼容性、各划分有效样本量及数据泄漏；展示可训练/不可训练、问题清单及修改后的复查结果。阻断项与提示项待定；无标注自监督/蒸馏按实际输入要求检查，不强制人工标签。检查通过的数据版本或训练方法改变后重新检查；交付后保留目标端验收结果。 |

部分标签导出至少要明确以下策略：排除非选中框但保留图片、排除包含非选中类别的图片，或将非选中区域标为忽略（仅目标训练格式支持时）。哪种策略正确取决于任务定义，不应统一默认为背景。图片描述的标签筛选是筛选记录或对应区域，不能随意删掉描述中的词后宣称标注仍正确。

## 4. 八个用户场景的纸面模拟

### 场景一：从设备图片中挑出优质但有代表性的首批数据

假设某租户导入1万张设备图片，希望先训练一个检测算法。

1. 选择来源、设备和时间范围，导入完成后查看成功、坏图与重复组。
2. 自动设备场景分类、图片质量评分，并开展自动核验；人工检查争议与抽检样例，调整明显错误。
3. 用户按场景、时间、质量筛选，同时保留夜间、遮挡及小目标样本。
4. 查看场景和设备分布，冻结首批候选图片名单，然后进入预标注。

模拟发现：同一设备可能换场景；高质量样本不必然覆盖真实难例；选择日期字段会改变筛选结果。补充D02—D08，不能仅靠总质量分决定训练价值。

### 场景二：“框出穿红色衣服的人”，同时用于小模型和向量任务

1. 新建语义预标注任务，指定目标指令、标签定义和模型。
2. 先对少量图试跑，检查多个人、红色物体但非衣服、背面/遮挡及无匹配图片。
3. 对目标框、类别/属性和漏标开展自动核验；达标自动通过，分歧结果由人工修正并再次核验。
4. 检测任务把审核通过的框用于训练；向量任务可选择引用该版本、切图并独立生成、核验描述。
5. 修改原框后提示旧切图来源已变化，重新生成产生新版本。

模拟发现：“红衣人”可以是专用类别，也可以是“人”的属性；没有返回框不代表真负样本；描述原图与描述切图范围不同；原图清晰但切图过小也可能无法用于描述。补充D04、A03—A09、A11，保留生产线独立。

### 场景三：用百张内标注尽快验证新算法

假设已有DINOv3预训练权重、80张审核通过的训练图片，以及独立的验证/测试样例；自动与人工通过来源分别保留，百张是否包含验证集待定。

1. 指定下游任务、基础权重和小样本数据集；检查类别缺失和数据重复。
2. 选择快速微调任务并记录参数与算力预算；平台发起训练并观察曲线。
3. 在独立测试样例上比较基础模型与微调模型，查看漏检、误检和失败场景。
4. 用候选模型给下一批数据预标注，经自动核验、疑难处理和必要抽检后增加数据形成下一轮实验，避免仅靠同一模型自我认可形成错误循环。
5. 若另有未标注图片，可另建自监督/蒸馏任务，记录实际采用方法，不与少样本微调混为同一次任务。

模拟发现：80张相邻帧可能只有几个独立场景；训练集上效果好不等于泛化；未标注领域适应与百张标注下游训练是不同目标。补充E04、T05—T07。不保证百张必然得到可上线模型。

### 场景四：只导出“人”和“车辆”，适配另一训练格式

1. 从审核通过的标注中选定两类标签及数据集版本，并保留自动/人工通过来源。
2. 查看筛选后的图片、目标数，查看被过滤为空的图片和真负样本数量。
3. 选择模板，检查字段、坐标、类别编号以及图片路径预览。
4. 明确非选中标签的处理策略，校验训练/验证/测试划分的一致性。
5. 导出并直接交付训练服务器，保存模板版本、标签映射和目标端结果。

模拟发现：过滤标签可能使图片变成空标注；训练格式的忽略区能力不同；同一描述中多个目标不适合机械删词。补充E01—E06。

### 场景五：两个租户同时使用外接算力，其中一人开启SSH调试

1. 两个租户各自选择任务数据和算力；平台显示专属或共享资源，以及排队原因。
2. 租户A跑预标注并准备训练，租户B运行另一任务；模型加载和任务占用分别记录。
3. A开启其目标的SSH窗口，断开浏览器后训练继续。
4. A任务结束，先保存模型、日志和指标；只清理A对应的进程和资源。
5. 若B仍调用共享模型，模型继续保留；若网络失联，释放状态保持未知/待确认。
6. 调试需要延长保留时，按明确规则记录；任务结果不会因释放临时算力而丢失。

模拟发现：关闭窗口、停止任务、卸载模型和释放机器不能互相等同；共享服务器SSH可能绕过数据隔离。补充C02—C07、M01—M03、O01。

### 场景六：比较候选模型，发布模型并回退

1. 将候选与旧模型放在同一固定测试集上对比。
2. 向量模型分别测试文字、图片查询，区分外观与语义样例；描述模型和检测模型使用各自验证要求。
3. 保存指标、样例、报告和模型版本；用户选定模型及发布目标。
4. 交付模型及必要配套信息，记录目标回执能确认到哪一步。
5. 回退时选择该目标上一次已知版本，保留操作结果。
6. 测试向量独立保留/清理；生产发布物仅模型及其必要配套文件。

模拟发现：下发完成不表示线上效果已验证；只有权重没有标签表可能无法恢复旧行为；新旧模型不能在不同测试条件下简单比较。补充T04、V03—V05、P01—P03。

### 场景七：一万张图片尽量自动标注和自动审核

1. 在小规模已人工核验样本上试跑预标注、核验和候选排序，检查“红衣人”、遮挡、相似背景、空输出等案例，校准各任务的通过规则。
2. 为整批图片生成候选框/描述；先检查格式、坐标、标签定义和图像范围是否匹配。
3. 达标样本自动通过；不确定样本按需使用多轮大模型、图文Embedding或rerank。核验模型看到实际图片/切图和任务要求，不能只检查文字表述是否流畅。
4. 对框标注还要检查漏标，对描述检查属性、动作和关系；候选都相似或同一模型多次回答一致时，不据此认定没有错误。
5. 出现明确问题时自动修正并重新核验；持续分歧、无证据或达到轮数/成本上限的样本转人工或保持待定。
6. 人工集中处理异常队列，并少量抽检自动通过样本。抽检错误可触发同类样本重新核验，修改产生新版本。
7. 冻结审核通过的数据集；报告同时显示自动通过率、人工处理量、抽检错误、平均轮数和成本。

模拟发现：错误可能在多轮中被重复认可；相关性分不能替代属性事实或框完整性核验；自动化率很高也可能牺牲数据质量。因此新增A12—A18和H04。目标是降低人工介入与单位合格数据成本，不把所有图片无条件送入完整模型链。

### 场景八：同一张图复用到不同任务，并更新审核策略后再训练

假设一张图有红衣人和蓝衣人，要分别用于红衣人检测、普通人检测，以及红衣人的图片描述/向量任务。

1. 红衣人检测任务明确只标符合定义的红衣人；普通人检测任务要求标出所有人。红衣人框已经通过审核，也不能据此认定普通人任务已完整。
2. 红衣人切图用于衣服颜色描述时检查局部清晰度；若描述涉及人与围栏的动作或关系，补充扩大裁剪范围或原图。上下文不足的结论保持无法判断。
3. 人工只改动其中一个框或描述后，重算受影响的切图与核验结果；图片级完整性重新判断。其他满足复用条件的结果保留，已冻结的数据集不改变。
4. 更换审核提示词或rerank版本时，在固定基准样本上比较新旧策略；部分样本由人工先盲审再对比。调整规则的样本与独立验证样本分开，发现退步后按待定的阻断/提示规则处理。
5. 记录人工修正原因，按本轮人工预算推荐缺失类别、新场景和有分歧且有代表性的下一批样本。基准与独立测试样本不自动转入训练。
6. 冻结数据集、检查就绪条件，并交付训练服务器。完整性未知、类别映射错误或格式不兼容等问题按训练方法处理，不能仅凭单框通过就发起检测训练。
7. 若运行中取消任务，迟到的标注或核验结果不写回有效版本；提交重试先核对远端状态，避免同一次提交创建多个训练任务。
8. 候选模型在固定测试集上分别检查旧类别、旧设备、旧场景和新增数据范围，保存改善与退步情况，再决定下发或继续修正。

模拟发现：共享原图和复用单个结果不能代替任务完整性判断；切图可能丢失关系信息；修改审核策略及局部标注有各自影响范围；重试不等于新建实验。补充D09、A19—A22、E07、T11、V06。验收指标与人工投入数量仍待定。

## 5. 参考项目调研结论

调研日期：2026-09-30。以下为公开文档核查，不是安装或实际运行验证。

### X-AnyLabeling

官方仓库展示了AI辅助标注、批量预测、本地/远程推理、图像描述、Grounding及多格式导入导出能力，适合参考预标注交互和人工修正流程。它的主体是桌面标注应用，不能据此认为已经覆盖本平台的多租户、训练管理、统计和模型发布需求。[官方仓库](https://github.com/CVHub520/X-AnyLabeling)

Rex-Omni示例记录了文本提示检测、描述定位和可批处理任务；同时视觉示例提示有批处理限制。因此，本平台应对每个预标注模型声明“支持哪些输入、输出和批任务”，不默认所有模型具备相同能力。[Rex-Omni示例](https://github.com/CVHub520/X-AnyLabeling/blob/main/examples/vision_language/rexomni/README.md)

用户指南包含多种格式转换及部分标签筛选的例子。能借鉴字段和标签映射，但自定义模板、负样本策略和导出数据版本仍是本平台独立需求。[导入导出指南](https://github.com/CVHub520/X-AnyLabeling/blob/main/docs/en/user_guide.md)

其远程服务和自定义模型文档还可参考模型接入、预测结果表达和卸载能力声明。[远程服务](https://github.com/CVHub520/X-AnyLabeling-Server)、[自定义模型指南](https://github.com/CVHub520/X-AnyLabeling/blob/main/docs/en/custom_model.md)

### LightlyTrain与DINOv3

当前官方支持矩阵列出了DINOv3的下游微调和蒸馏；原生自监督预训练与蒸馏不能仅因都使用未标注数据而混称。依据当前文档，不能直接把LightlyTrain对DINOv3的支持当作原生DINOv3自监督训练已经满足。[LightlyTrain支持矩阵](https://docs.lightly.ai/train/stable/)、[蒸馏文档](https://docs.lightly.ai/train/stable/pretrain_distill/methods/distillation.html)

DINOv3相关目标检测和图像分类微调有官方文档；它们能作为快速迭代能力参考。文档支持训练功能，不等于对用户特定算法保证100张样本的质量、耗时或上线效果。[目标检测](https://docs.lightly.ai/train/stable/object_detection.html)、[图像分类](https://docs.lightly.ai/train/stable/image_classification.html)

Meta官方DINOv3仓库提供原生训练示例，并把文本对齐作为独立训练部分。需求应保留“原生自监督训练”入口的独立接入评估，且向量任务需要分别验证文字和视觉查询能力。[DINOv3官方训练与文本对齐](https://github.com/facebookresearch/dinov3#training)

参考工具和模型权重的使用条件需要纳入接入评估：X-AnyLabeling仓库声明GPL-3.0，LightlyTrain提供AGPL-3.0及其他许可方案。本文没有作出具体集成方式或授权判断。[X-AnyLabeling许可声明](https://github.com/CVHub520/X-AnyLabeling#license)、[LightlyTrain许可声明](https://github.com/lightly-ai/lightly-train#license)

### 自动研判补充调研

Qwen官方多模态reranker说明其输出为查询与文档（可含图片）的相关性分，Embedding用于跨模态表征与检索。把它们用于辅助核验是本平台的需求应用，不能从官方检索能力直接推导出标注事实和框精度已经得到验证。[多模态Reranker](https://huggingface.co/Qwen/Qwen3-VL-Reranker-2B)、[多模态Embedding](https://huggingface.co/Qwen/Qwen3-VL-Embedding-2B)

Google的自一致性研究展示了多条候选推理路径的选择效果，研究中的测试是算术和常识推理，不能直接当成本平台图像标注质量提升的证据。因此多轮研判的轮数、通过条件和收益需要在具体数据上测量。[Self-Consistency研究](https://research.google/pubs/self-consistency-improves-chain-of-thought-reasoning-in-language-models/)

HumanSignal文档提供一致性、模型预测与已核验标注比较等质量评估流程，可参考争议样本筛选和抽检指标。这是质量管理参考，不代表选择其产品实现本需求。[一致性与质量评估](https://docs.humansignal.com/tutorials/how_to_measure_inter_annotator_agreement_and_build_human_consensus)

### 本次补充需求的参考依据

检测标注需要覆盖任务范围内的全部目标，局部指令生成的框不能自动视为完整检测标注。[Ultralytics标注建议](https://docs.ultralytics.com/yolov5/tutorials/tips-for-best-training-results/)

主动学习可作为有限人工投入下的样本选择参考；实际收益需要在本平台的数据与任务上比较。[Google Research主动学习研究](https://research.google/pubs/aspest-bridging-the-gap-between-active-learning-and-selective-prediction/)

部分盲审可参考先隐藏预标注、再揭示并比较的交互设置；本平台仅要求对部分基准和抽检样本支持该流程。[HumanSignal预标注显示设置](https://docs.humansignal.com/guide/project_settings_lse)

以上沿用本次需求讨论中的参考资料，不代表已集成相关工具或完成运行验证。

## 8. 本版整理决定

1. 按最新指令纳入多租户；此前“完全不需要权限管理”不再用于否定租户身份和隔离。复杂角色仍未列为明确需求。
2. 保留三条生产线独立、数据总量基线、向量仅测试和发布边界到下发/回退。
3. 此前十一项新增需求与本次确认的八项补充均有编号映射；其他纸面模拟细节仍标为“推演补充”，没有当成用户已确认指标。
4. DINOv3原生自监督、教师蒸馏、少样本微调分别描述；百张能力不承诺准确率。
5. 参考项目用于能力与行为调研，当前没有决定直接集成、开发平台或实际运行训练。
6. 最新要求将原先逐条人工确认的路径调整为自动核验优先。自动通过或人工通过均可按任务规则进入训练集；保留疑难处理、抽检和修改版本。具体阈值与预算待验证。
7. 本次按用户指令将八项补充并入原需求文档，增加八条需求、一个纸面场景和七个待定决策点；高/中优先级为建议，数值指标、执行规则和开发排期未确认。

# 文件夹、压缩包与断点续传

打开“图片管理 → 上传图片”，填写目标图片集，选择图片、文件夹或ZIP/TAR，再点击“开始 / 继续上传”。支持ZIP、TAR、tar.gz和tgz及其中的子目录；所有图片加入所选图片集，不自动按目录新建图片集。不支持RAR/7z、加密包和归档链接。

上传目标默认依次选择：当前筛选的图片集 → 上次使用且仍存在的图片集 → 已有第一集。刷新也会记住上次使用；工具栏和空列表的上传入口一致。不再自动填当天日期；没有已有集时留空，须主动新建或明确输入名称。

## YOLO已标注图片导入（2026-10-17）

在上传窗口勾选“同时导入YOLO标注（ZIP）”，仅选择目标图片集，**不绑定项目**。ZIP支持 `images/train/a.jpg` + `labels/train/a.txt`、`train/images/a.jpg` + `train/labels/a.txt`，也支持同目录图片/TXT；提供 `data.yaml/data.yml` 的 `names`（列表或从0连续编号的字典）或 `classes.txt`（每行一个类别）。包内多份类别表必须一致。

每行仅支持 `class x_center y_center width height`，坐标为归一化检测框；当前不支持分割、多边形、姿态或带置信度的预测TXT。负样本必须带空TXT，缺失TXT、类别越界、非有限/越界坐标、重复路径、符号链接或歧义配对均拒绝。先检查包内全部标注，再逐图入库；包损坏或后续处理失败时，之前已提交图片保留，重试不覆盖原标注。

图片进入所选图片集，图库保存可复用的导入标注来源，列表显示“YOLO·已信任/待审核”。图片管理“添加到标注项目”或项目“从图片库添加”时，可勾选“带入已有YOLO标注”；默认只添加图片，勾选后复制成各项目独立的标注版本。一个项目内的修改不影响图库来源和其他项目。

目标检测项目无类别且尚无标注时采用导入类别；已有类别须包含导入类别名，按名称匹配，不依赖类别编号顺序。已有同图标注保持原样，相同计跳过、不同计冲突；图库来源也不覆盖不同的重复导入。相同来源重新导入时，管理员可明确升级为信任，不改变已有项目副本。统计含新标注/相同跳过/冲突数及前20条说明。原图片集分辨率规则仍适用，需要全部接收时将本次阈值设为0。

默认带入项目后的标注待审核。**管理员可在导入时主动勾选“信任已有标注，直接用于训练/验证”**，图库来源保留确认人和时间，带入任意检测项目后直接可用，记录 `import_yolo` 来源及确认依据，无需逐图审核；已有项目标注状态保持不变。普通用户不可选择该信任选项。训练使用项目冻结导出集，验证使用当前项目或冻结val/test；信任标注不代表已证明训练/验证数据独立。

该模式复用分片上传和断点游标；续传保持相同ZIP、图片集、阈值和信任选项。已完成的YOLO包再次选择会逐图核对图库标注，不直接复用旧统计。020为上传记录增加可空格式/默认false信任字段，为图片增加可空导入标注JSON；已有行新增值为空/false，不改已有标注。

沿用目标图片集的分辨率及场景规则，可覆盖本次长边门槛：任一边大于等于门槛即可，0关闭。同内容在图片集中只保留一张，跨集共享原图和场景，已有成功分类不重复调用模型。图片入库后后台分类，失败保留并可重试。上传不要求标注项目，后续从图片库选图添加到项目。

## 中断后继续

- 分片连接中断、超时或临时502/503/504时，自动等待1秒、2秒各重试一次，只重传失败分片；成功后继续队列。重试耗尽时保留进度并提示“开始 / 继续上传”，不会清除已收分片。“暂停上传”也会立即取消等待中的重试；认证及校验错误不会自动重试。
- 只选文件、未点击“开始 / 继续上传”时不会自动上传。点击开始后，**关闭上传弹窗会继续处理当前队列**；重开保留目标图片集、门槛、进度和完成统计。仅修改目标图片集或门槛时，才重新校验所选文件。
- 刷新页面、关闭浏览器标签或离开图片管理页会停止尚未传完的本地队列；重新进入后重选原文件/文件夹续传。已完整收到并排队的文件继续在服务端入库。
- “暂停上传”停止浏览器传输/查询，完整分片保留；继续时只发送缺失分片。
- 刷新、关闭浏览器或断网后，重新选择**相同文件/文件夹、目标图片集和分辨率门槛**，再继续。服务器用文件名、大小和分片SHA-256识别内容；压缩包重新打包后内容变化会建立新记录。
- 重选大文件仍需逐片读取校验，浏览器只持有当前分片，不一次读取整个压缩包。
- 文件完整收到并排队后，关闭窗口不影响后台入库。后端重启恢复导入游标，每张图单独提交，已提交图片不重复新增。
- “最近上传与续传记录”显示自己的最近20条，可刷新或清除非处理中记录。清除记录不删除已入库图片，未完成文件则需重传。已完成会话复用其统计；原图被删除/移出目标集后重选会重新导入。

无效/超限单图和低分辨率图片分别计数，非图片文件忽略；不安全归档在任何图片入库前拒绝。包后半段损坏时，前面已提交的合格图片保留，修复后重传依靠内容去重。

## 限制与运行配置

浏览器需要支持文件夹选择和Web Crypto，通过**localhost或HTTPS**使用。普通远程HTTP不提供Web Crypto，界面会提示改用HTTPS/localhost。

| 配置 | 默认值 | 说明 |
|---|---:|---|
| 分片大小 | 8 MiB | 固定协议；前后端均校验SHA-256 |
| `MAX_UPLOAD_SIZE` | 10 MiB | 每张图片上限，包含包内图片；当前运行环境为100 MiB，保留已有配置 |
| `MAX_ARCHIVE_UPLOAD_SIZE` | 10 GiB | 单个压缩包上限 |
| `MAX_ARCHIVE_EXPANDED_SIZE` | 20 GiB | 单包声明的展开总量 |
| `MAX_ARCHIVE_FILES` | 50000 | 单包条目数，含图片、标注、目录及其他文件；YOLO图片/TXT分别计数 |
| `UPLOAD_RETENTION_DAYS` | 7天 | 上传中、失败、完成会话自最后活动起的保留期；启动及每小时清理，排队/处理中保留 |

限制在后端`.env`设置并重启，窗口从服务端读取；本轮未覆盖已有`.env`。图片分辨率/场景继续在“图片集设置”配置。

运行前升级Alembic到012。新增`image_uploads`存会话与游标、`image_upload_items`存短期入库引用，旧业务表不改。暂存为本地存储根目录`.incoming/<上传UUID>`，成功即清理；上传引用清理不删除原图。暂存不通过静态目录开放。

当前限单后端进程、本地存储。暂存需同时容纳分片、完整包和导入原图；10GiB上限是配置值，不代表已做10GiB压力测试。反向代理需允许至少8MiB请求体及单片传输时间。

## 接口

均要求主平台Bearer Token，仅当前用户/租户可操作自己的会话，其他用户返回404。

| 请求 | 行为 |
|---|---|
| GET `/api/image-uploads/config` | 分片大小、容量、条目及保留期限 |
| POST `/api/image-uploads` | JSON：filename、size、chunk_hashes（每片小写SHA-256）、collection_name、可选min_long_edge；YOLO增加annotation_format:"yolo"及可选trust_annotations（默认false，true仅管理员） |
| GET `/api/image-uploads` | 自己的最近20条 |
| GET `/api/image-uploads/{id}` | 状态、已收分片、游标与新增/重复/过滤/无效/忽略统计 |
| PUT `/api/image-uploads/{id}/parts/{index}` | 从0开始，原始二进制请求体，application/octet-stream |
| POST `/api/image-uploads/{id}/complete` | 缺片409；完整后排队，重复提交不重复入库 |
| DELETE `/api/image-uploads/{id}` | 清除记录与暂存；排队/入库中返回409 |

原`POST /api/images/batch-upload`仍兼容旧调用，仅图片；新窗口统一走分片接口。SmartEye拉取保持原流程。

图片列表响应增加 `has_imported_annotation`、`imported_annotation_trusted`，不在列表批量返回完整框。`POST /api/images/associate` 可增加 `include_imported_annotations:true`；响应另有annotated/annotation_skipped/conflicts/without_annotations，已有标注不覆盖。默认字段省略时仍只关联图片，兼容旧调用。

验收见[本轮证据](../testing/resumable-upload-verification-2026-10-15.json)。隔离库验证真实HTTP断开重连、012迁移、并发初始化；浏览器验证真实UI/Web Crypto，上传写入均拦截，业务库未写入合成样本。未验收10GiB实包、跨机器代理、多实例或EOS。

# 分类、描述、向量标注和模型裁剪

入口为 **标注与审核 → 选择项目 → 开始标注 / 继续标注**。项目管理页负责数据准备、处理队列和审核记录；向量检索与匹配判定在独立的向量标注工作台完成。项目管理新增「大模型描述标注」「向量匹配标注」，分类方式可选单选或多标签。描述和向量项目可不配置类别。

## 使用顺序

1. 在图片管理上传原图，添加到项目；同一原图可在多个项目复用，标注仍按项目独立。
2. 如需先切图：进入项目标注页的「标注准备」，选中原图，处理方式选「检测切图」。模型管理中所有已启用的 detection 模型均可选择，包括 YOLO、RF-DETR、SAM3；模型本身须支持相应目标。配置目标类别、置信度、每侧外扩百分比（默认20%）。
3. 查看后台处理队列。完成后点击「刷新图片列表」，选择来源为「裁剪图」的图片。原图不删除，每个框生成独立图片；裁剪图只保存在当前项目，不加入公共图片库。切图默认勾选「切图后仅标注裁剪图」，没有检测目标的原图不进入标注队列，也不写负样本。可通过「项目标注范围」切换为原图与裁剪图，原图始终保留。
4. 分类项目：打开图片，选择单个/多个类别，可补充描述，保存后审核。描述项目：选择描述模型、填写可选的本批提示词，生成后打开图片编辑和审核。留空沿用模型管理中的描述提示词。
5. 向量项目：点击「开始标注 / 继续标注」进入独立工作台（`/annotate/project/<project_id>`），默认「图片描述标注」，直接打开图片编辑描述，也可先在项目管理中调用大模型生成描述；**不要求生成向量或连接 Milvus**。只有选择「文搜图标注」或「以图搜图标注」时，才需要先在项目准备区选择 Embedding 模型建立索引，再检索当前项目中同模型版本的向量。每个结果可标为「正确」「错误」「无法判断」；检索结果的描述视图和分类视图只是展示方式，均共用图片描述/类别。
6. 历史查询自动保存，可继续判定。同一张图片对不同查询可有不同判断，例如对“黑衣”正确、对“白衣”错误。相似度不会自动变成标签。

所有图片标注均有版本、冲突检查和审核。模型描述待审核；生成期间的人工编辑或审核不会被迟到结果覆盖。无法判断/跳过不作为训练负样本。项目管理页的标注进度按当前标注范围统计；配对判定按各次查询保存。仅标注裁剪图时，队列、上一张/下一张、序号跳转、描述/建索引批处理、新验证集取数与导出均排除原图。项目图片页仍能保留并筛选全部图片、原图和裁剪图，排除的原图显示「切图来源」。

## 检索匹配标注审核与训练

向量项目的「标注与审核」页包含「检索匹配标注审核」区，展示已保存查询中的正确/错误关系、审核状态及通过/驳回操作。历史无审核字段的关系按待审处理，无需重新标注。每页最多 20 条查询，统计和审核筛选作用于本页查询；图片描述/分类仍在独立列表与统计中，避免把同一图片对不同查询的判定混为图片分类。接口按查询版本防止并发覆盖，修改正确/错误判定会清除原审核并回到待审。

选择已启用的 OpenAI 视觉对话模型，点击「大模型审核待审匹配」，默认处理当前项目全部待审关系，也可限制本页查询。模型独立看查询与候选图，不接收人工判定或相似度；图搜图以独立参考图和候选图输入。两者均判正确或均判错误均自动通过；分歧、模型不确定或请求失败标为「待人工复核」，显示理由、模型修订和完整 JSON 证据。可筛选待人工复核并通过/驳回。核心提示词在模型管理编辑，本批补充要求可在审核页填写。

复用项目后台队列，每个查询一个批次，支持取消/失败重试和服务中断恢复。按每条关系的人工判定/审核基线保护结果，同查询其他图片完成审核不会使本项失效；人工改标/审核、图片或参考图删除/变更、范围或模型配置变化会阻止旧结果覆盖。修改人工判定会清理旧 AI 证据并回到待审。

默认导出/冻结只包含已通过审核的匹配关系（AI一致通过或人工审核通过）。可明确包含未审核的人工判定；但 AI 分歧、不确定或失败的关系必须先人工复核，通过后才能导出，不能用包含待审核选项绕过。已驳回和无法判断不进入训练样本。来源包包含审核人、时间、状态和 AI 证据。Swift 匹配格式会拒绝同一 anchor 对同图的正负冲突，需统一历史判定；已冻结版本不可变，审核/改标后需重新冻结。

创建 Swift/WeMM 训练任务时可直接选择「平台标注数据（冻结版本）」，选择项目、配对来源并「冻结当前标注」，随后保存待启动任务。冻结复用图片包和 SHA256 校验，训练格式自动跟随任务类型/损失函数，不启动模型推理或训练。详见[模型训练](模型训练.md)。

## 删除裁剪图

标注准备区、图片描述列表、向量匹配结果和项目图片页均有「删除裁剪图」。确认后只移除当前项目的裁剪 Asset 及其标注；取消不发送删除请求，失败时弹窗保留错误并支持重试。删除会刷新列表、选中项、项目数量，移除当前/历史可见检索结果；原图、其他项目、已冻结导出和验证集保留。底层不可变图片文件沿用现有保留策略，不直接删除磁盘文件；已无Asset的向量记录不会进入检索候选。

准备区、图片描述列表、项目图片页支持勾选后「删除选中图片（N）」，表头复选框全选当前页，翻页保留已选项，确认弹窗说明包含其他分页的选择。检索结果支持逐张勾选及「全选本次结果」。一次请求调用既有 `/api/batch/assets/delete`，成功清空选择、回到首屏并刷新；失败保留选择及确认弹窗以重试，取消不请求。项目、图片来源、标注范围或当前查询切换会清理对应选择，避免误用旧选择。只处理显式勾选的项目图片；图片库原图、其他项目和底层文件保留。

此外提供独立的「删除全部图片」「删除全部裁剪图」入口，**无需勾选、不限当前页**。打开时通过 `/api/assets/selection` 一次读取当前项目、标注范围和来源筛选下所有图片 ID，确认框显示范围和总数；例如列表显示 20 张而范围有 21 张，会确认并删除 21 张。项目图片页的全部来源代表整个项目；筛选仅裁剪图时只处理所有裁剪图。匹配结果内「删除本次全部结果」只处理当前查询已返回的结果。确认后按当时的 ID 快照一次批量删除，后来新增的图片不纳入；取消无删除请求，读取/删除失败可在弹窗重试。图片库原图、其他项目与物理文件保留。

## 默认导出

点击「导出标注数据」下载ZIP。默认只导出审核通过的描述/分类及匹配关系；可明确勾选包含普通待审标注。AI分歧必须先人工复核。向量匹配按查询导出，无法判断不放入负样本。

- 单选分类：`classes/000/<asset_id>.png` 等编号目录；目录与类别对应关系见 `manifest.json`。
- 多标签/描述：图片及 `annotations.jsonl`，含 `image`、`labels`、`description`、标注版本、审核状态、内容SHA256、`source` 来源信息。
- 向量：另有 `queries.jsonl`，含 `query`、`positives`、`negatives`、`unknown`、模型空间和判定版本。以图查询会包含查询图片文件。
- 所有格式包含 `manifest.json`；裁剪来源包括原图ID/路径/SHA、检测框、扩展后区域、模型及修订。**同一原图的裁剪图应放在同一训练/验证划分，本包不自动划分。**

```json
{"image":"images/<asset_id>.png","labels":["黑衣","口罩"],"description":"穿黑色衣服并佩戴口罩的人","annotation_version":2,"review_status":"approved","source":{"parent_image_id":"<original_id>","crop":{"region":[12,20,180,340]}}}
```

```json
{"query":{"text":"穿黑色衣服的人"},"positives":[{"image":"images/a.png","judgment":"correct"}],"negatives":[{"image":"images/b.png","judgment":"incorrect"}],"unknown":["<asset_id>"]}
```

## ms-swift 训练格式导出

「导出标注数据」中可选择通用包，或指定训练格式。通用包保持原有文件结构；指定格式额外提供 `train.jsonl` 和 `README.txt`。ZIP 解压后先进入解压目录再启动训练，图片路径相对此目录，勿只复制 JSONL。不会自动划分 train/val，也不会触发推理或训练。

| 格式 | 输出规则 |
| --- | --- |
| 大模型 SFT | `messages` 包含 user 图片指令与 assistant 已保存的描述/类别，`images` 独立对齐；训练指令可编辑 |
| InfoNCE | anchor 文本或图片；每行恰好一个 `positive_messages`/`positive_images`；同查询多正样本拆行，人工标错结果作为 hard negatives |
| Contrastive / Online Contrastive | 每个配对一行，正确 `label=1`、错误 `label=0`；错误图片仍放在单个 `positive_messages` 槽位，由 label 表示关系 |
| Cosine Similarity | 结构同配对格式，现有人工正确/错误映射为 `1.0/0.0`；不使用检索相似度冒充人工连续评分 |

来源显式选择「图片描述配对」「分类标签配对」「检索匹配判定」。描述和类别遵守审核选项；跳过的图片不参与。描述仅使用已有非空描述，不以类别偷偷补齐；类别源按每个类别生成正配对（SFT以类别JSON数组作为回答）。这两类来源不会自动制造负样本，无需生成向量。检索判定源支持文本和图片 anchor，仅使用人工正确/错误判定，无法判断不进入训练样本；InfoNCE 没有正样本的查询跳过，全部跳过则返回清晰错误。

各消息序列的 `<image>` 和对应路径独立对齐。当前为图片平台，不输出未绑定的 video/audio 字段。SFT 指令可放置一个 `<image>`（任意位置），缺省自动加在前面；描述/类别/查询中若含未绑定的模态占位符会拒绝导出，避免产生错位训练数据。以图检索的 anchor 会一并打包，训练图片校验 SHA256，项目裁剪范围、来源和标注版本继续保留在 manifest。

```json
{"messages":[{"role":"user","content":"穿黑衣服的人"}],"positive_messages":[[{"role":"user","content":"<image>"}]],"positive_images":[["images/positive.png"]],"negative_messages":[[{"role":"user","content":"<image>"}]],"negative_images":[["images/negative.png"]]}
```

```json
{"messages":[{"role":"user","content":"<image>请描述衣服和口罩。"},{"role":"assistant","content":"穿黑色上衣，戴着口罩。"}],"images":["images/person.png"]}
```

`INFONCE_*` 参数和 loss 在训练端选择；相同查询可能对应多个正样本，训练采样时须避免将其互相当成 in-batch negatives。本次不新增 ms-swift 训练启动器、连续相似度评分、视频/音频或检测 grounding 转换。SFT结构参照[ms-swift标准多模态数据格式](https://swift.readthedocs.io/zh-cn/latest/Customization/Custom-dataset.html)，embedding结构按本次用户提供的独立字段对齐与单正样本约束实现。

## 数据和运行边界

- Milvus：默认 `http://192.168.1.115:19530`，无鉴权、`default` database，新集合 `image_platform_annotations_v1`。可通过 `MILVUS_URL` / `MILVUS_COLLECTION` 修改地址/集合名；写入集合必须以 `image_platform_` 开头。首期复用现有WEMM的2048维接口，COSINE距离。
- 022 数据迁移保留已有裁剪 Asset ID、图片文件和标注版本，解除公共图库关联；旧图库裁剪记录保留作历史存档，但不能浏览、选取、添加到其他项目或参与旧图库检索。新裁剪图使用项目专属路径，重复裁剪在项目内去重，保留原图/框/模型来源。已有含裁剪图且未明确设置范围的项目自动启用「仅标注裁剪图」。
- 按租户、项目、模型ID/修订、预处理隔离。只有已提交成功的索引条目可用于检索；取消/失效任务的外部写入不会成为可见候选。修改模型配置后，需新建索引批次。旧模型版本保留，不混查。
- 复用HTTP依赖，走Milvus REST v2，不新增pymilvus依赖。写入/检索与集合配置参考[Milvus集合接口](https://milvus.io/api-reference/restful/v2.5.x/v2/Collection%20(v2)/Create.md)及[检索接口](https://milvus.io/api-reference/restful/v2.5.x/v2/Vector%20(v2)/Search.md)。
- 后台队列持久保存，单进程串行运行，单批最多5000张；支持取消、失败重试。服务重启中断项标为失败，需要重试；配置/人工结果已变化的批次需重新创建。
- PostgreSQL保存标注、查询判定和索引成功元数据，Milvus保存向量。删除项目不会自动清理Milvus历史向量；它们不再进入项目检索，需要后续独立维护策略。
- 原 `/image-semantics` 跳转到标注项目。旧图片库生成批次可通过项目入口中的「查看旧图片库生成批次」访问，历史API仍保留。旧PG向量不自动迁移；添加原图到向量项目后建立新索引。
- 未开展大规模压测或模型识别质量评测；不同维度Embedding模型需要独立集合/适配。

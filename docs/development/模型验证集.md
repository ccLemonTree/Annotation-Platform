# 模型验证集

入口：侧栏“验证集”，地址 `/validation`。2026-10-17起默认直接验证YOLO / RF-DETR训练权重，在服务器独立容器中加载，无需先部署推理服务。原服务验证任务与API保留兼容。

页面新增“大模型图片描述”和“向量检索”页签；图片描述人工语义复核、文搜图/图搜图指标、服务与服务器模型目录来源见[大模型与向量验证](大模型与向量验证.md)。下文为目标检测口径。

## 使用步骤

1. 在项目管理选择或新建检测项目，添加验证图片、设置类别并完成标注及人工审核；也可在图片管理导入YOLO包时由管理员勾选“信任已有标注，直接用于训练/验证”，无需再逐图审核。负样本同样可由管理员信任导入。只有AI自动通过的图片不会作为验证真值。
2. 打开“验证集”→“创建验证集”，输入名称、选择项目。可保存项目当前人工审核样本，或选择已有冻结数据集的 `val` / `test` 划分。冻结样本必须保留对应版本的人工审核证据。
3. 在验证集行点击“验证权重”。选择已结束的平台训练任务和权重产物，或选择服务器、模型类型并填写已有权重的绝对路径。支持YOLO、RF-DETR Medium和2XLarge，2XLarge需确认许可证。类别不一致时设置“训练类别 → 真值类别”映射，例如 `{"person":"人"}`。
4. 查看进度及结果，按误检、漏检、类别混淆、推理失败或正确样本筛选；“查看叠框”显示人工真值实线和模型预测虚线。需要记录时下载JSON报告。
5. 取消保留成功结果；重试只重新处理失败或取消的图片。权重/镜像变化需新建任务。远端停止未确认时占用保留，点击“确认停止验证”后才能重试；原服务任务仍按模型修订检查。

验证集固定类别、标注版本、真值框、原图哈希和来源；导入标注另保留来源/确认人，集合source记录imported_annotation_count和review_policy，含导入来源时不声称全部逐图人工审核。修改当前项目标注不会回写历史验证集。删除原项目后仍保留验证集及报告。原图共享，不复制图片；存储维护会保护验证集引用。

从冻结包创建验证集时，批量读取对应标注版本及项目图片，缺失时按租户和内容哈希批量定位共享原图；随后在内存中逐张核对版本、审核人、标注内容和图片哈希记录。不读取图片文件或启动推理。创建和更新标注请求的前端超时为120秒，创建弹窗显示等待秒数并禁止重复提交。若网络超时，后台仍可能保存成功，应先刷新列表确认，避免重复创建。

## 权重、类别与执行设备

- YOLO用 `ultralytics.YOLO(权重).predict(...)`，读取boxes.xyxy/conf/cls；类别顺序默认从权重读取，接口见[Ultralytics官方说明](https://docs.ultralytics.com/modes/predict/)。
- RF-DETR用 `from rfdetr import RFDETR`、`RFDETR.from_checkpoint(权重)`、`model.predict(..., threshold=推理门槛)`，读取xyxy/confidence/class_id。按训练时编号顺序填写类别；例如用户提供的Medium模型为 `fire, smoke`（0=fire，1=smoke）。不会强行重建/缩小检测头，超出类别表的预测会报错，避免错误映射。
- 平台训练模式固定原任务服务器和镜像，运行中权重不作为稳定产物候选；手动路径可用于平台外训练的权重。权重只读挂载，创建时记录SHA256，执行时再次校验，镜像固定digest且不自动下载。
- 默认CPU，限制4核和24GiB内存；点击“读取显卡”后可选单卡GPU。创建时与平台训练共用GPU事务锁，验证预留和训练hold互斥；启动前检查真实GPU进程及MIG状态，禁止抢占。
- 经哈希与尺寸核验的验证原图临时打包，通过ssh-manager上传到独立轮次目录；每批只加载一次模型。确认容器停止后删除本轮临时原图及传输ZIP，保留配置、预测和日志。原始验证集、图片、权重和训练目录均不修改。
- 打包时每秒核对任务状态，上传前后再次检查取消状态。上传超时按文件大小计算（至少330秒、最多4小时），只有收到明确成功回执才启动推理；上传失败会在任务和图片错误中显示“尚未启动推理”。较慢链路仍需等待传输完成，批次准备失败不代表模型漏检。
- 重启会停止旧轮次并标记未完成样本失败，供管理员明确重试；停止不确定时保留资源预留。仅单后端消费者，扩展多实例前需增加租约。

## 指标口径

| 项目 | 口径 |
|---|---|
| TP / FP / FN | 工作点下，同类别预测按分数排序，与真值按IoU一对一匹配；重复预测计FP，错类别计FP和FN |
| Precision | TP / (TP + FP) |
| Recall | TP / (TP + FN) |
| F1 | 2TP / (2TP + FP + FN) |
| AP50 | IoU=0.50时，101点插值精确率的均值 |
| AP50:95 | IoU=0.50到0.95、步长0.05的AP均值 |
| mAP | 对存在真值的类别求AP均值；缺少真值的类别AP显示“—”，不伪造为0 |
| 混淆矩阵 | 行为真值，列为预测；背景行表示误检，背景列表示漏检；类别混淆单列 |
| 负样本误检 | 无真值框图片中，在工作点下出现预测框的图片数 |

默认推理置信度0.001，工作点0.25，匹配IoU0.50，NMS IoU0.45；平台可以修改。AP使用推理门槛以上的预测，P/R/F1使用工作点，工作点不能低于推理门槛。推理时已丢弃的低分框无法恢复，比较模型时应保持参数一致。

模型侧参数沿用已有适配器，NMS只发给支持该字段的接口；SAM3等接口不会接收NMS值。匹配IoU是平台评估参数，与模型NMS不同。

每图每类最多100个预测参与指标。AP计算与[COCOeval](https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/cocoeval.py)独立对照，但首版不包含面积分段及crowd专用规则，不表示完整COCO评测。分母为0的指标显示“—”；存在真值但没有预测时Recall/F1为0，Precision为“—”。

## 结果范围与限制

- 只对成功推理样本计算指标，报告同时显示成功、失败、待处理和取消数。覆盖不完整时明确标为“部分结果”，不可当作全验证集表现。任务失败不计作模型漏检。
- “项目当前人工审核样本”没有自动证明与训练集独立。冻结val/test也需要核对训练记录、来源分组和近重复证据；页面不承诺自动发现所有裁剪图或连续帧泄漏。
- 每集最多5000张，超限拒绝，不能悄悄只取前5000张。当前按单后端执行；重启后处理中条目标失败，供管理员手动重试。
- 推理及图片预览核对冻结原图的哈希、尺寸。原图缺失或变化不会改成当前同名图片，会明确失败；报告保留。
- 权重模式固定SHA256、镜像digest、类别和参数；原服务模式依旧固定模型管理修订，外部服务原地换权重时无法证明权重未变。
- 当前不包含分类、分割、将本机权重上传到服务器、跨模型排行榜或重新训练。真实模型效果需选定独立人工真值集后运行验证。

# 检测标注操作

## 图片如何进入项目

先在独立图片库上传或拉取并筛选，再多选添加到项目；项目只使用原图，多个项目的标注和审核互不覆盖。详见[图片库与项目使用](图片库与项目使用说明.md)。

## 标注与审核入口

侧栏“标注与审核”先显示项目列表和各项目进度，选择项目后才显示其最新标注。列表以图片预览、文件名、框数、版本和审核状态为主；从“打开标注 / 审核”进入工作台看图审核。未标注图片从同项目的“查看项目图片”进入。状态和分页保存在URL，刷新及工作台切图返回仍保留原项目与筛选；从项目图片进入时仍返回项目图片。

## 上一张与下一张

工作台上方“审核”支持全部状态、待审核、已通过、已驳回，按每张图片最新标注判断；未标注图片只出现在全部状态中。可与“筛选”中的类别组合，取两者交集。从审核列表进入会继承审核状态，上一张、下一张、序号跳转、刷新及返回审核列表均保留筛选。修改筛选前请先保存草稿；无匹配图片时提示并保留当前图片及原筛选。

审核或保存后会重新读取筛选队列；若当前图片已不符合条件，保留画面并提示，上一张/下一张仍只在符合条件的图片中切换。筛选内没有图片时可点击“清除筛选”。筛选数量和序号对应当前筛选结果，不是项目全部图片。见[审核筛选验收](../testing/2026-10-26-workspace-review-filter.json)。

项目管理、标注项目卡片、项目图片及项目标注审核页提供“继续标注”按钮（首次打开过此项目的工作台后显示）。按当前账号和项目记住最后成功打开的图片，退出工作台或刷新后可继续。记录在当前浏览器中；更换浏览器/设备或清理网站数据后不会同步。继续前核对图片仍属于当前项目，网络失败保留位置供重试，图片已移除则清理此项目的失效位置。记录位置不等于保存草稿，离开前仍需保存修改。

工作台按当前项目的图片顺序切换，与项目图片列表一致（创建时间倒序，同时间按ID倒序）。直接读取当前图片位置和前后图片，无需逐页扫描整个项目；首张禁用上一张，末张禁用下一张。项目增删图片后位置可能变化。

“上一张”和“下一张”之间显示“序号输入框 / 总数”。直接输入第几张，按回车跳转，无需额外按钮；只接受1至总数之间的整数。跳转前沿用自动保存，查询失败或保存冲突保留当前图和草稿，序号恢复为当前图片位置。跳转复用项目图片列表，每次只读取目标序号的一张图片。

加载位置时显示“定位中…”。若出现“图片顺序读取失败”，点击“重试切图读取”即可重读，当前图片和草稿保留。按钮与A/D、左右方向键仍遵循下文的自动保存规则：保存失败或版本冲突时停在原图。修复验收见[切图验证](../testing/workspace-navigation-verification-2026-10-15.json)。

## 类别在哪里设置

在主平台“项目管理 → 新建项目／编辑项目 → 标注类别”中输入名称并按回车，支持逗号分隔。类别属于项目，存入已有的 label_schema.labels。工作台上方“框类别”决定新框类别；右侧“选中框类别”修改当前框；1–9 对应配置中的前九个类别。

项目类别改名时，在“编辑项目 → 同步已有标注类别”指定旧类别到新类别的对应关系，再保存项目。页面也会列出已标注框正在使用、但不在当前配置中的旧类别。例如把“人”改为“person”，先修改标注类别，再将旧“人”对应到“person”。已有框使用的类别被删除且未设置映射时，更新会被拒绝；仅新增类别或调整顺序不会改框。

保存项目后，所有受影响图片的最新框同时改名，坐标和其他标注信息不变，每张图片新增一个待审核版本。允许明确合并类别和交换名称；不按列表位置猜测对应关系。历史标注与冻结包保留原名称和审核记录，新版本需重新审核。项目配置或标注版本已变化时返回409，重新打开编辑窗口或重新加载标注后核对。

2026-10-13已备份并同步test-img中的2张图片、5个框：“人”→“person”，同步当时的新版本为v4、v2，均待审核；之后新增标注和审核以平台当前记录为准。6张原图及两个冻结包哈希不变。未配置类别的项目不默认使用“人”，须先配置后标注。

## 批量删除项目中的指定类别框

管理员在检测标注工作台点击 **批量删除类别框**，选择 `person` 等类别后点击 **预览影响**。操作作用于当前项目全部参与标注的图片，不随工作台标签筛选缩小；仅裁剪图项目仍只处理裁剪图。确认框显示影响图片数、框数、删除后变为空标注的图片数及当前已审核图片数。预览为零时不能执行，改变类别后须重新预览。

点击 **确认删除**后，只从最新已保存标注移除精确匹配的类别框，保留图片、其他框及标注元数据。每张受影响图片建立新的待审核版本，原版本和审核记录保留，负样本须由管理员审核；当前图片、历史、审核状态和导航重新读取，删除类别的筛选自动清除。项目类别配置、其他项目、图库原始导入标注和已冻结导出包保持原样。

有未保存草稿、正在绘制或查看历史时不能发起批量操作。执行前锁定项目资产并重新核对预览；标注、审核、类别配置或图片范围变化时返回409，须重新预览。全部修改在同一事务中完成，途中失败回滚；通信失败时先重新预览核对结果，不直接重复提交。取消窗口不会提交删除，普通用户不显示按钮，后端同样要求管理员权限。

验收使用隔离数据和独立PostgreSQL数据库；对真实项目仅只读预览，实际删除由用户确认。见[批量删除验收](../testing/2026-10-26-project-label-removal.json)。

## 工作台窗口布局

桌面窗口宽度至少992px时，工作台使用剩余窗口高度：压缩重复标题，工具栏留在上方，画布完整适应区域，负样本确认留在画布下方；右侧框列表/属性/历史独立滚动。窗口改变不重置当前缩放，“适应图片”恢复完整原图。仍按原图像素保存标注，黑色边缘是适应窗口的留白，不裁剪原图。

窄屏继续纵向排列，避免把画布压得过小。已检查1366×768、1692×947和1280×600桌面窗口，以及390×844窄屏；证据见[窗口布局验收](../testing/workspace-viewport-verification-2026-10-14.json)。

## 鼠标与重叠框

- 默认工具：空白处拖动绘制，点击或拖动框选择/移动，拖右下角黄块改变宽高。按 Shift 拖动可在已有框内强制绘制。
- 滚轮以光标位置缩放；上方 + / − 按钮以视图中心缩放，“适应图片”重置视图。比例为适应视图的相对倍率，范围20%–800%，不是显示像素与原图像素的1:1保证。
- 按住 Ctrl/Cmd 或空格拖动平移，也支持鼠标中键。缩放和平移只改变视图，保存的坐标始终是原图像素。
- 重叠处优先命中面积较小的框；Alt 点击在该位置命中的框之间循环。右侧框列表可精确选择。
- 重叠可能是正常遮挡，不做自动删除/合并。同类别 IoU ≥ 0.9 的框提示可能重复，由标注人核对。该提示不是自动审核。

## 键盘

| 按键 | 操作 |
|---|---|
| Ctrl/Cmd+S | 保存当前标注 |
| Ctrl/Cmd+Z | 撤销 |
| Ctrl/Cmd+Shift+Z / Ctrl+Y | 重做 |
| Delete / Backspace | 删除选中框 |
| N | 清空当前图片全部框并确认负样本，可用Ctrl/Cmd+Z撤销；手动保存或切图时写入新版本 |
| B / V | 画框 / 选择工具 |
| 1–9 | 选择项目类别；有选中框时也修改其类别 |
| A / D 或左右方向键 | 上一张 / 下一张；有修改时先自动保存，成功后切图 |
| Tab / Shift+Tab | 画布聚焦时选择下一框 / 上一框；到边缘后继续按可离开画布 |
| Esc | 取消正在拖动的操作或取消选择 |

输入框、类别选择、弹窗、中文输入合成和按键长按时不触发工作台全局快捷键。页面“快捷键”按钮可打开说明。

画布下方的“标记负样本（N）”与快捷键相同，一次清空全部框并勾选负样本；历史版本只读，绘制或保存过程中不执行。不会直接删除服务器历史标注；保存后形成待审核的新版本。继续位置、序号与负样本验证见[本轮验收](../testing/workspace-progress-verification-2026-10-15.json)。

## 撤销与保存冲突

撤销覆盖绘制、移动、尺寸、坐标、类别、删除及负样本勾选，每次拖动只记一条。最多保留本地100步；操作结束前按 Esc 或收到 pointercancel 会丢弃该次临时拖动。

这些操作先修改本地草稿，手动保存或切换图片时才形成服务器新版本。上一张/下一张按钮与A/D、方向键均先保存，成功后切图；无修改不新增版本。保存失败或409时停在原图并保留草稿。删除最后一个框后须勾选负样本确认，否则不会自动保存或切图。离开标注工作台仍有未保存提示；刷新或关闭浏览器并不保证自动保存。保存、重新加载、切换图片或查看历史会清空本地操作栈；服务器历史继续保留。

保存仍携带 base_version。其他人已更新时返回409，不覆盖新版本，本地框和撤销操作保留。记录当前修改后再重新加载并核对，平台不自动合并两个版本的框。历史版本只读；审核流程保持原样。

## 验收边界

参考F:/hzxf/labeling的交互，复用当前React/SVG实现；参考项目未修改，没有增加依赖。当前验证包括142项后端回归（显式启用4项独立PostgreSQL和6项真实CPU数据加载器用例）、5项编辑状态/几何测试，以及类别映射3项、自动保存6项、标注交互25项和界面布局23项浏览器检查；双入口构建通过。记录见[类别同步与自动保存验收](../testing/label-sync-autosave-verification-2026-10-13.json)。

浏览器写入及500/409由拦截数据验证，读取真实图片；真实类别同步通过主API执行，并核对历史、坐标、计数及原图/冻结包哈希。多指触屏、跨浏览器及真实多用户手工操作尚未联调；并发旧版本写入与类别同步由独立PostgreSQL用例覆盖。自动模型预标注服务仍未部署。

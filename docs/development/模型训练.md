# 模型训练

侧栏“模型训练”对应 `/training`。管理员创建、预检查、启动、停止任务；租户内用户可查看配置、日志和产物。保存配置不会启动容器，启动还需预检查通过并明确确认。

## DINOv3 ViT-S/16 · LTDETR 检测微调（2026-10-19）

新增训练器 `dinov3_vits16_ltdetr`，针对 `dinov3/vits16-ltdetr-coco` 完整预训练检测模型进行**监督微调**，不是 `lightly-train pretrain`。电瓶车等目标必须先有框标注、完成审核并划分train/val；约100张原图不能直接训练本检测器。可先使用现有文本提示检测预标注，再人工补漏、改框、排除自行车/摩托车等误标。

### 镜像和完整权重准备

默认镜像使用用户指定的 `lightly/train:latest`。镜像必须事先在所选服务器存在；平台不会自动拉取。`latest`可能变化，预检查会在无GPU、禁网、只读权重容器中检查公开训练API并CPU加载本地完整检测模型，显示Lightly版本和型号；启动继续固定实际镜像digest。不是在平台FastAPI环境安装Lightly。

以下是**管理员在所选Linux训练服务器手动准备的示例命令**，本次开发没有执行下载或远端写入：

```bash
docker pull lightly/train:latest
mkdir -p /ai/chen/training/weights
curl -fL --retry 3 \
  'https://lightly-train-checkpoints.s3.us-east-1.amazonaws.com/dinov3_vits16_ltdetr_coco_251218_4812416b.pt' \
  -o /ai/chen/training/weights/dinov3_vits16_ltdetr_coco_251218_4812416b.pt
printf '%s  %s\n' \
  '4812416b861a80f305889cf1408775044c8b05f1baf9be45cd4b1d0edd5d4532' \
  '/ai/chen/training/weights/dinov3_vits16_ltdetr_coco_251218_4812416b.pt' | sha256sum -c -
```

URL和SHA256来自[Lightly Train v0.17.0模型注册](https://github.com/lightly-ai/lightly-train/blob/v0.17.0/src/lightly_train/_task_models/ltdetr_object_detection/config.py)；开发时仅HEAD确认URL返回200。若文件已存在，先校验再决定是否下载，不覆盖正在使用的权重。训练表单填写完整文件绝对路径，不填模型名称；仅DINOv3骨干`.pth`不能替代完整检测`.pt`。也可使用同架构先前导出的完整检测权重继续微调，模型身份需为`dinov3/vits16-ltdetr`或`dinov3/vits16-ltdetr-coco`。

### 数据与参数

- 平台来源：复用已审核、明确train/val的冻结YOLO/COCO；可选择训练类别。原图片、冻结ZIP、来源标注不变；任务目录生成类别映射，未选类别的图片保留为背景样本。
- 服务器来源：YOLO配置包含`names/train/val`；或Roboflow式COCO的`train/valid`（也支持`val`）目录，每个划分含`_annotations.coco.json`。不修改原文件或筛选标签，在内存构造Lightly data对象。
- test图片保留在原数据/冻结包中，不传入Lightly训练或验证。按摄像头、视频片段或拍摄时间分组后再划分，避免相邻帧泄漏；独立测试图片也不应参与预训练。
- 初始参数：`steps=1000`、**全部GPU合计**`batch_size=4`、梯度累积1、`lr=1e-4`、骨干学习率比例0.01、预热100步、每100步保存/验证、`16-mixed`、2个数据加载进程、随机种子42。所有参数可编辑，总batch须被所选卡数整除，预热步数须小于总步数。首版使用全部所选单机GPU；这些数值只是约100张图的起点，不保证精度或训练时长。
- `backbone_freeze=false`默认微调整个检测器，骨干使用较小学习率；也可明确冻结骨干作对照。不要仅依据训练loss选模型，应看独立val的漏检、误检和mAP。

### 产物与试用

训练调用公开 `lightly_train.train_object_detection`，`model`为本地完整权重路径。框架在任务`train/exported_models/`保存`exported_best.pt`、`exported_last.pt`，以及`train/checkpoints/`中的检查点；沿用平台日志、状态和产物下载。完整导出权重包含检测结构和训练类别，可在“模型效果预览”或“模型验证”选择DINOv3训练任务的产物，也可手填服务器权重路径，镜像使用`lightly/train:latest`或实际兼容的固定版本。类别顺序留空时从权重读取；若手填则严格核对。不自动部署在线检测服务。DINOv3与RF-DETR使用检测器原生后处理，平台NMS IoU不是其原生predict接口参数。

独立使用导出模型：

```python
import lightly_train
model = lightly_train.load_model('/path/to/exported_best.pt', device='cpu')
result = model.predict('/path/to/image.jpg', threshold=0.25)
# result['bboxes']: 原图像素xyxy；result['labels']: 类别ID；model.classes: ID到类别名。
```

许可遵循[Lightly Train许可说明](https://github.com/lightly-ai/lightly-train/blob/main/docs/source/licensing.md)及DINOv3权重条款。

本地验收涵盖类型化配置、API草稿/编辑、冻结YOLO/COCO、类别重排/背景样本/test隔离、脚本调用、CPU预检查失败保护和检测预测转换。没有执行真实Lightly镜像训练或该模型权重推理，尚未证明真实GPU训练、独立模型加载和电瓶车检测精度；需标注数据和远端镜像/完整权重就绪后完成短训练与留出图验收。

## 数据来源

- **服务器已有路径**：YOLO填写已有YAML文件；RF-DETR填写已有数据集目录或标准data.yaml/data.yml文件（文件输入转换为所在目录，框架读取目录内标准配置或COCO）；Swift/WeMM填写训练JSONL。直接交给对应训练器，沿用原配置、标签编号和数据划分，不生成新数据配置、不筛选标签。RF-DETR不支持自定义YAML文件名；同目录存在data.yaml时拒绝单独指定data.yml，避免实际读取另一配置。预检查按镜像内框架规则解析路径，不擅自修正YAML；原配置引用的容器路径应在附加挂载中配置为对应只读目录。
- **平台冻结导出集**：先在项目中冻结仅已审核的明确train/val划分。YOLO使用YOLO格式，RF-DETR使用YOLO或COCO格式。启动时按SHA256复用训练服务器的冻结ZIP缓存；未命中才通过ssh-manager SFTP上传，核对包SHA256及每张图片SHA256，再生成训练器目录；不重新导出、不把test集当val。超过40000成员或40GiB展开大小拒绝解包。
- **平台标注数据（Swift/WeMM）**：在创建任务中选择此来源、标注项目和数据来源，点击「冻结当前标注」，自动选择生成的固定版本，也可复用已有版本。支持描述、分类标签配对，以及向量项目的检索匹配判定。Swift causal_lm 使用 SFT；embedding 使用与 loss_type 一致的 InfoNCE、Contrastive、Online Contrastive 或 Cosine Similarity。冻结空样本或同一查询/图片存在正负冲突会报错，需统一历史判定。默认仅已审核描述/分类，可明确包含待审核；匹配关系默认仅含审核通过项；可明确包含普通待审，但 AI 分歧需先人工复核，通过后导出。图片引用自动改为容器 `/output/dataset/` 下绝对路径，无需手工挂载平台图片。仍需填写服务器基础模型路径，启动时校验 GPU/镜像/目录；保存只创建待启动任务。不会自动划分 train/val，启用评估仍需独立服务器验证 JSONL。同一原图的裁剪图不可跨训练/验证集。
- 基础权重首次保存任务后，按租户、服务器、训练器自动复用最近保存的路径；可修改，不跨训练器复用权重。输出根目录默认 `/ai/chen/training/runs/YYYYMMDD-HHMMSS`（北京时间），可修改；不存在时自动在可写父目录下创建，再增加任务UUID避免覆盖。

### 冻结包服务器缓存

缓存固定在所选训练服务器的 `/ai/chen/training/dataset-cache/<SHA256>/input.zip`，跨任务输出根目录复用。同一服务器、SSH账号需有读写权限。首次上传先暂存于任务目录，校验成功后原子发布缓存并移除本次暂存包；后续任务重新校验缓存SHA256，命中便跳过上传，启动记录显示命中或首次上传的结果。旧任务中的原始 `input.zip` 会从同租户、同服务器、相同冻结包的最近5个任务查找，校验后复制入缓存，旧文件不删除。

平台单后端进程内，同一服务器记录和SHA256的准备过程串行执行；服务器端按SHA256加文件锁、临时写入和原子替换，避免并发任务读到半包。损坏缓存不命中；上传不完整不会发布或解包。缓存仅复用原冻结ZIP，每个任务仍独立解压、逐图校验、生成标签映射及保存训练输出，修改某次训练数据不影响其他任务。不同SHA256不复用；服务器已有路径来源沿用原流程。

删除任务记录不会清理服务器缓存或旧任务文件，当前不自动淘汰缓存，需按磁盘情况手动维护。取消不会启动容器；正在进行的传输或校验可能完成后才结束，已完成的缓存可供后续任务使用。

### 自动配置与选择标签

仅平台标注数据选择冻结版本后可选择训练标签，默认全部。服务器已有数据完全沿用原配置。平台冻结数据支持YOLO及RF-DETR的YOLO/COCO检测数据；Swift/WeMM的JSONL不做检测标签过滤。所选标签按原始类别顺序连续编号，生成 `prepared-dataset/class_mapping.json` 记录新旧类别映射，train和val都必须有选定类别标注。

平台冻结包按原SHA256传输后，训练镜像在任务目录自动生成 `prepared-dataset/data.yaml`（YOLO/Roboflow YOLO）或各划分COCO文件，包含本次路径、标签与类别数量；无需用户手写配置。保留源文件与原train/val/test划分，不复制全部图片，使用只读源图片链接和新标注文件。未选类别的框被移除，图片作为背景保留；YOLO空标注或缺失标注文件按背景样本处理。

RF-DETR Medium/2XLarge在加载模型前，使用镜像内RF-DETR的类别识别方法读取本次实际训练数据，并将结果显式传给构造函数的 `num_classes`。服务器数据读取现有配置；平台冻结数据在标签筛选和编号重映射完成后读取生成目录，因此只选1类时传1，而非原数据集类别数。日志输出实际目录及类别数；读取失败或类别为空时停止，不回退到预训练权重类别数。当前三类数据初始化为 `num_classes=3`，分类头含背景槽共4通道。仅影响修复后新启动任务，已有训练权重不被改写。

绍兴已有两份YAML均包含fire、smoke、star。实查data.yaml指向train/images、valid/images，yolo-data.yaml指向images/train、images/val；两者均写了容器路径 `/workspace/dataset`。YOLO若使用这类配置，可将服务器 `/ai/chen/training/datasets/middle` 附加只读挂载到 `/workspace/dataset`，保持配置内容不变。RF-DETR可输入 `/ai/chen/training/datasets/middle` 或 `/ai/chen/training/datasets/middle/data.yaml`，由实际框架读取标准配置及划分。

## 参数

向量匹配现支持大模型独立审核：人工与模型一致自动通过，不一致/不确定/失败转人工。冻结默认只含已通过关系，包含普通待审选项不会绕过 AI 分歧复核。审核改变后需重新冻结，已保存的固定版本不被改写。训练配置、预检查中的 JSON、审核及冻结证据统一按缩进的等宽可滚动区域显示，类别映射 JSON 离开编辑框时格式化；机器下载的 JSON/JSONL 格式保持原约定。

| 训练器 | 初始化 | 训练参数与默认值 |
|---|---|---|
| YOLO26 | 已有 `.pt` 权重路径 | epochs=300、batch=48（总batch）、patience=15、save_period=10、device=auto、seed=42 |
| RF-DETR Medium | `RFDETRMedium(pretrain_weights=..., num_classes=本次数据类别数)` | epochs=100、batch_size=4、grad_accum_steps=4、lr=0.0001、devices=auto |
| RF-DETR 2XLarge | `RFDETR2XLarge(accept_platform_model_license=..., pretrain_weights=..., num_classes=本次数据类别数)` | epochs=100、batch_size=1、grad_accum_steps=2、lr=0.0001、devices=auto |
| Swift大模型SFT | 已有模型目录；swift sft | task_type=causal_lm；其余见下 |
| WeMM向量微调 | 已有模型目录；swift sft | task_type=embedding、loss_type=infonce；其余见下 |

Swift参数均在页面配置：tuner_type=lora、lora_rank=8、lora_alpha=32、torch_dtype=float16、num_train_epochs=1、per_device_train_batch_size=1、gradient_accumulation_steps=1、learning_rate=0.00005、max_length=2048、lazy_tokenize=true、dataloader_num_workers=2、logging_steps=10、save_steps=100、save_total_limit=3、eval_strategy=no、dataloader_drop_last=true、freeze_vit=true、freeze_aligner=false。启用评估时必须提供服务器验证JSONL。

环境变量也可配置：MAX_PIXELS=100352、PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True、INFONCE_USE_BATCH=false、INFONCE_HARD_NEGATIVES=4、TOKENIZERS_PARALLELISM=false、CUDA_VISIBLE_DEVICES=auto、NPROC_PER_NODE=auto；另提供可选IMAGE_MAX_TOKEN_NUM。图像上限的实际消费变量取决于对应镜像中的Swift/图像处理器，不把设置存在当作限额已生效。

公共配置包括镜像、GPU UUID、输出根目录、产物子目录（默认train）、共享内存（默认16GiB）及附加挂载。数据和基础权重目录自动只读挂载；输出使用“根目录/任务UUID”，在容器内挂载为 `/output`，训练产物写入 `/output/<产物子目录>`，不会覆盖旧任务目录。附加挂载默认只读，不允许系统目录、Docker套接字或覆盖 `/output`。

共享内存对应Docker `--shm-size`，设置容器 `/dev/shm` 的容量上限，主要用于PyTorch数据加载进程间交换数据。它使用主机RAM，不是GPU显存；设为16GiB不会立即预占16GiB，也不会增加可用显存。空间过小可能出现数据加载worker的bus error；主机实际内存不足仍可能OOM。

物理GPU用UUID选择，容器内编号从0开始。`device=auto`使用全部所选卡；手填device须使用容器内编号。NPROC_PER_NODE须等于所选卡数，CUDA_VISIBLE_DEVICES如手填须覆盖这些容器内编号。RF-DETR devices可为auto或不超过所选卡数的正整数。2XLarge许可证必须由管理员明确确认；Medium不能使用不兼容的Large架构权重。

## 镜像与执行

YOLO总batch必须能被实际使用的GPU数整除。例如7卡时batch=48不兼容，可改为49或选择可整除48的卡数；平台在保存配置时校验。

- 检测默认镜像：`aisfh5.com:9091/ai/jashan_train:yolo-rfdetr`。
- Swift默认镜像：`modelscope-registry.cn-hangzhou.cr.aliyuncs.com/modelscope-repo/modelscope:ubuntu22.04-cuda13.0.3-py312-torch2.13.0-vllm0.28.0-modelscope1.40.0-swift4.5.3`。
- 使用服务器已存在的镜像、权重和数据。镜像缺失时不自动pull，基础权重缺失时不自动下载；训练容器禁网，训练前应准备模型所需全部本地文件。镜像检查记录实际image ID，并以该ID创建容器。
- 统一以 `python3 -u /output/train.py` 执行，RF-DETR/YOLO按对应Python API调用，Swift使用参数数组执行CLI，不拼接用户Shell命令。
- 每任务保留 `run_config.json`、`train.py`、所有Docker日志与框架产物。日志读取最近200行，最多160000字符；合并读取stdout/stderr，清理ANSI和进度回写。日志面板使用等宽字体/行号，支持横向滚动、自动换行和跟随最新，保留错误/告警。产物页最多列出500文件的路径/大小/类型，完整文件仍留服务器。

### 下载模型产物与删除任务

详情“模型产物”中点击“下载到本地”，支持权重、配置和日志。后端只允许该任务产物子目录内的普通文件，拒绝绝对路径、穿越和符号链接；经ssh-manager SFTP临时下载并核对服务器SHA256和大小，再由浏览器保存。过程中变化的权重会拒绝下载，请选稳定检查点或结束后重试。大文件需等待服务器传输和校验；本机需有对应大小临时空间，正常发送或连接结束后清理本轮副本。

管理员可在待启动、已完成、失败或已取消任务详情点击“删除任务”并确认。只移除平台记录，服务器上的数据、权重、日志和容器全部保留；删除后不能从原任务入口下载，应先下载所需产物。准备中、训练中、停止中、状态未知或仍有GPU hold的任务拒绝删除，须先停止并确认释放；不把删除当作停止命令。历史验证任务的独立权重快照/指标保留。

## 状态与资源

状态：draft→starting→running→completed/failed；停止经过stopping→canceled。网络、SSH或Docker状态无法确认时为unknown，保留GPU hold。后端重启只核对现有容器，不自动重发启动命令。已退出且退出码为0仍须找到权重文件才标完成，未完成训练不标为可用模型。

GPU已有计算进程时阻止启动，不停止外部服务；平台用GPU UUID唯一约束防止两个有效训练任务重复占用。启动前在服务器再次核查，仍不能阻止独立于本平台的外部调度器随后抢用同一卡。停止只接受匹配平台任务标签的容器，并写入取消标记阻止迟到启动；确认停止才释放hold。不会删除容器、数据或产物。活动任务使用的服务器连接禁止修改或删除。

待启动（draft）任务可在详情中点击“编辑配置”修改，保存后清空旧预检查，须重新检查；已提交、结束或取消的任务改参数需创建新任务。首版不提供故障自动重试、断点续训、多机、调参、LoRA合并或模型部署。仅单后端进程，训练状态15秒轮询，网络异常保留占用。

## 接口与运维

2026-10-20新增“效果分析与对比”：训练列表或详情同名入口，先读服务器指标，再调用已配置的大模型生成持久报告。支持全部训练器的可用指标；最多对比3个更早完成任务，标明数据/类别/验证配置差异，不自动重新评测。详见[操作与接口](../api/训练效果分析.md)。

鉴权前缀 `/api/training`：GET catalog、servers、defaults、runs、runs/{id}、runs/{id}/logs、runs/{id}/artifacts；POST dataset、runs、runs/{id}/precheck、start、stop、refresh；PUT runs/{id}修改待启动配置。servers/defaults和所有POST、PUT限管理员，GET任务按租户隔离。defaults按服务器/训练器读取最近保存权重；dataset仅以无GPU、只读源挂载的临时容器读取类别/划分，不创建任务、不准备训练数据。

2026-10-17新增 `GET /api/training/runs/{id}/artifacts/download?path=相对路径`（同租户读取，响应文件，路径非法422、传输校验不一致409）和 `DELETE /api/training/runs/{id}`（管理员，成功204，活动状态/持有GPU返回409，仅删记录）。所有文件传输继续使用ssh-manager MCP；本机临时路径不出现在响应中。

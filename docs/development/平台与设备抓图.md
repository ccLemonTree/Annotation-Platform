# 平台管理与设备定时抓图

2026-11-05：定时抓图只抓最新成功一张并入库/关联项目，继承设备已有场景。定时抓图不替换设备代表图，不改变场景标签、状态、缓存输入及版本，也不因分类配置版本变化而自动排队；没有分类结果的设备继续保持未分类。设备同步的既有自动分类规则保留；重新分类由用户主动触发，人工修正结果继续受保护。此变更不自动清理或重跑历史任务。

2026-11-04：设备筛选拆分业务场景与摄像机位。业务场景维持任一/全部匹配，多个机位内部取任一；两组条件取交集，并在分页前生效。“同步与分类进度”改为工具栏按钮打开抽屉，保留平台范围统计、同步平台进度和当前分类批次。覆盖率进度不因少量失败变成整条红色，失败数量单独突出显示。

## 使用

数据拉取页新增“平台管理”和“设备抓图”。平台管理可以新增、编辑、删除平台，单独执行连接测试；启用状态与连接状态分别显示，保留最近检测时间和错误。密码不返回浏览器，编辑时留空保留原密码。手工配置不会被中央平台同步覆盖；删除保留历史图片、项目引用和任务，中央同步也不会重新加入已删除的平台。仍有运行任务或启用调度引用的平台须先停止对应任务。

平台列表支持按平台名称、服务地址、平台标识进行不区分大小写的包含搜索，忽略首尾空格；在完整列表筛选后分页，输入时不重复请求后台。连接错误提示包含平台名称。

平台管理搜索框旁支持“全部平台 / 在线平台 / 不在线平台”，与搜索条件组合，在分页前筛选；切换条件回到第一页。不在线包含连接失败、未配置及未检测；依据连接状态，不依据启用开关，停用但最近检测在线的平台仍属于在线。刷新或检测更新结果后按当前筛选条件显示；一键检测仍覆盖全部平台。此次仅热更新前端，未重启后端，验证见 `docs/testing/platform-status-filter-2026-11-03.json`。

在线状态不是后台定时实时探测，而是最近一次连接测试或设备同步的结果；刷新平台只读取保存状态。判断时应同时查看检测时间。连接测试包含登录验证，成功不等于所有设备分页、抓图及其他业务接口都已验收。

管理员可一键检测全部未删除平台，包含停用平台，不受搜索或分页影响。缺少地址、账号或密码时标记未配置；其他平台分别保留在线/连接失败原因和检测时间。限制一批检测、最多两个连接请求同时执行，显示进度与在线/失败/未配置数量；刷新页面后读取最近任务继续显示。仅连接和登录，不同步设备、不拉图、不分类，也不启用定时探测。

可停止后续检测，当前平台的既有登录流程需等待结束或超时，取消后的迟到结果不覆盖状态。任务类型为 `platform-check`，使用已有任务表，无数据库迁移。此前为保留分类暂存，用户随后要求清空设备及任务，已在无活动业务时随代表图流程一起更新115；前期验收见 `docs/testing/platform-bulk-check-2026-11-03.json`，本次上线见 `docs/testing/device-representatives-2026-11-03.json`。

设备抓图页可以同步全部启用平台或指定平台的设备。后台逐平台登录、分页查询，错误可在执行记录中展开查看；页面不会把平台启用标记当作已经连接。上游设备接口可访问的设备范围由各平台接口决定，原始状态和场景另外保留，不冒充设备实时在线检测。

选择设备后创建定时拉图，设置间隔、可选标注项目、图片集和分辨率阈值。项目管理每个项目提供“数据拉取”入口，自动预选此项目并筛选其计划。计划把目的地持久保存，后续轮次不依赖页面临时选择。图片沿用统一入库和哈希去重；绑定项目时新增项目引用，共享原图。

“全选筛选结果”读取设备列表当前筛选条件命中的全部分页，不只当前页；显示已选数量和读取进度。切换分页保留选择，改变筛选条件清空选择，清空也可取消尚未完成的全选。分页读取失败或发现设备总数变化、重复记录、提前空页时保留原选择并提示重试，避免只选中部分却显示完成。全选数量不限；现有“分类所选设备”和单个定时拉图任务最多提交1000台设备，超出时按钮禁用并提示。此项在115仅热更新前端，不重启后端或停止任务，场景多选待部署包已合入此改动，验证见 `docs/testing/device-select-all-2026-11-03.json`。

定时拉取的是设备在上游平台已经生成的抓图。2026-11-04按用户要求改为每轮每设备仅查询最新成功一张：第一页、每页1条、按记录ID降序，不再按时间窗口补拉或翻页抓取历史。已有计划保留其间隔、设备和目标项目，更新后下一轮使用新逻辑。相同内容复用原图及项目引用；最新图低于分辨率阈值时计入过滤，不继续寻找更旧图片。无成功抓图时本轮为空；查询、下载或入库失败记录原因，下一轮重试。可以立即执行、暂停、启用或删除计划，同一计划不并行运行；最多两个计划同时执行。

## 设备场景

选择设备批量分类，或分类当前平台/全部启用平台的设备。有本地抓图时优先用设备代表图识别场景，没有抓图时才按设备名称识别。沿用默认入库模板的模型和候选场景，可在“场景分类设置”修改。同设备、同名称、代表图和配置版本复用结果，后续图片继承，避免逐图重复识别；失败也缓存，直到显式重试或输入变化。已有图但文件不可读取时提示失败，不悄悄退回名称分类。场景支持多标签，不修改检测类别或上游场景。

平台下拉框支持“仅在线平台”，设备支持“有图片 / 无图片”筛选。有图片指设备已有本地代表图引用，不代表上游实时在线。

选择具体平台时，“同步当前平台设备”只同步这个平台；不选择具体平台且勾选“仅在线平台”时，操作全部已检测在线且启用的平台。未勾选时同步会检查全部启用平台的连接，仅同步连接成功的平台。同步新增设备后，开启自动分类则自动入队；已有结果保留，设备名称或代表图变化时重新分类，无须每次重跑全部设备。

同步设备时先补取代表图，再允许自动分类：无可用本地代表图的设备按设备ID查询最新成功抓图（按ID降序，仅第一页、每页1条），只下载这一张；已有本地代表图复用。无抓图、查询或下载失败、图片无效时保留固定中文原因，回退名称分类，不将取图失败当成设备同步失败或分类失败。取图次数和有图/复用/无图/失败数量按平台显示，失败明细保留前100台。重同步时仍只补取缺图设备。

代表图复用统一内容哈希文件及硬链接，不自动创建数据集图片或项目引用，不应用数据集长边阈值；因此640×360等小图也能作为代表图。以后正式入库同字节图片共享原文件。一个平台复用同一次登录，全部同步及取图最多两个平台同时执行；取消或服务重启后不发布迟到图片、标记未完成代表图，人工场景仍保留。

“重跑失败分类”覆盖所示平台范围所有分页中当前失败的设备；设备行“重跑分类”只重跑一台。复用 `/devices/classify` 的布尔字段 `only_failed`，执行前再次检查失败状态，保留成功、未匹配及人工修正结果。批量全部分类和失败重跑均尊重平台选择与“仅在线平台”；设备搜索、场景、分类状态、图片筛选只筛选列表。服务端按平台和设备ID游标分页，避免失败状态改变后漏过后续设备。

失败重跑与一键检测全部平台已在115随代表图流程一并发布，未启动真实同步、分类或全平台检测。之前暂存阶段验证见 `docs/testing/device-failed-retry-2026-11-03.json`。

各拉图路径保留平台、设备ID及设备名，原图和项目图片显示来源设备。只有名称而无设备ID的来源按平台内名称分组，用于共享分类，不可当真实设备创建抓图计划。无设备信息的上传或AI图仍使用原有图片场景分类。同字节图片有多个设备来源时保留来源列表，图片场景为已成功来源的标签并集，不随最后一次下载覆盖。

人工修正后自动分类跳过该设备，结果同步给该设备已入库图片。分类期间手工修改、取消任务、再次分类、代表图变化或设备改名，会阻止迟到结果覆盖当前结果。代表图通过同源认证接口预览，不向页面输出平台登录凭据。

人工“修正场景”弹窗自动展示放大的鉴权代表图，便于边看图片边修改场景。代表图缩略图支持点击或键盘打开大图，复用鉴权图片预览弹窗，Esc或关闭按钮退出；不触发设备选择、同步或分类。此项已在115单文件热更新，无需后端重启。

设备场景支持多选大类和具体场景，命中任一条件即匹配。重复 `scene` 查询参数保留各名称，后端展开大类、去重并在分页前执行筛选，切换和清空回到第一页。此前为保留同步与分类任务暂存；2026-11-04用户确认任务完成并要求发布后，已在活动队列全部为空时更新115并重启后端。代表图放大、全选筛选结果和进度条均保留，未重新启动分类。原始隔离验证见 `docs/testing/device-preview-scene-filter-2026-11-03.json`，上线验收见 `docs/testing/device-scene-multiselect-release-2026-11-04.json`。

平台概况显示当前设备总数、已处理分类、分类成功、未匹配场景、失败、排队/处理中和未分类；分类成功必须有场景标签，包括有标签的人工修正，已处理等于成功加未匹配加失败。点击未匹配数量可筛选空结果，“查看失败设备”按平台筛选全部当前失败设备，并显示名称和原因。执行记录保留每次任务的时间、范围和平台成功/未匹配/失败/跳过数量；分类任务每个平台保留前100台失败设备的名称、ID和原因，避免大任务让轮询响应无限增长。当前统计与历史任务统计分开显示，旧记录缺失的时间、数量不反推补造。

设备列表上方的“同步与分类进度”使用现有轮询统计：同步显示任务的平台处理百分比，以及正在处理平台的代表图数量/设备总数和百分比；平台总量尚未返回时显示正在登录或查询设备列表，不编造进度。执行记录也显示服务端已记录的任务进度条。

分类条显示当前平台筛选范围内已同步设备的整体处理覆盖率，分子为成功、未匹配和失败之和，并分别列出结果、排队/处理中、未分类数量；不把自动分类的每100台批次当作全量。当前批次已处理/跳过数另行显示。同步增加设备会使分母增长，设备搜索与场景筛选不改变总进度范围；零设备显示0，缺失统计时不推算。进度条已在115单文件热更新，保留当前同步/分类任务，场景多选仍暂存待发布，验证见 `docs/testing/device-progress-2026-11-03.json`。

模型正常返回空标签表示“未匹配场景”，不表示分类命中或模型调用失败。底层 `completed` 保留处理完成与缓存语义；设备、图片及项目图片接口对空完成结果返回 `unmatched`，界面显示提示并支持单独筛选，无需改写旧记录。旧执行记录未区分命中时明确提示，不能将请求完成数量当作匹配成功数量。此修正不会自动重新分类，验证见 `docs/testing/scene-unmatched-2026-11-03.json`。

平台/设备写操作和新任务取消仅管理员可执行，沿用 SmartEye 主租户限制。分类任务最多两个批次；同步最多两个批次且上游查询总并发最多两个。后台可在执行记录取消，当前网络请求可能需要等待超时结束。

## 两级场景分类（2026-11-03）

场景按“大类 → 具体场景”配置，默认七类、33个具体场景：交通场景、自然环境、生产作业、公共区域、居住商业、室内空间、摄像机位。例如交通场景包含道路、路口、停车场、隧道、桥梁、公交站。管理员可在设备场景设置和图片集设置中添加、改名或删除大类，维护其下具体场景；一个具体场景只能归属一个大类，同一设备仍支持多个具体场景。

模型提示词包含分组信息，输出仍使用具体场景名称。旧标签、原图和人工结果不重写；修改大类归属仅改变组织方式。重命名或删除具体场景后，旧结果保留为历史场景，编辑人工结果时可以保留原有标签，不能新增名单之外的任意标签。

设备、图片库、项目图片与数据复用支持两级选择。按大类筛选时在数据库分页前展开子场景，兼容以前只标“大类名称”的结果；未知大类返回空结果。图片和项目筛选只使用当前租户的全局/图片集规则。已有图片集继续保留各自独立规则，模型地址、提示词和分辨率规则不被本轮默认分类模板覆盖。

发布只新增JSON配置中的 `scene_groups`，既有 `scenes` 保持具体场景名单与旧客户端兼容，不新增数据库迁移。115发布前备份全局设置并应用用户确认的默认分组，不自动启动设备同步、抓图或重新分类。证据见 `docs/testing/scene-hierarchy-2026-11-03.json`。

## 重启与部署

数据库迁移为 `032`，新增三张独立状态表和 `smarteye.platforms.managed` 字段，不移动图片或重写项目资料。降级遇到已有管理数据会拒绝删表。

沿用单后端进程部署。服务重启后保留抓图计划但暂停，需手动启用；未完成执行标记中断，设备分类中状态改为失败并可重试。

115 更新前确认训练、验证、上传、自动处理、模型下发及 SmartEye 任务均无活动，再备份、同步本次文件、按发布包明确的目标迁移版本处理、重启后端并验证。不要在有活动训练时直接重启。图片优先分类、平台统计与两级场景补丁均不新增迁移，保留服务器实际版本。

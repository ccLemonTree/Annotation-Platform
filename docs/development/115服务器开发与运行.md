# 115服务器开发与运行

目标服务器：192.168.1.115，ssh-manager MCP名称`本地测试服务器`。

主目录：`/ai/chen/code/workspace/数据管理平台`。Windows目录保留作迁移回退，以后修改、调试、测试和构建均在服务器进行，不再启动本地前后端。

## 运行方式

- 页面：`http://192.168.1.115:3000`，Vite开发服务，适合当前调试流程。
- API：仅监听`127.0.0.1:18000`，由页面服务转发；115的8000已有向量服务，不占用。
- 服务：`data-platform-backend.service`和`data-platform-frontend.service`，由systemd管理。
- Python：主目录`backend-venv/bin/python`（3.12）；Node：`/usr/bin/node`（22）。依赖均在Linux重建。
- 数据库：继续使用115上的既有PostgreSQL及原账号、租户、标注和审核记录，无导入覆盖。
- 图片、冻结包：`backend/backend/data`；模型归档：其下`model-releases`。
- 私有配置：`backend/backend/.env`、`.runtime/ssh-config.toml`（权限600）。SSH桥接位于`.runtime/ssh-manager`；保留原JWT密钥，既有加密服务器密码可继续解密。

## 常用命令

通过ssh-manager MCP执行，工作目录始终显式设为对应远端目录。

```bash
cd '/ai/chen/code/workspace/数据管理平台'
systemctl status data-platform-backend data-platform-frontend --no-pager
journalctl -u data-platform-backend -n 80 --no-pager
journalctl -u data-platform-frontend -n 80 --no-pager

cd frontend
npm run build
npx oxlint src/pages/DetectionWorkspace.tsx src/api/assets.ts vite.config.ts

cd ../backend/backend
../../backend-venv/bin/python -m pytest tests/test_asset_navigation.py tests/test_annotation_scope.py -q
```

Vite源码修改自动刷新；后端修改后需重启`data-platform-backend`。重启前先确认没有活动训练、验证、上传、自动处理或模型下发；随后验证health和相关登录态接口。不要同时启动第二个后端实例。

## 迁移与回退

校验、安装、构建日志、数据库备份和迁移前业务指纹保存在`.runtime/migration`。本地历史测试缓存、node_modules、Windows虚拟环境、output及旧备份不作为运行依赖迁移，仍保留在Windows原目录。

回退需先停115的两个平台服务，确认业务停止后再在Windows启动旧副本。数据库是同一份，切换后新增文件只在115；回退前必须把新增文件完整同步回本地并校验，不能仅启动旧目录。禁止覆盖或恢复旧数据库快照来回退代码。

迁移验收结果以`docs/testing/2026-10-26-server115-migration.json`为准。

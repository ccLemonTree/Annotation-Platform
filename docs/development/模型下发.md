# 模型下发中心

管理员通过侧栏 **模型下发**（`/model-deployments`）进入独立页面。训练管理中已完成任务的 **归档与下发模型** 链接会带入来源任务。

## 模型版本与批量下发

1. **模型版本库**选择已完成的导出或完整模型，填写产物相对路径、名称、版本及推理类型，点击 **拉取并保存版本**。平台后台拉取一次，核验模型包及全部文件的 SHA256，完成后才能下发。
2. **服务器版本与批量下发**保存目标：模型对应一个仓库/模型槽位，镜像对应明确的容器或 K8s 工作负载。同一服务器可以保存多个模型和服务。SSH 连接来自现有 ssh-manager 配置。
3. 选择归档版本，多选兼容目标并 **创建批量任务**。创建只保存独立记录，不传输、不改变在线服务。
4. 在 **下发与镜像记录**点击 **准备本批次**，或在单条记录执行预检查及传输。模型包从平台本地归档复用，目标仓库外暂存并逐文件校验；完成为 **待生效**。
5. 手动点击 **本批次生效** 或单条 **生效**，确认影响范围后切换。各目标有独立状态、日志和实例结果，部分失败不会显示为整批成功。可重试失败目标或 **恢复旧版本**。

本地指平台后端所在服务器，配置项为 `MODEL_ARCHIVE_PATH`，默认 `backend/backend/data/model-releases/<租户>/<版本ID>/bundle.zip`。记录保存来源任务、版本、完整包 SHA256、大小和归档时间。同一模型名称与版本不可重复；平台不会自动删除旧包，引用版本的训练任务不能删除。

服务器台账显示已记录版本、核验时间及最近操作；**读取当前版本**会只读核对服务器。平台管理的模型通过发布标记及逐文件 SHA256 映射回版本；原有未纳管模型显示未纳管，不猜测版本。历史核验记录不代表持续实时监控。

## 来源及推理方式

| 来源 | 推理方式 | 下发结果 |
|---|---|---|
| 已完成 TensorRT 导出中的 `.engine` / `.plan` | 小模型 Triton | `<仓库>/<模型名>/config.pbtxt` 和 `1/model.plan` |
| Swift 完整训练或 LoRA 合并目录 | 大模型 Triton vLLM backend | `config.pbtxt`、`1/model.json` 和 `1/model/` 完整权重 |
| WeMM 完整训练或 LoRA 合并目录 | 原生 vLLM 向量 | `<仓库>/<目标目录名>/` 完整 HF 权重与 tokenizer |

完整目录必须含 `config.json`、权重及 tokenizer，索引中的所有权重分片须存在，不能含 adapter 配置或符号链接。产物路径相对于来源任务的输出子目录，不接受任意主机文件路径。小模型预检查还核对构建与推理 GPU 名称、TensorRT 运行库版本。

Triton 配置留空时沿用目标现有配置；首次下发生成最小配置。输入输出、batch、实例与 GPU 参数应适配实际模型。大模型 `model.json` 留空时沿用目标参数，模型路径根据真实容器挂载生成。

小模型生效逐实例调用 Triton Load API；大模型及向量重启所选 Docker 推理容器或滚动重启指定 K8s 工作负载，先释放旧进程显存，再等待冷启动。只在全部指定实例核验通过后记录生效。恢复保留的旧目录后重新加载/重启；旧记录不能覆盖更新的发布。

## SSH调试与实时日志

页面上方“SSH调试服务器”可选择ssh-manager中的服务器；目标行及详情也提供控制服务器、模型文件服务器的专用链接。链接仅选中目标，点击“连接终端”后才建立会话；沿用现有管理员鉴权、每用户2会话/全平台8会话、20分钟无输入断开、Ctrl+C和退出清理。目标地址或SSH账号变化会断开会话。

目标行“实时日志”和记录详情支持“更新过程日志 / 服务运行日志”。更新过程显示该记录的阶段日志，并读取Docker镜像拉取或本次K8s Ansible预分发的最新输出；服务运行日志读取目标容器或工作负载所属Pod，可切换实例，覆盖Triton、vLLM、NexusAI HTTP及Kafka worker。目标入口查看最新记录；历史记录入口保持自己的下发范围。

每次请求完成后等待2秒再刷新，可暂停、手动刷新和切换实例，关闭面板即取消请求。失败保留最后一次内容并显示错误，不假报最新；最多显示64KiB，服务日志最近200行，截断有提示。仅读取后端派生的日志路径和实例，拒绝任意路径/命令、目录符号链接，常见凭据及令牌脱敏，不会创建下发任务、拉镜像或重启服务。无日志可能表示尚未开始、此阶段无输出或实例已退出；通过SSH核对现场。

## 多服务器更新镜像

镜像目标支持 Triton、vLLM、NexusAI HTTP 和 Kafka worker。选择 **镜像更新**，输入明确的版本 tag 或 `@sha256:` 引用，多选目标后创建批次。**准备**与**生效**分开，准备完成不会更新在线服务。

### K8s：先通过本环境 Ansible 预分发

每个环境使用自己的 `preload-ai-images.yml`。默认从控制机 `/opt/*/ansible/preload-ai-images.yml` 唯一定位，也可以在目标配置填写剧本和 inventory 的绝对路径。清单必须覆盖该集群全部实时节点；自动发现会检查环境目录及预分发日志目录中的候选清单，缺节点时阻断。

1. 复用现有剧本的四段 Triton 镜像流水线，显式替换为本次所选服务镜像；不执行剧本中无关的 GME 镜像任务。
2. 先检查节点连接与 containerd，再由控制机拉取一次并导出镜像包。
3. Ansible 以4台一批分发、导入 `containerd` 的 `k8s.io` namespace，核对每个节点的镜像包 SHA256、镜像摘要和节点身份。同一批次、同一环境的多个目标复用成功的分发结果。
4. 全部节点通过后才进入待生效。手动生效前再次检查节点名单及缓存摘要，随后仅修改所选工作负载容器的镜像、发布标记和 `imagePullPolicy: Never`，使用不可变的镜像摘要引用。
5. 等待全部副本就绪、更新数量与目标一致、StatefulSet revision 收敛，并核验实际运行镜像ID。任何缺失或部分完成都不会记为成功。

节点缺图时会报错，不会临时触发所有节点回源拉取。新增节点、清理镜像缓存或恢复已被清理的旧镜像时，须先补齐预分发。恢复使用原镜像及本地缓存策略，原镜像不可自动删除。

仓库认证复用控制机的 containerd 配置及所选工作负载的 `imagePullSecrets`，敏感信息仅存控制机私有操作目录，不写入浏览器、命令参数或操作日志。镜像与模型操作共享服务互斥，同一工作负载或容器有未完成变更时阻止另一更新。

实现依据：[Ansible forks 与 serial](https://docs.ansible.com/projects/ansible/latest/playbook_guide/playbooks_strategies.html)、[Kubernetes 镜像拉取策略](https://kubernetes.io/docs/concepts/containers/images/#image-pull-policy)。

### Docker / Docker Kafka

准备阶段后台拉取目标镜像、保留原配置及旧镜像ID；手动生效时只更新所选服务。已有 Compose 服务通过原项目配置与私有镜像覆盖文件重建，配置与当前容器不一致时阻断。原生 Docker 通过本机 Unix socket 保留 GPU、端口、环境变量、挂载及网络配置，旧实例停止后保留，恢复时保留撤下的新实例及其数据。

逐容器检查运行镜像ID及健康状态；没有 healthcheck 的容器会明确显示仅核验运行状态和镜像ID。模型下发不修改 Kafka topic、消费组或业务路由；镜像更新可以重建明确选择的 Kafka worker。

## 持久化、恢复与限制

- 迁移024创建下发记录，025增加模型版本、目标配置、批次关联及操作租约。记录保留租户隔离，不占用训练 GPU 配额。单批最多50个目标，同时执行最多2个目标，归档一次执行1个。
- 首版要求单后端进程。应用重启后，未完成发布变为 **状态待核对**、归档变为中断；不会自动重放加载/重启。先只读核对，再人工继续原任务或恢复。服务租约在状态不明时保留，防止另一发布覆盖现场。
- 旧包、旧模型目录、容器配置和远端操作日志保留，不自动清理。需预留本地归档、目标暂存及备份空间；新增节点与旧镜像缓存需由运维保持完整。
- 模型暂存与在线仓库须在同一文件系统，仓库须为挂载点内的子目录；不接受仓库自身为文件系统根挂载点。
- K8s 支持明确 NFS/PVC 挂载及 StatefulSet/Deployment，要求完整 RollingUpdate，拒绝 OnDelete、partition 或暂停状态。预分发要求现有剧本包含四段明确的 Triton 流程及覆盖全部节点的有效清单。
- Docker 模型下发要求显式 bind mount 和模型启动路径。原生镜像更新要求本机 Unix socket，不支持自动删除或共享其他容器 namespace 的容器。Compose 配置须可恢复且未漂移。
- Triton 要求 explicit 模式；大模型启动参数须加载目标模型或 `*`。原生 vLLM 核对 `/v1/models` 的 served model。Docker 冷启动核验至少20分钟；K8s 至少20分钟并按副本数预留每副本10分钟窗口。后台操作可关闭页面后继续查看。
- 版本核验、健康检查和就绪检查不能代替业务样本推理验收。本轮真实远端仅盘点和语法检查，未执行生产模型传输、Ansible 镜像分发、加载或重启。完整记录见[下发中心验收](../testing/model-distribution-center-2026-10-24.json)。

模型协议依据：[Triton 模型仓库管理](https://docs.nvidia.com/deeplearning/triton-inference-server/user-guide/docs/protocol/extension_model_repository.html)、[vLLM 向量接口](https://docs.vllm.ai/en/latest/models/pooling_models/embed/)。

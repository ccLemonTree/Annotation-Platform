# 外部图片上传接口

外部服务使用项目上传密钥提交原图或已裁剪图片。密钥只对指定项目的上传接口有效。请使用外部服务可访问的平台地址，在经过不可信网络时使用 HTTPS。

## 创建上传密钥

平台管理员使用 `POST /api/auth/login` 登录返回的 `access_token` 调用以下接口。登录请求使用 `application/x-www-form-urlencoded`，字段为 `username` 和 `password`。

```bash
curl --fail-with-body "$PLATFORM_URL/api/projects/$PROJECT_ID/upload-keys" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"name":"外部采集服务","expires_in_days":90}'
```

成功返回 `201`，包含 `id`、`name`、`created_at`、`expires_at` 和 `token`。`token` 仅在创建时返回，将它保存到外部服务的密钥配置。有效期默认 90 天，可设为 1 至 365 天。

- `GET /api/projects/{project_id}/upload-keys` 列出密钥及到期时间。
- `DELETE /api/projects/{project_id}/upload-keys/{key_id}` 撤销密钥。

## 上传图片

```bash
curl --fail-with-body "$PLATFORM_URL/api/projects/$PROJECT_ID/ingest/images" \
  -H "Authorization: Bearer $PROJECT_UPLOAD_KEY" \
  -F 'image_kind=originals' \
  -F 'files=@frame-001.jpg' \
  -F 'files=@frame-002.png'
```

使用 `multipart/form-data`。每次提交 1 至 16 张 JPG、PNG、BMP 或 WebP 图片，单张大小受平台上传限制。`image_kind` 默认 `originals`，上传已裁剪图片时填 `crops`。原图使用项目同名图片集的长边限制，裁剪图默认无长边下限。

成功返回 `201`。

```json
{
  "asset_ids": ["a43d6c63-9c98-48de-9348-a95b906a78d9", "9c0a35cb-88e7-4485-a67f-c23e98931479"],
  "added_count": 2,
  "duplicate_count": 0,
  "queued_count": 2,
  "queue_warning": null
}
```

`asset_ids` 与上传文件的顺序一致。同一项目内以图片内容去重，重复上传返回已有资产 ID，可在请求超时后重试。`queued_count` 是本次自动入队的新增图片数，取决于项目是否开启「自动加入新上传及抓图」以及工作流输入类型。

常见错误码

| HTTP 状态 | 含义 |
| --- | --- |
| `400` | 图片无效、损坏或格式不支持 |
| `401` | 密钥缺失、无效、过期或不属于该项目 |
| `409` | 图片在其他项目中尚未审核通过，当前项目无法关联 |
| `413` | 图片超过单张大小限制 |
| `422` | 文件数量、图片类型或尺寸不符合要求 |

## 直接上传压缩包

使用同一个项目上传密钥，向 `POST /api/projects/{project_id}/ingest/archives` 发送压缩包的二进制内容。`filename` 用于选择解包格式，支持 `.zip`、`.tar`、`.tar.gz` 和 `.tgz`。文件名中的空格等字符需 URL 编码。

```bash
curl --fail-with-body \
  "$PLATFORM_URL/api/projects/$PROJECT_ID/ingest/archives?filename=frames.zip&image_kind=originals" \
  -H "Authorization: Bearer $PROJECT_UPLOAD_KEY" \
  -H 'Content-Type: application/octet-stream' \
  --data-binary '@frames.zip'
```

完整接收后返回 `202`、任务 `id` 和 `Location` 响应头。使用同一项目的有效上传密钥查询进度。

```bash
curl --fail-with-body "$PLATFORM_URL/api/projects/$PROJECT_ID/ingest/archives/$JOB_ID" \
  -H "Authorization: Bearer $PROJECT_UPLOAD_KEY"
```

`status` 为 `pending`、`processing`、`completed` 或 `failed`。平台会递归读取包内图片，自动关联 URL 指定的项目。开启自动接收的工作流会按输入类型接收符合条件的新增图片。`result.added_count`、`result.project_duplicates`、`result.project_conflicts` 和 `result.queued_count` 分别表示新增、已有、项目关联冲突和自动入队数量。非图片文件会被忽略，非法归档路径、链接或超出展开限制的压缩包会被拒绝。

此接口为单请求上传。传输中断时请重新提交，项目图片按内容去重。上传和展开大小以及条目数使用平台现有的压缩包限制。

## 给已入库图片补传 YOLO 标签

目标检测项目使用 `POST /api/projects/{project_id}/ingest/yolo-labels`。用同一项目密钥鉴权，发送 `multipart/form-data`。文件夹内的 TXT 每次提交 1 至 16 个。可选字段 `classes` 接受 `data.yaml`（含 `names`）、`data.yml` 或 `classes.txt`。

```bash
curl --fail-with-body "$PLATFORM_URL/api/projects/$PROJECT_ID/ingest/yolo-labels" \
  -H "Authorization: Bearer $PROJECT_UPLOAD_KEY" \
  -F 'files=@labels/frame01.txt' \
  -F 'files=@labels/frame02.txt'
```

Linux 可用下面的命令递归读取标签文件夹，按每批最多 16 个 TXT 发送。

```bash
find labels -type f -iname '*.txt' ! -iname 'classes.txt' -print0 |
  xargs -0 -r -n 16 bash -c '
    url=$1
    key=$2
    shift 2
    args=()
    for file do args+=(-F "files=@\"$file\""); done
    curl --fail-with-body "$url" -H "Authorization: Bearer $key" "${args[@]}"
  ' _ "$PLATFORM_URL/api/projects/$PROJECT_ID/ingest/yolo-labels" "$PROJECT_UPLOAD_KEY"
```

也可提交只含标签的 ZIP。标签可放在任意子目录，类别表可以放在包内，或随请求另传 `classes`。

```bash
curl --fail-with-body "$PLATFORM_URL/api/projects/$PROJECT_ID/ingest/yolo-labels" \
  -H "Authorization: Bearer $PROJECT_UPLOAD_KEY" \
  -F 'archive=@labels.zip'
```

TXT 与图片按不含扩展名的文件名匹配，忽略大小写。重名图片或重名标签会报告冲突。每行使用 `class x_center y_center width height`，坐标为归一化值。空 TXT 明确表示负样本。新标注进入待审核，已有标注保留。提供类别表时，项目无类别且无标注则带入类别表。省略类别表时，框保留原始 YOLO 编号，可在标注页为每个框选择项目类别。图片上的框都设好类别后才可审核通过或纳入检测训练导出。

响应 `items` 按文件报告 `imported`、`unchanged`、`conflict`、`missing` 或 `invalid`，有对应图片时返回 `asset_id`。标签 ZIP 请求在处理完成后返回。传输中断可重试，相同标注会返回 `unchanged`。

# 数据管理与模型生产线：需求细化 v0.2

日期：2026-09-30  
用途：需求讨论、范围确认和后续验收准备。

本文依据本次对话整理。用户明确的功能与流程推演补充项分别标记；验收描述是便于讨论的草案，不表示指标已经定稿。案例数字仅用于纸面模拟，未实际执行训练、数据导入或生产发布。本文不选择数据库、前后端技术或调度组件的实现方案。

## 1. 当前范围与变化

| 项目 | 当前需求 |
|---|---|
| 使用环境 | 公司内部使用，最初约两名用户；本次新增多租户。租户数量、成员数量及租户含义待定。 |
| 数据规模 | 沿用最多约20万张图片、每算法约1万张、非每日持续新增的基线。20万是全平台还是每租户上限需随多租户确认。 |
| 数据来源 | SmartEye（http://192.168.1.115:5000/）和用户上传；实际原图及接口契约待确认。 |
| 生产线关系 | YOLO检测、大模型图片描述、向量模型图片描述独立；同一原图可进入多条生产线。检测切图后再描述是可选路径。 |
| 人工工作 | 模型预标注后人工修改确认；本次新增复核流程及工作量统计。是否每条都必须第二人复核待定。 |
| 模型种类 | YOLO类检测模型、图片描述大模型、向量模型；新增DINOv3相关自监督训练和百张内快速微调。 |
| 向量用途 | 支持向量模型训练、批量生成测试向量、文字搜图、以图搜图。检索同时考虑外观与语义，二者分别评价。 |
| 平台终点 | 模型测试、版本记录、下发和回退。生成向量仅测试使用，线上推理效果监控不在本期范围。 |
| 资源使用 | 内部集群、多节点算力和外接算力；新增动态释放与SSH调试窗口。 |
| 开发接入 | 标注数据统一表达，自定义导出模板，标准化训练接入规则。 |

多租户使原先“完全不需要权限管理”的范围发生变化。需求层至少需要租户身份、成员归属和租户间隔离，复杂岗位角色、审批链和计费不在本次默认假设内。跨租户共享必须明确授权。

## 2. 从用户工作出发的完整流程

选择租户和项目 → 导入图片 → 设备/场景分类与质量评分 → 筛选并组成候选数据集 → 选择独立标注任务 → 模型预标注 → 人工修改、确认及复核 → 固定数据集版本 → 选择标签和导出模板 → 交付训练服务器 → 发起训练 → 查看日志、指标和产物 → 独立测试及版本比较 → 下发模型或回退。

向量分支在测试阶段增加“批量生成向量和检索评测”；DINOv3分支增加“无标注训练/蒸馏、少样本下游微调”的明确方法选择。它们的任务、数据和模型版本均独立记录。

## 3. 细化需求表

“沿用”与“新增”表示用户已提出功能；“推演补充”表示从流程中发现的建议，仍待确认。所有验收口径中的阈值、时间和支持名单都需后续定稿。

### 3.1 数据接入、分类与筛选

| 编号 | 需求 | 来源 | 验收口径草案 |
|---|---|---|---|
| D01 | SmartEye接入和用户批量上传。 | 沿用 | 导入结果显示成功、失败、重复数量；图片可预览，来源可追溯。 |
| D02 | 按租户、项目、来源、设备、日期和图片类型管理；设备未知时可为空或人工补充。 | 沿用+新增 | 拍摄时间与入库时间可区分；用户上传图片不强制伪造设备信息。日期筛选采用哪个字段待定。 |
| D03 | 设备场景分类：对有设备来源的图片识别设备所处场景，并支持人工修改。 | 新增 | 场景类别可配置；无法判断有独立状态；设备场景变化可按时间保留记录。区分设备场景标签与单张图片内容标签。 |
| D04 | 图像质量打分，辅助初步筛选。 | 新增；切图评价为补充 | 展示总分及原因；可按质量筛选和排序。原图和切图分别评价，切图不直接继承原图总分。清晰度、曝光、遮挡、分辨率等维度及分值范围待定。记录评分模型/规则版本。 |
| D05 | 质量筛选与任务适用性分别判断，保留困难样本入口。 | 推演补充 | 夜间、模糊、遮挡、小目标等不能仅凭低质量分自动删除；能为特定任务保留一定比例。 |
| D06 | 图片去重和近重复关系管理。 | 沿用；近重复为补充 | 给出重复依据；重复判定口径待定。默认建议标记和分组，再由人决定保留。跨租户去重不得泄露另一租户的数据存在情况。 |
| D07 | 组合筛选、批量选择、保存筛选条件，并统计类别/设备/场景分布。 | 沿用+推演补充 | 可按日期、设备、类型、质量、标签和标注状态组合筛选；自定义业务字段不固定写死。筛选结果与最终数据集名单有区别。 |
| D08 | 导入中断后补录，源图片地址失效、源数据更新和删除可识别。 | 推演补充 | 重试不重复创建同一数据；坏图和不可访问图片有失败清单，不被当作可训练样本。 |

### 3.2 标注与语义预标注

| 编号 | 需求 | 来源 | 验收口径草案 |
|---|---|---|---|
| A01 | YOLO类框与类别标注；大模型和向量任务分别进行图片描述。 | 沿用 | 三条任务独立维护标注、规则、状态和版本；共享原图不自动共享标注。 |
| A02 | 支持整图描述、检测后切图描述。 | 沿用 | 切图关联原图、框、检测结果版本与切图规则；框修改后旧切图可识别为旧版本。描述与实际使用的图一致。 |
| A03 | 语义理解预标注：输入“框出穿红色衣服的人”等自然语言要求，产生可编辑目标框。 | 新增 | 能处理多个匹配、无匹配、含糊指令和失败；结果回到原图坐标，不能把一段文字回答直接视为检测标注。 |
| A04 | 语义定位结果分别用于小模型标注、目标切图、向量任务的目标区域与描述。 | 新增 | 保留指令、模型版本、类别和属性解释；“人+红色衣服属性”与“红衣人类别”由任务标签规则决定。 |
| A05 | 模型先生成结果，人工修改确认；支持批量预标注和小批试跑。 | 沿用+推演补充 | 可增加、删除、移动框或修改描述；小批检查后再整批运行。重跑不覆盖已人工修改/确认的数据。 |
| A06 | 标注数据采用统一表达，保存框、类别、属性、图片描述、来源和状态。 | 新增 | 坐标约定明确；检测框、图片描述等保留各自类型，不强行转成同一种标注。各导出格式由模板转换。 |
| A07 | 管理标签表和标注规则版本，支持任务自定义类别与属性。 | 推演补充 | 同名标签可区分语义；类别重命名、合并、拆分后历史版本仍可追溯。 |
| A08 | 区分未标注、预标注、人工确认、待复核、通过、退回、无目标和无效样本。 | 推演补充 | 模型无输出不自动成为真负样本；未经确认的伪标签与人工通过样本分开统计。是否允许伪标签参与训练由明确规则决定。 |
| A09 | 标注复核、退回与修改记录；两人同时修改可发现冲突。 | 新增+推演补充 | 记录本次复核的具体标注版本；改动已通过结果时需重新确认或复核。复核是否必须第二人完成待定。 |
| A10 | 高效人工操作：快捷键、上一个/下一个、批量确认、自动保存与撤销。 | 推演补充 | 编辑结果不因切换页面丢失；批量操作前能确认范围；模型低置信或错误样例可优先处理。 |
| A11 | 独立任务间可选择复用已审核描述或框。 | 推演补充 | 引用/复制来源及版本可见，目标任务可独立修订；一方修改不悄悄改变另一方已冻结的数据集。 |

### 3.3 数据集、标签选择与导出

| 编号 | 需求 | 来源 | 验收口径草案 |
|---|---|---|---|
| E01 | 导出数据集时选择标签。 | 新增 | 支持选全部或部分标签；导出前预览图片数、目标数、描述数和标签分布。 |
| E02 | 预设格式和自定义导出模板。 | 新增 | 模板可定义字段映射、类别编号、目录结构、坐标表达、图片路径和描述形式，并可预览、校验和保存版本。支持格式名单待定。 |
| E03 | 选择部分标签后的语义与空标注处理明确。 | 推演补充 | 原类别编号与导出编号映射固定并一致用于各数据划分；区分真正负样本、被过滤为空和未完成标注。 |
| E04 | 固定训练/验证/测试数据集版本，保留图片与标注清单。 | 推演补充 | 同一原图、切图和近重复组不跨训练与独立测试集合。重新导出同一版本能重现同一内容。分组方式可按设备/场景等决定。 |
| E05 | 数据直接交付训练服务器；可选择目标和数据集版本。 | 沿用 | 用户不必本地下载再上传；显示传输进度、目标端验收结果及失败清单；重试不产生混乱版本。 |
| E06 | 对数据删除、标签变更、模板改版的影响可追溯。 | 推演补充 | 可查受影响任务和数据集；不静默改变正在训练或历史模型对应的数据。物理删除和保留规则待定。 |

部分标签导出至少要明确以下策略：排除非选中框但保留图片、排除包含非选中类别的图片，或将非选中区域标为忽略（仅目标训练格式支持时）。哪种策略正确取决于任务定义，不应统一默认为背景。图片描述的标签筛选是筛选记录或对应区域，不能随意删掉描述中的词后宣称标注仍正确。

### 3.4 标准化训练与DINOv3

| 编号 | 需求 | 来源 | 验收口径草案 |
|---|---|---|---|
| T01 | 从平台发起训练，展示排队、准备数据、运行、产物保存、完成和失败。 | 沿用 | 进度单位按模型显示epoch/step；无法估计百分比时不显示虚假百分比。 |
| T02 | 新模型训练可按标准规则接入。 | 新增 | 声明任务类型、输入格式、参数、基础权重、算力需求、进度/指标、模型产物、评测和导出能力；接入后能使用通用页面。 |
| T03 | 训练方法按能力展示，支持模型参数模板与版本记录。 | 新增+推演补充 | YOLO、图片描述大模型、图文向量模型和DINOv3任务保持不同输入/训练方法；不承诺每个模型都能暂停、续训或所有格式导出。 |
| T04 | 保存数据集、标签表、模板、代码/环境、基础权重、参数与训练结果的关联。 | 沿用+推演补充 | 能回答一个模型由什么数据和配置训练；best、last与用于发布的权重可区分。 |
| T05 | DINOv3相关自监督模型训练：使用无人工标注图片开展视觉表征学习。 | 新增，方法待确认 | 明确原生DINOv3自监督预训练/继续训练与教师蒸馏的区别，分别记录方法。不能用蒸馏任务悄悄代替用户要求的原生方法。 |
| T06 | DINOv3百张内快速微调，用于模型前期迭代。 | 新增，口径待确认 | 在已确认的小样本和预训练权重上发起下游任务训练，保存学习曲线、结果样例和耗时；“百张内”是总量还是每类、训练量还是含测试量待定。 |
| T07 | 小样本结果可与基础模型和后续数据版本比较。 | 推演补充 | 独立测试样本不参与训练或调参；低样本、缺类别和过拟合风险可从数据及指标看到。百张是可运行规模，不是效果保证。 |
| T08 | 新模型接入需完成最小任务验证。 | 推演补充 | 小数据集训练、指标展示、权重保存、离线加载测试、停止/失败处理和释放检查通过后，声明已接入的具体能力。 |
| T09 | 可停止、重试和按模型能力恢复训练。 | 推演补充 | SSH断开不等于任务取消；取消/恢复有明确状态，失败原因可查。 |
| T10 | DeepSeek基于已保存的训练/测试记录生成分析报表。 | 沿用 | 报表关联实验及数据版本，结论能对应原始指标和样例；失败或缺数据时不编造结果。 |

训练标准化要求统一的是“如何接入、控制、观察和取得产物”。各模型的损失函数、优化器、数据结构和训练脚本保留差异。本次不指定框架代码结构。

### 3.5 向量测试和模型验证

| 编号 | 需求 | 来源 | 验收口径草案 |
|---|---|---|---|
| V01 | 训练向量模型，并对指定测试数据批量生成向量。 | 沿用 | 记录模型版本、源数据版本、预处理、向量维度及生成进度；失败样本可追查。 |
| V02 | 文字搜图、以图搜图，覆盖外观相似和内容语义相关。 | 沿用 | 有独立查询与期望结果；外观与语义分别报告，避免一种高分掩盖另一种失效。 |
| V03 | 用统一测试集比较多个向量模型。 | 推演补充 | 查询、检索图库和评价条件固定；能观察排序结果、错误案例和检索指标，原图/切图结果可关联查看。 |
| V04 | 检测模型、图片描述模型、向量模型分别定义离线测试要求。 | 沿用+推演补充 | 检测看漏检/误检和分类，描述看事实与要求符合度，检索看相关结果及排序。具体阈值由业务确认。 |
| V05 | 测试向量与生产发布分开，按实验保存或清理。 | 沿用+推演补充 | 仅发布模型；清理测试向量不影响模型权重、测试报告和必要来源记录。保存期限待定。 |

DINOv3视觉特征可研究用于视觉相似，但不能因为它输出向量，就认为其具备文字搜图能力。文字搜图涉及图文对齐，应独立声明和验证。

### 3.6 外接算力、动态释放与调试

| 编号 | 需求 | 来源 | 验收口径草案 |
|---|---|---|---|
| C01 | 外接算力：连接已有服务器/集群和已有模型推理服务。 | 新增+沿用 | 可查看连接状态、资源能力、当前任务和归属；K8s管理多节点任务，SSH用于外接服务器连接或调试。具体支持方式待定。 |
| C02 | 分配、排队和展示算力占用，资源不足时可见原因。 | 推演补充 | GPU、显存等能力与任务匹配；租户不会同时抢占同一专属资源；资源是否可共享需声明。 |
| C03 | 动态加载/卸载预标注、分类或评分模型。 | 新增细化 | 忙碌模型不因空闲策略卸载；卸载后显存实际释放可确认，模型文件与结果保留。 |
| C04 | 任务结束、失败或取消后释放任务占用的算力。 | 新增细化 | 只释放平台管理的任务资源；共享机器上的其他任务不受影响。外部API只能停止请求时，不能声称已释放服务商显存。 |
| C05 | 释放前保全必要产物，释放状态可确认。 | 推演补充 | 权重、日志和指标保存后再清理临时资源；归档失败、释放失败和网络状态不明独立显示，不误报完成。 |
| C06 | 平台内SSH远程窗口用于调试。 | 新增 | 入口关联租户和算力目标；可查看任务日志和文件。窗口关闭不隐式取消训练。主机级还是任务容器级访问待定。 |
| C07 | 定义空闲保留、手动保留调试与自动释放规则。 | 推演补充 | 调试保留状态可见、有截止条件；预标注任务、训练任务和调试会话同时使用资源时避免误释放。 |

释放“模型显存”“任务GPU占用”“租用服务器实例”是三个不同范围。当前默认理解是释放平台管理的模型和任务占用；是否需要自动停机、退租或销毁实例尚未确认。K8s调度不能作为网络影响被消除的验收口径，数据传输和断线恢复仍需独立验收。

### 3.7 人工进度、效率与多租户

| 编号 | 需求 | 来源 | 验收口径草案 |
|---|---|---|---|
| H01 | 展示人工标注、确认、复核和返工进度。 | 新增 | 按租户、项目、任务和人员查看待处理、已完成、已通过、退回数量；图片数、框数、描述数分别统计。 |
| H02 | 展示标注速度和复核速度。 | 新增 | 说明使用工作时长还是自然时长，剔除长时间停留造成的误差；预标注量不计作人工新增工作量。 |

| M01 | 多租户数据和工作范围隔离。 | 新增 | 原图、标签、模板、标注、数据集、模型、日志、向量测试、算力凭据和发布目标均有租户归属。 |
| M02 | 跨租户共享规则。 | 推演补充 | 仅明确共享的资产可访问；原始数据去重或共用底层文件不能绕过业务隔离。修改和删除不得破坏其他租户已合法使用的数据。 |
| M03 | 租户资源额度和访问边界。 | 新增细化+推演补充 | 基本成员归属可判定；SSH不能绕过租户隔离；并发算力/存储额度可识别。角色数量、管理员行为和共享服务范围待确认。 |

### 3.8 发布、数据可靠性和性能

| 编号 | 需求 | 来源 | 验收口径草案 |
|---|---|---|---|
| P01 | 发布训练好的模型，记录目标和交付结果。 | 沿用 | 区分发送、接收、激活已确认等状态。目标无法回传生效信息时只能记录待确认，不能据传输完成判定线上效果。 |
| P02 | 按目标回退到已有模型版本。 | 沿用 | 回退包包含必要标签映射、预处理和推理配置；回退结果可记录。不同目标当前版本独立维护。 |
| P03 | 平台范围到下发与回退，生成向量仅作测试。 | 沿用 | 不要求查看线上推理业务效果；保存模型、交付记录和回退依据。 |
| O01 | 数据与模型保存、备份和删除恢复规则。 | 推演补充 | 删除有明确范围；计算资源释放不删除必要数据；保留多久及可恢复范围待定。 |
| O02 | 20万张规模下的浏览、筛选、标注保存和批任务交互。 | 沿用规模+推演补充 | 列表不一次加载全部图片；批处理进度可见。交互响应、并发任务、存储容量和恢复目标数值待定。 |
| O03 | 标准化接入文档及模型能力清单。 | 新增细化 | 新模型接入方法、输入/输出、支持环境、错误状态和维护责任清楚；避免仅有训练脚本而无法在平台完整使用。 |

## 4. 六个用户场景的纸面模拟

### 场景一：从设备图片中挑出优质但有代表性的首批数据

假设某租户导入1万张设备图片，希望先训练一个检测算法。

1. 选择来源、设备和时间范围，导入完成后查看成功、坏图与重复组。
2. 自动设备场景分类、图片质量评分；人工检查少量样例并调整明显错误。
3. 用户按场景、时间、质量筛选，同时保留夜间、遮挡及小目标样本。
4. 查看场景和设备分布，冻结首批候选图片名单，然后进入预标注。

模拟发现：同一设备可能换场景；高质量样本不必然覆盖真实难例；选择日期字段会改变筛选结果。补充D02—D08，不能仅靠总质量分决定训练价值。

### 场景二：“框出穿红色衣服的人”，同时用于小模型和向量任务

1. 新建语义预标注任务，指定目标指令、标签定义和模型。
2. 先对少量图试跑，检查多个人、红色物体但非衣服、背面/遮挡及无匹配图片。
3. 人工修正目标框，确认类别/属性语义；需要复核时交由复核流程。
4. 检测任务把确认的框用于训练；向量任务可选择引用确认版本、切图并独立生成/修正描述。
5. 修改原框后提示旧切图来源已变化，重新生成产生新版本。

模拟发现：“红衣人”可以是专用类别，也可以是“人”的属性；没有返回框不代表真负样本；描述原图与描述切图范围不同；原图清晰但切图过小也可能无法用于描述。补充D04、A03—A09、A11，保留生产线独立。

### 场景三：用百张内标注尽快验证新算法

假设已有DINOv3预训练权重、80张已确认训练图片，以及独立的验证/测试样例；百张是否包含验证集待定。

1. 指定下游任务、基础权重和小样本数据集；检查类别缺失和数据重复。
2. 选择快速微调任务并记录参数与算力预算；平台发起训练并观察曲线。
3. 在独立测试样例上比较基础模型与微调模型，查看漏检、误检和失败场景。
4. 用候选模型给下一批数据预标注，人工确认后增加数据形成下一轮实验。
5. 若另有未标注图片，可另建自监督/蒸馏任务，记录实际采用方法，不与少样本微调混为同一次任务。

模拟发现：80张相邻帧可能只有几个独立场景；训练集上效果好不等于泛化；未标注领域适应与百张标注下游训练是不同目标。补充E04、T05—T07。不保证百张必然得到可上线模型。

### 场景四：只导出“人”和“车辆”，适配另一训练格式

1. 从已确认标注中选定两类标签及数据集版本。
2. 查看筛选后的图片、目标数，查看被过滤为空的图片和真负样本数量。
3. 选择模板，检查字段、坐标、类别编号以及图片路径预览。
4. 明确非选中标签的处理策略，校验训练/验证/测试划分的一致性。
5. 导出并直接交付训练服务器，保存模板版本、标签映射和目标端结果。

模拟发现：过滤标签可能使图片变成空标注；训练格式的忽略区能力不同；同一描述中多个目标不适合机械删词。补充E01—E06。

### 场景五：两个租户同时使用外接算力，其中一人开启SSH调试

1. 两个租户各自选择任务数据和算力；平台显示专属或共享资源，以及排队原因。
2. 租户A跑预标注并准备训练，租户B运行另一任务；模型加载和任务占用分别记录。
3. A开启其目标的SSH窗口，断开浏览器后训练继续。
4. A任务结束，先保存模型、日志和指标；只清理A对应的进程和资源。
5. 若B仍调用共享模型，模型继续保留；若网络失联，释放状态保持未知/待确认。
6. 调试需要延长保留时，按明确规则记录；任务结果不会因释放临时算力而丢失。

模拟发现：关闭窗口、停止任务、卸载模型和释放机器不能互相等同；共享服务器SSH可能绕过数据隔离。补充C02—C07、M01—M03、O01。

### 场景六：比较候选模型，发布模型并回退

1. 将候选与旧模型放在同一固定测试集上对比。
2. 向量模型分别测试文字、图片查询，区分外观与语义样例；描述模型和检测模型使用各自验证要求。
3. 保存指标、样例、报告和模型版本；用户选定模型及发布目标。
4. 交付模型及必要配套信息，记录目标回执能确认到哪一步。
5. 回退时选择该目标上一次已知版本，保留操作结果。
6. 测试向量独立保留/清理；生产发布物仅模型及其必要配套文件。

模拟发现：下发完成不表示线上效果已验证；只有权重没有标签表可能无法恢复旧行为；新旧模型不能在不同测试条件下简单比较。补充T04、V03—V05、P01—P03。

## 5. 参考项目调研结论

调研日期：2026-09-30。以下为公开文档核查，不是安装或实际运行验证。

### X-AnyLabeling

官方仓库展示了AI辅助标注、批量预测、本地/远程推理、图像描述、Grounding及多格式导入导出能力，适合参考预标注交互和人工修正流程。它的主体是桌面标注应用，不能据此认为已经覆盖本平台的多租户、训练管理、统计和模型发布需求。[官方仓库](https://github.com/CVHub520/X-AnyLabeling)

Rex-Omni示例记录了文本提示检测、描述定位和可批处理任务；同时视觉示例提示有批处理限制。因此，本平台应对每个预标注模型声明“支持哪些输入、输出和批任务”，不默认所有模型具备相同能力。[Rex-Omni示例](https://github.com/CVHub520/X-AnyLabeling/blob/main/examples/vision_language/rexomni/README.md)

用户指南包含多种格式转换及部分标签筛选的例子。能借鉴字段和标签映射，但自定义模板、负样本策略和导出数据版本仍是本平台独立需求。[导入导出指南](https://github.com/CVHub520/X-AnyLabeling/blob/main/docs/en/user_guide.md)

其远程服务和自定义模型文档还可参考模型接入、预测结果表达和卸载能力声明。[远程服务](https://github.com/CVHub520/X-AnyLabeling-Server)、[自定义模型指南](https://github.com/CVHub520/X-AnyLabeling/blob/main/docs/en/custom_model.md)

### LightlyTrain与DINOv3

当前官方支持矩阵列出了DINOv3的下游微调和蒸馏；原生自监督预训练与蒸馏不能仅因都使用未标注数据而混称。依据当前文档，不能直接把LightlyTrain对DINOv3的支持当作原生DINOv3自监督训练已经满足。[LightlyTrain支持矩阵](https://docs.lightly.ai/train/stable/)、[蒸馏文档](https://docs.lightly.ai/train/stable/pretrain_distill/methods/distillation.html)

DINOv3相关目标检测和图像分类微调有官方文档；它们能作为快速迭代能力参考。文档支持训练功能，不等于对用户特定算法保证100张样本的质量、耗时或上线效果。[目标检测](https://docs.lightly.ai/train/stable/object_detection.html)、[图像分类](https://docs.lightly.ai/train/stable/image_classification.html)

Meta官方DINOv3仓库提供原生训练示例，并把文本对齐作为独立训练部分。需求应保留“原生自监督训练”入口的独立接入评估，且向量任务需要分别验证文字和视觉查询能力。[DINOv3官方训练与文本对齐](https://github.com/facebookresearch/dinov3#training)

参考工具和模型权重的使用条件需要纳入接入评估：X-AnyLabeling仓库声明GPL-3.0，LightlyTrain提供AGPL-3.0及其他许可方案。本文没有作出具体集成方式或授权判断。[X-AnyLabeling许可声明](https://github.com/CVHub520/X-AnyLabeling#license)、[LightlyTrain许可声明](https://github.com/lightly-ai/lightly-train#license)

## 8. 本版整理决定

1. 按最新指令纳入多租户；此前“完全不需要权限管理”不再用于否定租户身份和隔离。复杂角色仍未列为明确需求。
2. 保留三条生产线独立、数据总量基线、向量仅测试和发布边界到下发/回退。
3. 新增十项均有编号映射；纸面模拟产生的细节标为“推演补充”，没有当成用户已确认指标。
4. DINOv3原生自监督、教师蒸馏、少样本微调分别描述；百张能力不承诺准确率。
5. 参考项目用于能力与行为调研，当前没有决定直接集成、开发平台或实际运行训练。

# SmartEye 内置模块

正式源码参考为用户指定仓库 `suLemonTree/auto-img-downloader` 的本地克隆 `ebee9a9`。原工作目录保持不变；[源码核对记录](../../../../docs/testing/p1-source-manifest.json)记录迁入前20个Python文件与正式源码的换行归一化对照，并非迁入后适配代码的字节一致性声明。

## 运行方式

只启动主 FastAPI 后端（8000）和主前端（3000），不启动 Flask 独立服务。`bridge.py`将保留的 Flask 路由放在主认证之后，统一前缀 `/api/smarteye`。前端 `frontend/smarteye/`使用同一次Vite构建，通过同源iframe隔离原页面样式；六组可用页面与原接口保留，原侧栏占位链接仍为占位。

主库当前须完成011迁移（包含006的内置模块）。当前已备份后从005升级006，保留既有数据；不要为接入SmartEye重跑带删表行为的旧迁移。新建库的完整初始化仍待另行验收。

`smarteye` schema保存原平台、台账设备、监控、AI任务和结果表；连接的search_path限定为此schema，避免误写主业务同名表。主库另有 `smarteye_jobs/files/schedules`三表，保存用途、操作者、执行轮次、进度、文件引用及调度配置。后台任务使用独立连接。

当前已复制99个平台、401个告警类型配置。原独立SmartEye的旧下载图片、历史任务、AI历史和设备缓存未迁移，需单独制定存量迁移与校验方案。

## 配置与存储

数据库、JWT、租户和存储使用主应用 `.env`。旧平台登录与AI等私有配置使用主后端 `.env.smarteye`，只读取模块实际需要的键，不覆盖主数据库/代理环境。两份配置均不提交；容器部署需另行注入配置，当前没有验收Docker运行。

任务可选“仅下载”或“用于标注”并指定项目。最终图片按真实平台名加入命名图片集，多个平台分开；AI素材／结果或缺少平台信息的路径使用明确默认名。成功的最终图片先进入独立图片库，用于标注时再自动建立项目使用记录；仅下载也可稍后筛选并添加到多个项目，无需重新上传或复制原图。原图通过主 `LocalStorage`原子保存至 `images/<hash>`；SmartEye任务目录在同一本地存储卷中创建硬链接，项目保存引用。ZIP是额外交付包，不是第二份原图存储。裁剪模式的临时整图不进入图片库或项目，输出裁剪图按用途关联。

图片解码、尺寸/格式、大小、路径与哈希校验在写入前执行；项目内哈希唯一约束防止重复资产。取消、中断及旧执行轮次的迟到图片不能进入项目。任务文件名复用时更新引用，保留原哈希文件，不覆盖已有原图。

当前要求一个后端进程、本地支持硬链接的文件系统。EOS尚未接入，配置为非本地存储时模块明确拒绝启动。删除引用或临时目录保留主哈希原图；无引用图片及ZIP的物理清理尚未实现，需要关注磁盘容量。

上传/SmartEye最终图片按目标图片集独立入库规则：长边大于等于阈值，初始720，可选指定目标图片集或按平台名归类；任务可覆盖阈值，0关闭；低分辨率项跳过并记录filtered_count。裁剪临时整图绕过最终规则。合格图先入库/关联，由主后端单进程的持久分类队列调用可配置Qwen服务，同集按内容去重；场景结果跟原图共享，重复图不重新推理，手动重分类结果所有所属集可见。多标签和失败重试在图片库查看。场景不修改平台图片集或检测类别。见[场景与入库规则](../../../../docs/development/图片场景与入库规则.md)。

## 状态与恢复

重启后未完成任务标为 `interrupted`，调度配置保留但不自动启动。检测、台账、智搜、工具下载可手动重试，已登记图片从本地缓存复用。监控需在原页面手动重新启动；AI及素材/选图任务从对应页面重新提交，禁止通用自动重试付费AI。

取消AI只停止本地后续处理，已提交到远端的生成请求可能继续计费。原AI历史表保留其自身处理记录，当前取消/中断状态以统一任务面板为准。
